# 比赛二路同步 v0.1.26

用于 B 站及已启用平台插件的多位主播观看同一比赛时，选择其中一路作为主画面，同时听多位主播的声音并合并弹幕。

## 安装与入口

1. 源码版先更新 `requirements.txt` 的依赖；EXE 版需要包含 PyAV 的新版完整程序。旧 EXE 仅替换插件无法增加原生解码组件。通过「设置 → 插件 → 装载插件」选择 `match-sync-v0.1.26.zip`。
2. 重启这一份程序；插件卡片应显示「比赛二路同步 / 0.1.26 / 已加载」。
3. 点击关注栏底部、布局预设旁的「比赛二路」按钮。左侧关注栏保留，右侧观看区域切换为主画面与合并弹幕，不增加顶部工具栏。
4. 将左侧关注栏卡片拖到右侧观看区域；第一路加入后自动开始，再拖其他卡片加入更多直播间。点击下方设置栏每位主播名字旁的「主画面」按钮选择想看的主播画面，「自动对齐比赛画面」也在同一栏。
5. 再次点击「比赛二路」按钮关闭模式，停止插件取流与混音，返回原画面墙。同次启动关闭再开启保留参与房间，重新取流并清除暂停状态；重启程序后参与列表为空，旧测试房间不会自动加入。重新拖入同一房间可沿用该房间的调节值。

虎牙、斗鱼、抖音等平台需先启用对应平台插件，沿用其公开直播流、画质与弹幕能力；完整多平台弹幕需使用包含该平台弹幕组件的主程序。仍通过关注卡片拖入；独立窗口也支持平台前缀（如 `huya:房间号`）或官方直播链接。

已有旧版时，安装器不支持同 ID 覆盖安装。退出程序后，将新 ZIP 内 `match_sync` 文件夹的文件覆盖到这份程序的 `plugins_user/match_sync/`，再重启；配置文件无需改动。

源码开发目录 `_match_sync` 会被本体跳过，避免开发文件自动装载。ZIP 顶层目录是 `match_sync`；请使用 ZIP 安装。

## 调节

- 右侧弹幕贯穿观看区域全高；各路设置仅占左侧视频下方的无边框滚动栏，拖动分隔线可调高度。每路控件按主播选择、声音、弹幕、偏移、画面区域和移除分组横向铺满面板，组内保持紧凑单行；宽度不足时可横向滚动。音量条旁显示 0–100 的实时数值。右上角「最小化」收起整个设置栏，左侧视频区域底部的「展开设置」恢复原有高度和调节值，期间画面、声音与弹幕继续播放。每路独立启用声音、调音量、选择声道、启用弹幕、修改主播名称。拖入第一路自动开始。
- 设置栏顶部两角与上方播放栏统一为 8 像素圆角，底部保留 12 像素圆角及半透明深色渐变底，控件采用 8 像素圆角与半透明填色。原 Tile 按钮保留本体圆角样式。
- 各平台的二路弹幕统一在昵称前用 `【主播名称】` 标注来源直播间，并采用该路预设颜色。现有粉丝牌数据缺少所属主播信息，无法可靠区分其他主播的牌子，因此二路面板不显示粉丝牌，也不虚构等级；仅修改显示副本。
- 移除最后一个直播间时立即清空画面和弹幕、停止取流与混音，不保留最后一帧；再次拖入任意支持平台的卡片自动开始。移除或重连后重新获取直播地址。
- 声道可选「原始声道 / 仅左输出 / 仅右输出」；仅左或仅右会将这一路的完整声音混为单声道再送到相应耳机一侧，切换即时生效。
- 主画面复用原画面格按钮：悬停右上角选择画质、刷新或移除，下方调音量、静音、暂停/继续、全屏与录制。画质选择重新获取该房间对应档位的流，期间显示原有缓冲动画，收到可播放帧后自动收起，不显示空房间的拖入提示；不会重启其他房间。暂停只冻结并静音主画面这一路，其他房间继续；恢复时返回当前对齐进度。录制保存原始直播流。画面格静音与设置栏的声音开关双向同步；音量数值也同步更新。按 F（或本体配置的放大快捷键）进入或退出二路主画面全屏，退出恢复视频与设置栏的分隔位置；编辑主播名称时不触发全屏。左上角仅保留 LIVE 和主画面直播间标题，不显示获取人数提示；未收到标题时暂用主播名称。
- 来源颜色只提供蓝、粉、紫、绿、黄、橙六种预设；界面和弹幕来源标签不显示房间号。开启二路时隐藏原布局的蓝色观看标记，正在由二路取流的关注卡片改用粉色边框；竖屏头像条同样隐藏旧标记并加粉框。移除或停止取流即取消粉框，退出二路恢复原布局标记。
- 右侧弹幕和主画面「弹幕」开关共用所有已开启弹幕的直播间，来源统一为「【主播名称】」。单路关闭弹幕即停止该路连接，重新开启会重建连接；B 站临时连接失败自动重试。右侧批量消息按参与房间均分每次显示额度；画面滚动弹幕按来源轮流分配轨道，每路最多暂存一条最新消息，超过 5 秒的等待消息丢弃，避免某一路集中到达时挤掉其他来源。缩放或改变字号后重新检查轨道间距，舍弃会重叠的后发弹幕。二路使用 Qt 浮层绘制，不使用原生 VLC 浮层，避免遮黑画面与残影。主画面滚动弹幕开启或关闭不停止视频、声音或右侧弹幕。
- 斗鱼取流使用软件已记住的斗鱼登录状态向官方接口申请画质，二路保留用户请求档位供重试，同时单独显示平台实际返回档位；账号不可用时仍如实显示实际档位。
- 偏移按钮正下方常驻小字说明（左缘与「偏移」对齐，窄屏可换行）：单位为秒，+ 正数延后本路，− 负数相对提前本路。鼠标悬停「+」「−」按钮也会分别弹出说明，涵盖画面、声音和弹幕的作用。
- 「播放偏移」同时调节该路画面、声音和弹幕：点击「+」延后、点击「−」提前，步进 0.1 秒，也可直接输入。负偏移会相对提前本路；超出基础缓冲时，系统同时延后较快的其他路，保证不读取未来画面或音频。实际缓存仍不足时会明确显示等待缓存。旧版弹幕微调值不再使用。
- 点击「对照微调」、进入偏移输入框或按「+/−」会展开对照画面。预览使用和声音相同的当前播放进度，不使用直播最新帧冒充播放帧。左侧固定主画面，右侧为当前微调直播间；三路及以上可用上方主播选择切换右侧对照，点击某路偏移会自动选中该路。各路显示相对主画面的实际提前/延后秒数；可勾选「放大框选区域」查看计时器。点击右上「收起对照」或取消「对照微调」隐藏预览，保留所有偏移并继续播放。对照期间暂停自动匹配，收起后按原开关继续。点击「最小化」同时收起对照面板。
- 自动同步比较共同比赛区域，估计分辨率约 0.5 秒；连续两次一致的结果才应用。自动模式将较快的一路延后到最慢的一路，额外保留约 2 秒基础缓冲。
- 若自动对齐困难，点击该路「选择比赛画面」，框选各主播画面中相同的比赛内容，避开头像、边框和字幕。框选弹窗冻结点击时该路主画面或对照区正在显示的帧；暂停或缓冲时使用屏幕保留的画面。未显示的房间使用共同播放时钟及该路偏移取帧，不使用缓存里的最新帧；尚未出现播放画面时提示先等待画面。这告诉插件应比较哪一块画面；正常时无需操作。图像指纹提高至 512 位，并优先比较连续画面中发生变化的部分；更换框选区域保留此前确认的偏移，只重新收集该路区域特征。计时器需持续变化，字体、裁剪比例或比赛不同仍可能无法确认；匹配不是读取数字的 OCR。切换主画面会重新确认匹配。
- 静止画面、不同比赛、遮挡、切场景、重复回放等可能无法判定时间差。界面显示匹配状态与置信度；失败时保持上次确认的偏移，可关闭自动同步并手动调整。
- 点击「比赛二路」关闭模式，停止取流、弹幕与混音，并恢复主程序当前的静音设定。二路期间原画面墙隐藏，后台声音由插件接管，避免原生视频覆盖和重复出声；关闭后恢复原画面墙。重新开启会刷新远程流地址，不能沿用上一次已经过期的地址。

## 运行与资源

使用已有 FFmpeg、PySide6、本体 B 站弹幕组件及平台插件提供的弹幕客户端，无需额外安装 pip 包。源码从程序旁边或 PATH 找 FFmpeg；EXE 从其所在目录找。账户只沿用本体现有登录态，不写账号配置。

v0.1.15 的 Qt 画面弹幕透明绘制修复由配套主程序 `ddm/video_danmaku.py` 提供，需同时更新主程序源码；仅替换插件不会更新旧 EXE 内部的绘制实现。

v0.1.21 避免主画面每帧重复布局画质、静音及暂停控件，降低斗鱼 60 帧主画面的绘制开销。斗鱼弹幕先解析靓号对应的实际房间号，再登录和订阅，修复显示已连接却没有消息的问题；该弹幕修复由主程序 `ddm/live_danmaku.py` 提供，需要同时更新主程序源码，单独换插件不能更新旧 EXE 中的弹幕实现。

v0.1.22 的二路全屏沿用主程序的鼠标自动隐藏：鼠标在视频区域静止 3 秒后隐藏鼠标与控制条，移动时恢复；菜单、模态窗口或失去焦点时保持鼠标可见。F、Esc、停止二路或关闭窗口都会恢复鼠标与控制条。

v0.1.24 在进入二路模式时立即静音原画面墙全部播放器，不需要先加入房间或建立二路音频输出。空列表、停止二路播放、移除全部房间及本体播放器重连时仍保持原画面墙静音；关闭二路模式后按各格子的静音设置恢复，不修改其保存配置。

v0.1.25 首次主画面及切换主画面时默认请求平台最高画质，按平台档位排列选择，B 站包含高于 10000 的 2K 等档位；画质查询在解码线程内完成。已经处于最高档的流继续播放，其他房间不改档或重启。用户手动降档会保留，重新选择该房间为主画面时再次默认最高；平台因登录态或源限制返回较低画质时如实显示实际档位。

v0.1.23 优化首次匹配与误判：每秒两次图像指纹，最少收集 8 份；只比较双方都有变化的指纹位置，重叠的半秒候选桶聚合边界抖动，并以中位数剔除偏离超过 0.35 秒的配对。验证共同时间区间最后 8 秒内至少 6 个独立变化画面、一对一且时间顺序一致，覆盖至少 2.5 秒，最新支持距共同区间末端不超过约 1.5 秒。相距至少 0.75 秒的另一候选若评分达到最佳的 85%，拒绝判定。置信度至少 65% 且连续两轮一致才采用；每 3 秒检查一次。弱证据保留已确认偏移，手动锁定仍不受自动匹配覆盖。这是基于动态画面的估计，不保证逐帧精度；双方比赛画面位置/大小差异较大时，仍需分别框选共同区域。

v0.1.26 使用 FFmpeg 保留原始视频码流，PyAV 按真实 PTS 解码。主画面与对照保留实际片源分辨率和帧率，不再经过 720P/1080P 缩放、固定 30/60 帧或 JPEG 二次压缩；显示大小只在绘制时适配窗口。匹配只保存小尺寸画面特征；完整 RGB 图片由后台线程按播放时刻预取，界面线程只绘制。

每路原始压缩视频仍限制为 60 秒、96 MiB，按完整 GOP 淘汰，音频约 11 MiB；实际缓存时长受源码率和 GOP 长度限制。当前可见画面额外预取最多 8 张、64 MiB 图片，隐藏后释放预取，停止时结束后台线程。预取不足时最多使用早于目标 50ms 的已解码帧，不显示未来内容。`Decoder.diagnostics()` 提供源尺寸、帧率、收帧数、压缩缓存大小/时长和后台图片解码耗时；Canvas 统计不同帧显示次数及重复轮询次数。本地测试覆盖三路 1440P60、B 帧、30/59.94 帧、源像素一致性、跳转、停止与进程清理；不能据此保证任意网络和硬件的长期实播性能。

原画面墙的布局与房间保留，二路期间隐藏，关闭模式后恢复；二路界面嵌入右侧观看区域，不弹出独立观看窗口。斗鱼二路每次启动重新申请流地址，避免复用画面墙已使用的单消费者地址；连续 8 秒未收到画面会结束当前解码并重新取流，B 站轮换候选线路，其他平台重新申请地址。网络读取也有 6 秒超时，避免一直停在加载。持续收帧但播放时钟已跑到缓存前面时，按各活跃房间缓存的共同可用范围回调播放时钟；画面、声音与弹幕共用该时钟，保持手动相对偏移，不重启正常取流。未手动锁定时，超过 3 秒未收新帧的房间不参与时钟回调；手动锁定时仍等待该路的共同缓存，不让其他路单独继续。过大延后导致缓存不足仍明确等待。各平台共用相同的 FFmpeg 图像/PCM 缓存、自动匹配、手动偏移、画质、暂停、全屏及录制控制。声音通过独立的 Qt 音频输出混合，避免多路叠加过载；设备更换时重建输出。FFmpeg 子进程按本体现有方式后台运行并加入退出清理 Job。

## 人工验收

源码版与 EXE 版应分别按以下步骤验收，安装位置和配置目录各自独立。不要把源码版验证当作 EXE 验证。

1. 点击关注栏底部「比赛二路」，将两个正在看同一比赛的 B 站关注卡片拖到右侧。应自动开始并收到两路声音和弹幕，无论原有粉丝牌属于谁，昵称前都只显示一份来源主播文字标记，不显示原牌或虚构等级；重复拖动不能添加重复房间。
2. 切换主画面，两路声音与弹幕继续。若其他路解说慢约 4–5 秒，在它那一行尝试 −4 至 −5 秒，观察对照区的比赛计时器与相对偏移；较快主画面会相应延后。关闭对照时不停止取流。逐路关闭声音、调音量、关闭弹幕，操作只作用于该房间。确认音量条数值实时更新，格子静音按钮与该主播的声音开关双向一致；画质切换显示缓冲动画，收到画面后消失。
3. 自动同步至少等待 10–20 秒；画面差异较大时分别圈选共同比赛区域。观察匹配状态，再用比赛计时器、击杀提示或场景切换检查两路内容是否对齐；听辨解说应对应当前比赛内容。
4. 主画面选择按钮应紧邻各主播名字，自动对齐应在下方，各路操作应分组横向铺满面板并保持单行。弹幕应贯穿右侧全高，设置栏应仅位于左侧视频下方，能滚动查看更多房间，并可拖动分隔线调高度；点击「最小化」后整栏消失、左侧画面扩大、右侧弹幕高度不变，左侧底部「展开设置」恢复原高度和调节值。播放偏移从零点击「−」再点击「+」，应回到零；改到 +3 秒时，该路声音与弹幕一起延后，主画面选到该路时画面也延后。切换预设来源颜色，应只改变该路弹幕颜色。将两路分别选仅左、仅右，声音应分别来自耳机两侧。
5. 换成不同比赛、主播全屏聊天或静止画面，自动状态应报告匹配不足，不能凭相同启动时间报告同步成功。
6. 调整主窗口大小，二路界面应随右侧观看区域改变；按 F 应放大主画面，再按 F 或 Esc 恢复；名字编辑框中输入 f 不应全屏。左上角应只显示 LIVE 和当前主画面直播间标题。进入二路时原蓝色观看标记消失，二路取流主播出现粉框；点击「比赛二路」关闭，原画面墙房间、布局与标记应恢复。遇到断流、移除房间、立即开始/停止或退出程序，主程序应继续响应，插件 FFmpeg 与弹幕工作线程最终退出。系统换音频设备后仍可继续听声音。
7. 同次启动关闭再开启，应重新收到画面并能暂停/恢复、切换主画面和画质。重启整个程序再开启二路，参与列表应为空，第一张拖入卡片应成为主画面；禁用插件并重启，应无插件入口；删除插件并重启，应停止加载。

另需拖入虎牙、斗鱼、抖音的关注卡片，与 B 站组合切换主画面，逐路测试画质、音量/声道、弹幕、偏移和暂停。移除全部直播间应立即清空，重新拖入应自动播放。

## v0.1.16 缓冲与弹幕恢复

斗鱼弹幕每 20 秒发送保活，45 秒没有收到任何服务端数据会重新订阅；首次断线等待 1 秒，连续失败最多等待 5 秒，订阅成功后重新计算失败次数并继续轮换端口。服务端拒绝订阅时立即进入重连。

弹幕接收时刻映射到该路实际解码时间轴，避免解码逐渐落后于系统时间后弹幕长期留在队列；视频重连保留独立弹幕连接已收到的消息。

各路已有至少 0.25 秒共同缓存时，启动或调整偏移可直接跳到共同可用位置，画面与声音共用同一校正时钟，保留各路相对偏移。缓存无交集时仍等待真实内容；主画面与对照画面保留上一帧，明确显示缓冲状态，避免对齐过程清空变黑。取流首次重试等待缩短为 0.5 秒，连续失败最多 5 秒；不重启仍在正常收帧的直播间。

这些弹幕连接修复位于主程序 `ddm/live_danmaku.py`，需要使用更新后的源码主程序；仅覆盖插件不会替换旧 EXE 中的连接逻辑。

## v0.1.18 手动时间锁定

主动修改任一路偏移后，保留当时已确认的自动对齐基准及手动相对时间差，关闭自动对齐，并显示「手动时间已锁定」。收起对照、单路卡顿/重连、切换清晰度、切换主画面以及同次观看模式的停止重开均保留锁定。重新勾选「自动对齐比赛画面」解除锁定，恢复自动匹配。

锁定后，短暂停收可先播放已有共同缓存；某路缓存不足时，各未暂停房间使用同一进度共同等待，保留画面、显示缓冲，并输出静音以避免重复播放某段声音。即使该路超过 3 秒没有新帧，也不会将它排除后让其他路跑到前面。共同可用内容恢复至少 0.25 秒后继续；缓存不足或实际断流丢失的内容仍需等待，不凭空补帧。手动暂停的房间不阻塞其他路。

`dev/selfcheck_match_sync_lock.py` 覆盖手动覆盖自动匹配、两路分别长时卡顿、静音等待、重连保留基准、共同缓存恢复，以及主画面/清晰度/同次模式重开和主动解除锁定。
