# 成片样式核对表（录制前跟用户对齐）

这份是「片子长什么样」的口径，来源是 `BRIEF.md` / `STORYBOARD.md` / `frame.md`，
不是新决定的。录新的画面之前先确认这张表，避免录完才发现样式不对。

## 一、硬规格

| 项 | 值 | 出处 |
| --- | --- | --- |
| 画幅 / 帧率 | 1920×1080 / 24fps | `STORYBOARD.md` front-matter |
| 时长 | 60.0 秒（15 拍） | 分镜时长核算 |
| 声音 | **无口播、无配音**；BGM + 音效 | `BRIEF.md` `narration: no` |
| 字幕 / 正文字 | 有中文标题卡，**无口播字幕** | 分镜各拍 `onscreen` |
| 发布 | bilibili | `BRIEF.md` |
| 语言 | 中文（标题、副标题） | 同上 |

## 二、色场（一拍只用一种，平面不加纹理）

| 色场 | 色值 | 用在哪几拍 | 字色 |
| --- | --- | --- | --- |
| `field-black` | `#0d0e10` | 01 开场、15 片尾 | `#f1f2f5` |
| `field-dark` | `#222428` | 02 标题底、07 竖屏、12 重连、13 插件 | `#f1f2f5` |
| `field-blue` | `#00a1d6` | **03–06 布局整段** | `#0d1114`（深字压亮底） |
| `field-light` | `#f1f2f5` | 08–11 细节段、14 宣言 | `#101114` |

- B 站蓝 `#00a1d6` 是**唯一**强调色；粉色 `#fb7299` 不进设计系统
  （只在真实录屏里自然出现）。
- `field-blue` / `field-light` 上不许再叠渐变或纹理；`field-dark` / `field-black`
  允许一层极缓慢的极光渐变。

## 三、文字

- 主标题：Microsoft YaHei UI **4.6cqw / 700**，居中；副标题 **2.1cqw / 600 / 字距 0.16em**。
- 并列项**用空格分隔**（"音量 静音 画质"），不堆顿号。
- 每拍：主标题在上（约 `pad-top`），窗口在下。

## 四、窗口（真实录屏）怎么摆 —— 这是片子最要紧的一条

- **一切软件画面必须来自真机录屏或真机截图**，一个像素都不许用 DOM 重画。
- 窗口 **下沿被画面裁掉**（bottom 为负 cqw），暗示"界面还在往下延伸"；
  不要为了塞下整个窗口而缩小它。
- 柔和投影 `0 2cqw 5cqw rgba(0,0,0,0.28)`；**不许发光、不许描边高光、不许玻璃拟态**。
- 允许整体轻微 3D 斜置（`rotateY(-6deg)` 量级）或推近；不许变形到看不出是同一个窗口。
- 布局图 chip（贯穿 03–06 的母题）是 10cqw 见方、圆角 8px 的线框小方块。

## 五、节奏

- 15 拍：`6.0 + 4.5 + 3.5×4 + 5.5 + 3.5×4 + 3.5 + 4.5 + 4.5 = 60.0s`
- 三处刻意的静止：**01**（墙亮完停住）、**07**（转完停住）、**14**（整拍静止）。
- 唯一允许的持续运动：**06 / 08 的弹幕在滚**（主体自己的行为，不是装饰）。
- 不许：幻灯片式一格一换、屏保式各飘各的、懒呼吸、后半段慢推慢摇。

## 六、录制口径的修正（用户 2026-09-21 提出）

> "不需要一个一个将画面拖上去播放，他在视频中可以直接展示为正在播放的画面"

也就是说：**不需要拍"把直播间一个个拖上墙"的过程**。每一拍要的镜头就是
"这个布局下、画面墙已经是亮着的"，直接从已经装满、全部在播的状态录。

据此调整：

- 新 take 不用"逐格加人"的段落；改成**先一次性把墙填满在播房间**，再逐拍切布局。
- `take-plan.json` 里 `make-take-plan.py` 的"加入画面墙"若干步可以合成一次
  （或直接由起点配置预置满墙），省下的时间留给每个布局状态的停留。
- 各拍素材要的是"该布局下持续播放"的一段，而不是"切过去的那一下"。
  切换动作本身仍然保留（分镜 03–06 要的就是布局演化），但不靠它当主要素材。
