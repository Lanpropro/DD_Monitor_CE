### 2.1 开场运动实测（0–4.96s）[实测]

逐帧相位相关（24fps；取画面 **30–60%** 带避开标题，用 **0–7%** 带交叉验证）：

| t | 相机累计位移 | 瞬时速度 | 同时发生 |
| --- | --- | --- | --- |
| 0.00–1.38 | 0 → −189px | 0 → −258px/s，**匀加速**（位移 ∝ t²） | 标题 **0.52s 起淡入** |
| 1.38–1.88 | −189px 不动 | ≈0（**静止 0.5s**） | **1.44s 软件窗口从画面右缘进入** |

- 参考片在 **1.88s 处是原始素材的拼接点** —— 从静止一帧内跳到 315px/s，加速度物理上不成立。

## 五、动效规范 [补齐]

**只为这五个目的动**：反馈 / 空间连续性 / 状态指示 / 避免跳变 / 解释。

**属性**：只用 `transform`（`translate3d` / `scale` / `rotate` / `rotateY`）和 `opacity`。
**不动** `width/height/top/left/margin`（触发 layout，掉帧）。

**曲线**：
- 入场 / 退场 → **`cubic-bezier(0.23, 1, 0.32, 1)`**（强 ease-out）
- 屏上位移 / 变形 → `cubic-bezier(0.77, 0, 0.175, 1)`
- 匀速（滚动 / 弹幕）→ `linear`
- **摄像机位移 → `rail`（自定义）**：两端各 17% 做二次加减速，中间 66% 严格匀速。
  对称的 `ease-in-out` 在长距离移动里中段会"猛冲"，观感就是"快进缓出"；滑轨曲线没有这个问题
- **推进 / 落位 → `elastic.out(1, 0.62)`**：到位时要有一次看得见的回弹，别用干净的 `power*.out`
- **不用 `ease-in`**（起手慢，正卡在观众盯着的那一刻）

**时长**：

| 类型 | 时长 | 参考片依据 |
| --- | --- | --- |
| 元素飞入 / 填充 | 320–520ms | — |
| 布局切换（重排） | 480–720ms | — |
| 弹层弹出 | 180–260ms | — |
| **极快切（标题爆发）** | **250–500ms** | 15.33–17.08s 实测 0.42/0.50/0.83 |
| 光标移动 | 600–900ms | — |
| 镜头位移 / 推进 | 1200–2600ms | — |
| **开场氛围长镜头** | **6000ms 量级** | 0–6.58s 实测 6.58s |
| 收尾定格 | ≥3000ms | 60.00–63.37s 实测 3.37s |

**入场不用 `scale(0)`** —— 从 `scale(0.94~0.97) + opacity:0` 起。
**多元素入场错开 40–80ms**，不齐发。

## 七、逐拍规范

### 【0–12s】视角右移 + 软件填充 + 拆解（A 组 · `18-01-intro.html`）

**01 · 视角向右移动**（0.0–1.95s）
- **[手稿]** 视角向右移动；背景未定；左侧浮现出软件标题
- **[实现]** 背景 `bg-hall.jpg`（银河 + 山脉 + 湖面），在世界层 3600×1080 内 `object-fit: cover`；
  相机把世界层 `x` 从 0 推到 −1649（窗口落位居中），**速率曲线照参考片前 4s 实测**（见 2.1）：
  - `0.00–1.38s` **匀加速**（位移 ∝ t²，`power2.in`）走 189px，峰值 258px/s
  - `1.38–1.88s` **完全静止** 0.5s（静止段不写补间）
  - `1.88–5.60s` **恒定 368px/s**（`none`）走 1368px
  - `5.60–6.10s` **减速收尾**（`power2.out`）走 92px
  - 参考片在 1.88s 处是原始素材的拼接点（静止 → 315px/s 一帧内跳变）；我们是一镜到底，
    所以做成平滑起步后再匀速。368px/s 比参考片快约 17%，是为保住 A 组 12s 总长
- 软件窗口**平正**（照参考片那个窗口：正对镜头、无俯视倾斜）；世界坐标 `x=2109`，
  所以 `2109 − 189 = 1920` —— **窗口恰好 1.44s 贴上画布右缘进入**，而不是第 0 帧就露边
- 标题「DD监控室CE」+ 副标「多窗口直播监控」从 `translateX(-70px) + opacity:0` 浮入；
  **0.52s 起浮现**（550ms）、**1.79s 起 0.25s 隐去** —— 两个时刻都照参考片实测

**02 · 元素飞入填充**（随 01 一起落位）
- 软件窗口 = `Video_reference/fullscreen.png` 的真实截图切片（侧栏 / 主画面 / 5 小格，`--s: 0.2604`）
- **窗口外壳 = 类玻璃材质**（照参考片 LauncherX 那个窗口）：圆角 14px + 1px 冷色亮棱边 +
  顶部内侧高光 + 底部内侧暗棱 + 表面 124° 斜向反光（`.appwin::after`）+ 四层柔和外阴影；
  底色是**高不透明度**深灰渐变（`.93→.96`）—— 切片缝隙**不透**背后背景，
  玻璃感只做在**边缘**，不靠底色透明（底色一透明，缝隙透出银河就又是"软件画面缺一块"的观感）
- 素材位：`[素材: 6 路直播画面 → 替换切片]`

**03 · 软件拆开成各元素**（6.90–8.75s）
- **[手稿]** 视角突然向前推进；同背景；软件拆开成各元素
- **[实现]** 居中后相机先做一次**弹性推进**（5.40s 起，`z 0→230`，`elastic.out(1, 0.62)`，1.50s）；
  随后 7 个模块沿各自的 `translate3d(x, y, z)` 飞出画面（stagger 60ms，1.85s）——
  **每个模块都必须给 x/y**，只补 `z + opacity` 会看起来"在原地消失"而不是飞出去
- **保留软件主体**：模块飞走后留下窗口外壳（`#222428` 底 + 描边 + 三层投影），背景不透出来

**04 · 元素消散 + 标题**（8.90–12.0s）
- **[手稿]** 视角继续推进；各元素全部消散；出现标题 *向您介绍 **DDMonitorCE***
- **[实现]** 相机 `z 230→760`（1.65s，8.90s 起，`perspective 2000` → 约 **1.61 倍**），
  背景图与暗角随之淡出（9.35s）；**窗口壳不淡出**，最后的文字直接叠在窗口壳上
- **故意不铺满画布**（窗口落在 154,68 → 1767,950，四周留边）：月光出现的时段必须能看见窗口的
  边界和玻璃棱边，否则「透过窗口」无从体现（上一版推到 5.44 倍铺满，月光层按窗口坐标布的
  16 个光点只剩 1 个还落在画布内）
- **月光光影层 `.moon` 是 `.appwin` 的子层**（10.30s 起淡入）：一层 `.wash` 冷白光晕（径向渐变，
  光源在左上角）+ 16 个光点（stagger 50ms）+ 3 个四芒星（stagger 170ms）；
  `inset:0 + overflow:hidden + border-radius` 把光严格限制在窗口内 ——
  **光不直接显示在画面上，而是透过窗口玻璃透出来**
- 主标题 10.58s 起 `translateY(26px)→0` 落定 700ms

## 十、渲染陷阱（实测踩过的坑，写新镜头前必读）

这些坑的共同点是：DOM 的 `getBoundingClientRect()` 完全正常，但**绘制**是错的。
凡涉及 3D 变换，必须用 `tools/probe-variants.mjs` 截图后数像素来验证，只看几何会被骗。

| 症状 | 根因 | 正确做法 |
| --- | --- | --- |
| 软件窗口只画出上半部分，下半部分连窗口底色都没有，直接透出背景 | 祖先层有 `transform-style: preserve-3d`，子层再做 `rotationX` / `z` 变换时 Chrome 把该子层的绘制裁到局部 y≈363（实测只剩 417/548 行） | 祖先层**不要** `preserve-3d`；立体感改成给每个 3D 元素自带 `transformPerspective`（GSAP 属性），效果等价 |
| 同上 | 参与 3D 的层写了 `will-change: transform` —— Chrome 按布局尺寸给合成层光栅化，投影超出该边界就被整块裁掉 | 这些层不要写 `will-change` |
| 拆解"飞出画面"的模块看起来在原地消失 | 父层 `overflow: hidden` 把飞出动画整块剪掉了 | 承载"飞出去"的父层不要裁切，圆角交给子元素自己 `border-radius` |
| 布局动画一顿一顿 | 补间了 `left` / `top`，布局属性会吸附到整数设备像素 | 位移用 `x` / `y`；宽高可以保留 CSS 补间（离线逐帧渲染不在乎 layout 成本，而 transform 缩放会把格子里的文字/控制条一起拉变形） |
| 时间轴上的 callback 不触发 | 渲染器用 `seek(t, suppressEvents=true)` 跳帧取画 | 所有状态变化都必须写成时间轴上的补间，不能用 `tl.call()` |
| 相邻 tween 抢同一个 transform 分量，中途跳变 | 两个 tween 都补 `x` 且开始时间错开 | 让它们同时开始、各补不同属性（一个补 `opacity`，一个补 `width/height/x/y`） |

**验证工具**（都在 `tools/`）：

- `probe-variants.mjs` + 一份 JSON 配置 → 在不同时刻各截一张图，并打印选择器的真实 `opacity` 与 `getBoundingClientRect`
- `probe-shot.ps1` → 在截图上数某一列的暗行数、找"暗→亮"的裁切边界。**模型看不到图，构图只能靠这个数出来**
- `probe-dom.mjs` → 静态服务器 + CDP，把时间轴 seek 到指定时刻后读真实几何（注意 Windows 上路径分隔符要统一成 `/`，否则资源全 404，几何全是未变换的假象）
- `.ps1` 一律**纯 ASCII 注释**：Windows PowerShell 5.1 按 ANSI 读脚本，UTF-8 中文注释会变乱码，可能破坏字符串字面量
