## 并入方式

PR #10 的分支基于 v0.4（`2ea281c`），本仓库当前分支从更早的 `01dc472` 分出，双方各自演进了 100+ 提交。直接 `git merge` 会把两套历史里的 200 多个文件差异全部拉进来（40+ 冲突），因此只取其 3 个功能提交的净改动：

```
git fetch origin refs/pull/10/head:refs/remotes/origin/pr-10
git diff 2ea281c origin/pr-10 > _pr10_net.diff
git apply -3 _pr10_net.diff
```

19 个文件中 17 个干净落盘，只有两处需要人工合并：

- `ddm/widgets.py`：本地的全屏底栏已改成滑动动画（`_bar_progress`），PR 里直接 `bottom.setVisible()` 的做法与此冲突，保留本地动画，另外让输入区跟随底栏显隐；`_layout_areas()` 保留本地按动画进度计算底栏位置的那套几何，不采用 PR 的固定 `TILE_BAR_HEIGHT - 1`。
- `dev/selfcheck_tile_ui.py`：关注栏刷新按钮的断言，保留本地更严格的一版（同时检查 `refreshing` 属性和「排队」提示）。

- 新增 `ddm/danmaku_send.py`：每房间独立的输入区（`DanmakuComposer`）+ 表情浮窗（`EmoticonPopup`），网络请求走 `QThread`，关格子不阻塞。

- `ddm/app.py`：启动恢复、登录写入、退出登录清空 `bili_jct`。
- `ddm/login.py`、`ddm/web_login.py`：扫码与账号密码登录都收齐 `SESSDATA` + `bili_jct`。
- `ddm/widgets.py`：输入区内嵌进格子底栏（开播状态和弹幕开关之间），宽度自适应伸缩并在宽格子里限宽 340px；信息条原有的状态文字、音量数字、音量滑条、弹幕设置、录制入口在任何宽度都不隐藏。
- `ddm/theme.py`：输入区、表情浮窗、发送按钮的样式并入全局 QSS（发送按钮复用本地 `PrimaryButton` 主色胶囊样式，其余沿用底栏 `TileCtrl`），主题切换不再逐控件重设局部样式；新增 `theme.icon_color()` 供手绘图标取色。
- `ddm/danmaku_send.py`：表情入口改成 `EmoteButton` 手绘矢量图标（和暂停/刷新按钮同一套画法），不再用 `☺` 字形；图标按控件真实中心绘制（`QPointF(width/2, height/2)`），不再偏 1px。
- `ddm/widgets.py`：输入区两侧各加一段可伸缩空白，按实际位置二次校正，让输入区在底栏里**居中**；画面弹幕开关改成 `DanmakuToggleButton`，开启时在右下角画勾（B 站播放器同款），不再靠整块底色区分开/关。
- `ddm/fullscreen_cursor.py`：输入框有焦点时，鼠标停在画面上也不收起控制条。
- 新增自检 `dev/selfcheck_danmaku_send.py`、`dev/selfcheck_danmaku_composer.py`。

## 并入时修掉的问题（PR 自身 HEAD 是红的）

1. `d9be8b8` 给 `get_emoticons()` 加了 `buvid3` 请求，但没同步 `selfcheck_danmaku_send.py`，该用例的 mock 只返回表情列表，必然失败。已改为分别 mock 设备接口与表情接口，并补「设备 Cookie 只取一次」「取不到时直接报错不继续请求」两条断言。
2. `test_tile_composer_layout_platform_switch_and_theme` 里三处断言按「输入区单独占一行」的旧设计写的（输入框在底栏下方、提示浮层在输入框下方、200px 宽时输入框 > 40px）。在当前实现下，即使直接在 PR 基线上跑也不成立，已改成按内嵌式底栏检查布局与自适应行为。
3. `test_room_switch_reclaims_composer_space_without_resizing` 同样基于旧设计，改为验证切换房间时视频与底栏几何不变、输入区随平台显隐。
4. `ElidedLabel` 在控件被隐藏或宽度过窄时会把文本省略成空串，导致「连接中…」读出来是 `""`。已在 `_apply_elide()` 里兜底保留原文。

## 手动测试方案

从源码目录运行 `run.cmd`（已运行的进程要重启才载入新代码）。建议准备 1 个真实 B 站账号、1 个已开播直播间。

### 1. 登录与凭证

- [ ] 用旧配置（本次改动前登录过）直接发送：应提示「登录缺少 bili_jct，请退出 B 站账号后重新登录」，且不会发出弹幕。
- [ ] 退出 B 站账号后重新扫码登录，再发送：应成功，输入框清空。
- [ ] 用「账号密码登录」（内嵌浏览器）登录：窗口应等 `SESSDATA` 和 `bili_jct` 都拿到后再自动关闭；只拿到其中一个时不应关闭。
- [ ] 退出登录后重启程序，确认 `utils/config.json` 里不再保留旧 `bili_jct`。

### 2. 文字弹幕

- [ ] Enter 发送成功：内容清空，底栏不闪、不跳。
- [ ] 关闭输入焦点后按 Enter：不误发。
- [ ] 发送过快（连续双击发送）：只发出一条，按钮显示「…」期间不可重复提交。
- [ ] 发送失败（如被屏蔽、频率限制、未登录）：内容保留，输入框上方浮出原因，几秒后自动消失。
- [ ] 断网发送：提示网络失败，内容保留；恢复网络后可重发。

### 3. 键盘与中文输入法

- [ ] 在输入框里打 B、M、F 等单键：不触发播放器的快捷键。
- [ ] 中文输入法选词时按 Enter：只是上屏，不发送弹幕。
- [ ] 按 Esc：退出输入焦点，回到画面操作。

### 4. 表情

- [ ] 点「☺」：浮窗加载表情，按包分组，可滚动；首次打开有加载态。
- [ ] 未解锁（粉丝团等）表情灰置，悬停显示解锁条件，点了不发送。
- [ ] 小表情（`pkg_type=3`）：插入到光标位置，保留已有文字，不直接发送。
- [ ] 大表情/装扮表情（`pkg_type=1/2/5`）：点击直接发送，输入框里的文字草稿保留。
- [ ] 浮窗右上角「刷新」：重新拉取；断网时显示重试按钮。
- [ ] 未登录点「☺」：提示先登录 B 站。
- [ ] 切换房间后再开表情：列表跟着换房间刷新，不串房间。
- [ ] 表情图片加载：首次加载后再次打开不再重新下载（缓存目录里能看到）。

### 5. 全屏

- [ ] 单画面全屏后底栏自动隐藏，输入区跟着隐藏；鼠标移动后底栏和输入区一起滑出。
- [ ] 全屏时点进输入框打字，鼠标停在画面上不动：控制条和输入区不应被收起。
- [ ] 全屏发送后按 Esc 退出全屏：布局、视频尺寸恢复正常。

### 6. 多房间与平台

- [ ] 多画面布局下，各房间草稿互不影响；在一个格子发送不改变其他格子内容。
- [ ] 虎牙/斗鱼/抖音等插件房间：不显示输入区（B 站以外的平台不支持）。
- [ ] 空格子/未开播房间：输入区随房间状态正确显隐。
- [ ] 发送过程中切换房间或退出登录：旧请求返回后不清空新房间草稿、不弹错误。

### 7. 布局与外观回归

- [ ] 1+5、九分、竖屏、镜像、弹幕布局：底栏高度不变，视频区没有被输入区挤小，按钮不重叠。
- [ ] 1+5 的主画面：输入框封顶约 340px 且居中显示，不再横贯整条底栏；5 个小格子的输入框保持现在的尺寸。
- [ ] 画面弹幕开关：开启时只有右下角多一个勾，按钮底色不变；悬停才出现底色；提示文案在「开启/关闭画面弹幕」之间切换。
- [ ] 窗口从大拖到窄：输入框始终居中并逐级变短，发送按钮在约 540px 以下收起（Enter 仍可发送），状态文字、音量数字、音量滑条、弹幕设置、录制入口全程都在；拖到约 440px 以下输入区整块收起，视频和底栏不跳动。
- [ ] 深浅色主题、背景皮肤下：输入框、表情按钮、发送按钮、浮窗刷新按钮的圆角/字体/悬停态和底栏其他按钮一致；表情是描边笑脸图标且居中、发送按钮是主色胶囊，不是方角矩形。
- [ ] 收起关注栏、切换横竖屏、缩放窗口：输入框位置正确，不错位、不压住视频。

### 8. 已知限制（验收时确认是否可接受）

- 格子宽度约 440px 以下时不再显示输入区（分到的宽度不足 96px），原有底栏按钮优先保留；想窄格子也发弹幕，需要把那一格放大或全屏。
- 宽格子里输入框封顶 340px，多出来的宽度留给状态文字，所以输入框会靠右、和右侧按钮挨着。
- 640px 以下音量滑条固定为最小宽度（18px），拖动仍有效，只是不再随宽度变长。
- 表情列表依赖 B 站 `buvid3` 设备 Cookie，接口异常时会提示刷新重试，不会静默少图。
- 大表情发送后不写入本地弹幕记录，画面上的显示依赖 B 站回推。

## 离线自检

只跑本次相关的两项：

```
python dev\selfcheck_danmaku_send.py
python dev\selfcheck_danmaku_composer.py
```

全量自检放在后台、不弹窗跑（避免抢鼠标和窗口焦点）：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
$env:DDM_NO_SAVE = '1'
$env:PYTHON_VLC_LIB_PATH = "$PWD\libvlc.dll"
Get-ChildItem dev\selfcheck_*.py | ForEach-Object {
    python -u $_.FullName *> "work\$($_.BaseName).log"
    "{0}`texit={1}" -f $_.Name, $LASTEXITCODE
}
```

需要可见桌面或外部 EXE 的几项（`selfcheck_fullscreen_cursor`、`selfcheck_video_danmaku_native`、
`selfcheck_portrait_native`、`selfcheck_match_sync_native`、`selfcheck_match_sync_exe`、`*_live.py`）
在离屏模式下会失败或没有意义，需要单独在可见桌面上跑。
