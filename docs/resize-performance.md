# 窗口缩放性能方案

基于 PR13 的 `7d2464fc3c4ec4428043794c39ca9b46207024c9`，保留 libmpv、统一编解码设置、已有分区树和分隔线拖拽预览。

## 交互规则

| 阶段 | 行为 |
| --- | --- |
| 开始 | Windows 的 WM_ENTERSIZEMOVE 进入交互状态；只有实际尺寸变化才启动画面墙的轻量模式，单纯移动窗口不重排 |
| 拖动 | 画面墙以约 33ms 间隔处理最新尺寸；定时器运行时只替换目标尺寸，持续输入也能更新画面 |
| 几何更新 | 视频、控制条、弹幕和点击区域使用同一轮坐标；现有格子和视频 HWND 持续复用 |
| 装饰更新 | 遮罩按尺寸、DPI、全屏状态及原生窗口身份失效；按钮局部形状未变则复用遮罩；封面临时缩放缓存 |
| 松手 | WM_EXITSIZEMOVE 取消待执行更新，提交最终几何，生成需要的清晰封面并恢复普通模式 |
| 非拖动尺寸变化 | 保留普通几何更新；150ms 静默计时器统一处理方向切换与收尾 |
| 隐藏、关闭、全屏或预设切换 | 取消旧缩放任务，避免过期回调覆盖新布局 |

横竖屏在拖动结束后确定：宽高比不大于 0.9 转竖屏，不小于 1.0 转横屏，中间保持原方向。竖屏进入阈值保留原来的 0.9：六画面的横屏最小宽度会将 500×1000 的请求限制成 896×1000，若改为 0.85 就无法切换。用户明确选择另一方向的预设时立即执行并保留各方向布局记忆。

## 模块与分工

采用 codebase-design 的小 interface 和集中实现原则：

- 主窗口负责原生拖动生命周期、方向滞回和150ms收尾，不接触播放器解码设置。
- WallGrid 对外提供 `set_interactive_resize(active)` 和 `finish_resize()`，内部负责节流、最终提交、取消及 Tile 状态传播；现有分区树只计算坐标。
- Tile 负责一次几何更新内的视频和浮层一致性，以及封面、视频遮罩、按钮遮罩的缓存失效。
- VideoSurface 负责原生裁剪的去重和强制失效；保留周期巡检，修复 libmpv 更换窗口或重置裁剪区域的情况。

UI/UX Pro Max 的定向搜索未命中；使用其 quick-reference 中的 debounce-throttle、main-thread-budget 和 reduce-reflows 指导，具体 Qt/Win32 行为以现有源码与回归为准。

执行分工均使用 gpt-6.1-sol、medium：控件与画面墙代理负责 widgets.py；原生裁剪代理负责 video_surface.py 与必要的弹幕优化；验证代理负责整窗自检。主代理负责 app.py、文档、整合、静态检查和回归，各代理写入范围分离。

## 验证标准

- 1、6、16 格连续缩放时合并输入、持续更新，并在结束后准确落实最终尺寸。
- 移动窗口不产生布局提交；方向临界区不反复切换；显式预设切换仍立即生效。
- 视频 HWND、播放器对象和同方向缩放时的播放状态保持稳定。
- 相同遮罩不重复执行裁剪；真实尺寸、DPI、窗口重建及 libmpv 重置后仍恢复正确裁剪。
- 拖动期间不重复精绘封面，结束后恢复清晰显示；按钮位置、点击区域和圆角一致。
- 全屏进出、分隔线拖拽、侧栏收缩和布局记忆回归通过；关闭后无延迟布局任务。
- 类型检查与 lint 对照同一基线，无新增诊断；记录测试结果和调用计数，不能以调用量推断真实解码帧率。

既有音频改动不属于本次缩放优化，保持独立。

## 本轮验证结果

Windows 原生消息下，同一组 96 次尺寸输入，16 格布局计算从 PR13 基线的 144 次降为 49 次，减少约 66%。此计数使用 mock 播放器，不能推断真实解码帧率；33ms 是调度间隔，主线程繁忙时仍可能延迟。

新增三项缩放自检、六平台后台原生播放、六路真实播放器方向切换，以及预设、侧栏、弹幕和组合预设相关回归通过。独立复核发现并补测了“方向尚未提交时选择新预设或当前预设”的覆盖问题。类型检查及 lint 对照基线无新增诊断，新增自检脚本检查无错误。

旧 `selfcheck_tile_fullscreen.py` 的功能断言通过后，退出阶段发生 `0xC0000409`，PR13 基线亦能复现；该旧脚本整项不计为通过。跨显示器 DPI 仅完成模拟事件和倍率覆盖，未进行双显示器实拖。

Windows 冻结 EXE 另行通过启动、真实原生缩放消息、16 格几何与 HWND 保持、显式预设和正常退出检查：48 次尺寸输入合并为 23 次布局计算。57 个冻结业务模块与打包时源码一致，便携 ZIP 完整性检查通过。此打包验证包含工作区既有音频文件，不将它们纳入本次提交。

## 复现检查

Windows普通及最大化窗口的标题栏拖动直接由系统移动真实HWND。旧的鼠标捕获、阈值接管和替代预览窗口已移除；不会在抓起时抓图、创建预览或遮蔽真实窗口。吸附、双击及从最大化拖出均使用系统行为。

原生 `WM_ENTERSIZEMOVE` / `WM_EXITSIZEMOVE` 仍驱动既有的交互缩放标志与最终布局收尾。纯移动不改变客户区尺寸时不重排画面墙；跨DPI时Qt正常处理原生窗口及布局，因此不再提供旧预览对跨屏重配成本的遮挡。

最大化时不按屏幕方向改写普通窗口还原矩形。竖屏最大化采用竖屏布局，还原到横向普通窗口时恢复该方向记忆。最大化/还原只使用画面墙轻量模式和最终布局收尾，不禁用根布局或 Qt 重绘。

自检覆盖标题栏消息委托、无鼠标捕获/替代窗口、同屏移动不隐藏且不重排、原生最大化还原和双击。`--screens --players 3` 使用双屏、123张合成关注及三路本地视频，检查3/6/16格原生跨屏、DPI、播放进度、原生几何及HWND/播放器身份。程序化移动不能替代实际鼠标输入及视觉验收。

```powershell
python dev/run_checks.py --script selfcheck_display_transition
python dev/run_checks.py --script selfcheck_display_transition --timeout 240 -- --screens --players 3 --output work/display-transition.json
```

第二条需要两块已连接的屏幕，其中一块为竖屏；测试窗口会实际跨屏、最大化和还原，FFmpeg 临时生成本地视频，不使用用户配置或安装插件。输出为 Qt 布局调用与耗时、几何和原生身份检查，不代表 DWM 最终帧率。不同 DPI 下 Qt 本身的字体、原生窗口及遮罩换算仍有成本，需人工验收实际跟手感。

在已安装项目依赖的 Windows 环境，从仓库根目录运行：

```powershell

$env:QT_QPA_PLATFORM = 'windows'
python dev/selfcheck_resize_surface.py
python dev/selfcheck_window_resize.py --native-messages
$env:QT_QPA_PLATFORM = 'offscreen'
python dev/selfcheck_resize_widgets.py
```

整窗自检使用 mock 播放器并禁止网络，覆盖 1、6、16 格；可追加 `--baseline` 对照原始 PR13。真实多路播放仍需实测。源码验证记录已归档至本机 `work/test-artifacts/host/resize-20261019/`，历史 EXE 验证记录原位置为 `results/resize-test-20261019/`，运行日志、个人配置和打包产物不进入 Git。

## 方向切换的排布合并（2026-11-01）

侧栏切换为顶部横栏时会重新挂载工具控件，这些操作会同步激活根布局，导致画面墙在中间尺寸下重复调整原生视频。现在仅在 `_apply_orientation` 同一次同步调用内暂缓根布局计算，侧栏与预设确定后恢复并提交最终布局；`finally` 保留调用前的布局开关，异常后也不会冻结。此范围不跨越事件循环，不拦截 DPI，也不禁用 Qt 重绘。

本机 Windows、16 格、123 张合成关注、无真实直播的 cProfile 采样：横转竖排布 7→3 次、Tile 内部布局 93→29 次，方向函数约 1.35→0.41 秒；竖转横排布 8→2 次，方向函数约 1.47→0.79 秒。采样包含 profiler 开销及测试机原生窗口成本，不是实际呈现帧率或所有机器的速度保证。专项检查断言侧栏重组期间不排布中间视频几何，并覆盖异常恢复。
