# 窗口缩放性能

> 类型：设计 ｜ 状态：维护中 ｜ 适用版本：0.7.x ｜ 更新：2026-11-15 ｜ 读者：贡献者、维护者

本页记录当前窗口缩放的行为、职责和验收方法。2026 年 10—11 月的方案迭代、开发分工、采样数字及逐批测试结果保存在[历史实施记录](archive/resize-performance-202611.md)。

## 现行交互

| 阶段 | 行为 |
| --- | --- |
| 开始拖动或缩放 | Windows 原生移动/缩放消息确定交互状态；纯移动不触发画面墙的尺寸排布 |
| 连续缩放 | 画面墙合并中间尺寸输入，定时器处理最新目标；视频、底栏、弹幕和点击区域使用同一轮坐标 |
| 松手 | 取消待处理的旧尺寸，提交最终几何，恢复完整浮层与封面绘制 |
| 非交互尺寸变化 | 使用现有几何更新与 150ms 静默收尾；显式切换布局、全屏、隐藏和关闭时清理旧任务 |

横竖屏切换使用滞回：宽高比不大于 0.9 转竖屏，不小于 1.0 转横屏，中间保持原方向。用户明确选择另一方向的布局时立即应用。现有格子、播放器核心和视频 HWND 应随缩放复用；最终位置与窗口尺寸一致。

## 职责边界

- `ddm/app.py` 与 `ddm/window_layout.py` 管理原生交互消息、方向切换和最终收尾。
- `ddm/wall_layout.py` 与 `ddm/wall_widgets.py` 管理画面墙中间尺寸合并、分区几何和格子传播。
- `ddm/video_surface.py` 管理原生视频窗口裁剪；格子自身管理底栏、浮层和封面绘制。

修改缩放路径时，先确认是消息顺序、画面墙布局、Qt 控件重绘、原生窗口几何还是 Quick 弹幕遮罩耗时，再针对对应职责模块调整。局部调用次数或耗时不能直接当作桌面帧率。

## 验证与人工复查

`run.cmd --check-window-layout` 检查布局与窗口状态回归；相关缩放专项仍按[验证指南](development/testing.md)运行。`run.cmd --diagnose-window-resize` 在真实操作时将消息、布局和绘制调用耗时写入本机 `logs/window-resize.jsonl`，用于定位本次问题。

人工从根目录 `run.cmd` 在 1、6、16 格和横竖屏布局中连续缩放、移动、最大化拖出及跨屏移动，检查画面贴合、播放连续、弹幕遮罩和松手后的最终布局。2026-11-09 的根入口复查确认普通缩放明显改善、文字和按钮正常；最大化拖出时的闪烁与跨 DPI 手感仍应按真实现场重新验收。历史测量条件与局限见[实施记录](archive/resize-performance-202611.md)。
