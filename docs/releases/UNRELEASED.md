# v0.7.1 发布与开发记录

0.7 发布后的本轮更新整理于 [v0.7.1 更新说明](RELEASE-v0.7.1.md)。正式发布状态以 GitHub Release 为准；下方保留验收证据与历史开发记录，不将仍待定位的问题列为已修复。

## 未决问题诊断入口整合（待人工验收）

- 诊断工具1.3新增显式专项选择：文件夹错位、界面卡顿、通知关闭残留、弹幕回退、拖放异常、斗鱼播放/深度采集、主题及全屏切换耗时。已验收的SC黑块、交换残影、替换点击、全屏底栏和信息窗口层级不新增专项入口。
- 正式程序与根目录共用 `--diagnose-session=<类型>`。`Ctrl+Alt+F8` 留下时间标记；文件夹/卡顿模式还保存当前列表布局，通知模式保存可见状态，弹幕模式重新开启有限采样。保持原通知关闭和播放交互，不据此宣称 issue #149、弹幕回退或通知残留已修复。
- 生成包收集白名单中的已有专项及轮转JSONL，最多24份、每份末尾2MB；提供阶段与会话摘要、构建提交和入口协议。不收集SC源图，不读取聊天内容，不自动上传；历史日志按时间和会话区分。旧版主程序可继续收集现有日志，但新专项需支持该入口的主程序。
- 斗鱼深度模式显式使用本地中继，不能与普通播放当作无扰动性能对照。自动化检查仅验证采集功能和隐私边界，真实故障仍待采集定位。

## 开播通知点击关闭后残留（调查中，未确认修复）

- 2026-11-04 用户反馈：久用或疑似高负载时，点击开播通知“×”后记录已被关闭，但通知画面仍残留，多条可能延迟后同时消失；录制通知暂未遇到。目前不能复现，负载与根因未确认。
- 原关闭路径先移除记录，再等待 180ms 退场动画结束才隐藏窗口。先前尝试的“立即隐藏”提交 `5c18cb3` 仅为候选规避方案，用户要求先检查原因后已撤回；最终只保留只读采集与测试，原关闭策略不变。按“立即隐藏”目标编写的旧回归失败不证明原故障已复现。
- 开播通知独立创建，不走录制进度的固定编号复用路径。头像／封面回调仅更新样式与绘制，没有显式重新显示窗口。当前重点为图片背景绘制的界面线程开销、多个弹窗重排时的点击接收，以及 Qt／Windows 已隐藏后是否仍有旧画面；均需真实现场证据。
- 根入口 `run.cmd --check-notice-close` 检查原有关闭生命周期和只读采集；真实采集使用 `run.cmd --diagnose-notice-close`，补充鼠标按下／释放／clicked、开播分类、图像回调、paintEvent 与原生可见状态。2026-11-04 用户授权继续打包发布 0.7.1；发布保留原关闭方式，不上传实验性重建包，不并入未确认修复。

## 启动窗口与初始布局（已验收）

- 修复侧栏 Logo、标题、副标题和账号条在加入父容器前显示，导致启动时短暂出现多个独立小窗口的问题。
- 首次显示和最大化在首帧前同步完成画面墙布局，避免先显示小尺寸格子、再等待缩放定时器铺满窗口；首次绘制后的窗口缩放仍使用原有合并处理。
- 根据测试 EXE 的真实录像继续修正：在映射窗口前按目标屏幕和原生标题栏准备最大化客户区，避免 Windows 已显示大窗口、Qt 仍保留小布局的间隙。遮罩缓存读取已有 HWND，不在隐藏的构建阶段强制创建／重建原生窗口；普通底栏不再把事件过滤器挂到整面画面墙。
- 验证：隔离回归检查侧栏构造、隐藏期间不创建 HWND、原生窗口可见时的客户区尺寸、普通底栏过滤范围、首次最大化、横竖布局、后续缩放和隐藏重开；Windows 原生检查与真实发行版冷启动体验分开验收。
- 人工验收：正常退出后从根目录 `run.cmd` 启动，确认无独立小窗口、格子首次显示就铺满；再检查最大化／还原及横竖缩放。EXE 必须使用包含本修复的新构建，原 0.7 发行文件不会自动改变。
- 2026-11-03 用户确认 preview2 测试 EXE 验收通过，PR #148 已合入 `develop`。本机相同空配置窗口显示仅快约 0.3～0.4 秒，保留这一测量范围；正式 0.7 发行文件尚未更新。

## 标题栏拖动与拖放目标异常（待验收）

- 修正 Windows 标题栏拖动读取原生消息窗口句柄的字段，避免触发 `MSG` 没有 `hwnd` 属性的异常。
- 拖入房间时先确认目标仍在画面墙并保存目的格子编号；交换或布局刷新后沿用该编号，避免再次查找已移出列表的旧目标。已失效的排队拖放不再改动房间或启动播放器。
- 回归覆盖真实 `wintypes.MSG` 字段读取、目标在交换刷新中被替换、投递前移除及播放器不重建。两处实际异常来自 2026-11-03 日志；本批不据此宣称三次 `AppHangB1` 的死锁根因已经修复。

## 普通画面悬浮条与光标静置隐藏（已验收）

- 非全屏画面内鼠标静置约 3 秒后隐藏上方控制按钮、LIVE／标题及时长浮标，移动鼠标后恢复；底部控制栏保持显示。
- 同时隐藏视频区域内的光标，移动、离开画面、打开菜单或隐藏窗口时恢复原来的光标；原生视频子窗口也生效，不使用普通画面的全局光标覆盖。
- 悬停控制按钮、打开菜单、按住鼠标或操作弹幕输入控件时保留悬浮条；隐藏后继续检测鼠标移动，离开画面及隐藏窗口时停止对应轮询。全屏继续使用原有显隐流程。

## 临时菜单与背景主题订阅释放（已验收）

- 格子右键和画质菜单在执行结束后释放，包括取消与异常返回，避免临时菜单、滑条及回调随使用次数累积；保留原有音量、画质与插件操作。
- 背景层以 Qt 槽接收主题变化，销毁后自动断开连接，避免全局信号保留已销毁控件及其图像、再次切主题时回调已销毁对象。
- 新增 `selfcheck_widget_lifetime` 并加入 `smoke` / `offline`，根目录可用 `run.cmd --check-widget-lifetime` 一键检查菜单重复进退、交互与异常收尾，以及背景销毁后的弱引用回收和无异常回调。该生命周期回归不替代真实直播的长期内存验收。
- 2026-11-03，用户确认根目录人工验收通过，PR #139 已合入 `develop`；验收范围为本轮菜单与背景主题订阅释放修复，不表示软件所有长期内存或原生空指针问题均已排除。

## 独立全屏呈现与弹幕尺寸缓存（已验收）

- 目标格子临时独立呈现到全屏区域，原主窗口、侧栏和画面墙保留尺寸与位置；退出时回到保存的位置，不重排画面墙。继续使用原播放器和视频 HWND，不使用截图定格过渡。
- 共享 Quick 弹幕沿用原窗口与纹理，切换呈现区域、坐标偏移和原生所有者；快捷键、闲置光标、底栏及托盘恢复跟随当前呈现窗口。
- 尺寸变化先复用当前弹幕纹理，需要改变字号／描边／裁切／DPI 时由后台 QImage 绘制最终内容，再回到界面线程替换。每条当前弹幕最多保留两个尺寸；快速切换、改设置、表情加载和清空后，旧任务结果不能覆盖当前状态。
- 普通 `run.cmd` 的全屏采集继续保留，记录界面帧间隔及后台重绘待完成状态。功能回归与原生后台检查不能替代真实直播的黑帧、闪烁及流畅度验收。
- 2026-11-02，用户在根目录开发版完成本轮人工验收，反馈“体感非常好，我个人验收通过”。此结论对应独立全屏呈现的切换体验；其他专项问题与跨屏／高 DPI 场景仍按各自记录跟进。

## 全屏输入弹幕时控制栏闪烁（已验收）

- 全屏底栏改为由 Qt 统一绘制的透明工具窗口，完整保留按钮、输入框和光标，避免手动透明上传与普通控件重绘交替覆盖；全屏切换完成后显式恢复底栏刷新，并遮去只读原生标签的重复黑底；退出全屏恢复原来的子控件底栏。
- 保留自动隐藏、反向动画、画面尺寸、输入草稿及交互；底栏跟随主窗口移动，隐藏主窗口时同步隐藏；Windows 全屏显隐使用固定位置的淡入淡出，避免滑入时移动原生窗口造成错位，保留动画反向中断和系统动画开关。完全隐藏后重新唤起时，先完成布局再启动动画，并屏蔽起止值配置期间的中间信号，避免瞬间闪现或跳过淡入。
- 根入口支持 `run.cmd --diagnose-fullscreen-input`，在首次输入后最多采集 20 秒、300 条重绘／焦点事件，不记录输入文字；普通启动不启用该专项采集。

## 开播提醒选择替换画面（已验收）

- 当前布局没有可见空格时，开播提醒操作改为“替换”。点击后，再点击画面墙内的目标画面，沿用既有换房流程替换该格；不扩展布局、不自动挑选目标。
- 有空格时仍直接放入；已经上墙的房间不重复添加。选择期间可按 Esc 取消，隐藏或关闭主窗口同样取消，侧栏点击不会误替换。

## 手动停止即时回放缓存时保存（已验收）

- 手动选择“停止即时回放缓存”后，先完成正在写入的片段，再按设置保存最近 N 分钟到录制目录的 replays 子目录；不足 N 分钟则保存已有内容。
- 保存失败保留原始分段；停止后不会被自动缓存策略立即重新开启。明确停止保存后立即退出也会完成导出，普通退出、自动清理缓存不额外生成回放文件。

## 设置导航与即时回放标识（已验收）

- “托盘行为”移到“插件”上方，插件、软件更新及独立设置窗口对应页面同步调整。
- 仅开启即时回放的格子显示蓝色“● REC”，完整录制沿用红色“● REC”；窄格子沿用圆点简写。点击行为、按钮尺寸和录制／回放逻辑沿用原有行为。

## 可改名、可切换的默认文件夹（已验收）

- 新用户初始默认文件夹命名为“默认关注”，已有“未分类”或自定义名称保留。
- 默认文件夹支持行内改名、图标编辑中的名称修改、拖动和独立排序；为空时同普通文件夹一样显示，添加、导入和移入菜单使用实际名称。
- 普通文件夹右键可“设为默认文件夹”。切换保留已有关注的归属、文件夹名称、顺序及智能规则来源，原默认文件夹成为普通文件夹；新添加或未指定分类的关注进入新的默认文件夹。
- 删除文件夹保留关注；删除当前默认文件夹时自动改用另一个普通文件夹，最后一个非智能文件夹保留作为接收目标。保存重启后保留默认选择，不重建已删除的旧“未分类”文件夹。

## 主程序单实例运行（已验收）

- 打包版本同一用户只能运行一个主程序，重复启动时唤回已有主窗口；最小化或隐藏到托盘时恢复窗口，保留当前直播与布局。源码开发版允许多开，方便同时测试。
- 第二实例只发送本机唤回请求后退出，不重复加载账号配置、创建主窗口或播放器；设置子进程与更新助手不受限制。异常退出后可重新启动，设置触发重启前主动释放实例锁。

## 托盘行为设置（已验收）

- 新增“设置 → 托盘行为”，从常规页移入“关闭窗口时”选项；默认开启“进入托盘后暂停播放”，关闭后继续后台播放。普通最小化及切换到其他软件不触发。
- 隐藏到托盘时释放观看播放器并取消取流／重试；恢复主窗口时重新连接直播，原本手动暂停的格子保持暂停。独立录制继续运行，正在启动的录制完成取流后再停止观看。

## 逐格直播流信息面板（已验收）

- 播放格子的右键菜单新增“直播流信息…”，每格独立打开并每秒刷新，重复点击复用窗口；切流、重连后跟随当前播放器，格子清空或移除后自动关闭。
- 展示播放状态、封装格式、libmpv 内核、视频编码／分辨率／帧率／解码方式、音频编码／采样率／声道／码率、流编码器、源服务器域名、缓冲时长及大小、解码帧率和丢帧、视频码率及下载速率。
- 未提供的字段显示未知，停止或重连时不沿用上一条流的数据；下载速率与编码码率分开，代理分片估算明确标注。仅展示域名，不展示含鉴权参数的播放 URL。

## PR104 醒目留言交互与设置（已验收）

- 弹幕栏醒目留言改为文本视口之外的独立覆盖层，普通弹幕滚动与历史翻阅不再移动 SC。
- 每条 SC 独立保存折叠状态和截止时间，点击只展开该条；同 ID 刷新、新留言及其他卡片点击不重置已有留言计时。
- 「设置 → 弹幕」加入可拖动摆放、右下角缩放的 SC 缩略图；画面弹幕菜单提供进入设置的入口，沿用相对位置及 75–200% 大小设置，双击恢复默认位置与大小。设置作用于视频和弹幕栏。
- SC 调节示例使用不含关注栏的简化布局，展示大主画面、右上两路小画面和右下弹幕栏；不读取播放截图、不显示弹幕或 SC 示例正文，仅以色块展示 SC 的位置、大小和不透明度。两种调节目标沿用外观页圆角按钮样式切换，设置值同步；滑块和自动折叠输入框缩短，不再填满整行。独立设置窗口同样支持。

1. 浏览器只读取目标主播的身份、固定房间号及必要卡片资料，核对主页身份和房间归属，不从链接参数猜测主播 UID。
2. 本体将已确认的主页资料交给插件；首次添加直接使用该资料，避免再次匿名请求导致失败。
3. 主页资料仅供一次添加使用，60 秒后失效；官网未给出直播状态时保留“待刷新”，不将未知状态当成已开播或已下播。
4. 后续状态刷新、取流与弹幕继续读取实时资料；保存并恢复已确认的主播 UID 映射，不保存该临时快照或播放地址。
5. 页面解析失败时尝试公开房间接口；失败提示及日志区分超时、HTTP 拒绝、非 JSON、缺少房间资料及验证相关页面特征。日志不记录凭证、页面正文或带签名的播放地址。

本体和插件需要配套更新，不能只更新插件后宣称已应用完整修复。正式发布需从届时根目录已提交的完整开发源码构建，使用相同 Qt 依赖；插件从独立源码仓构建，不复制本机安装副本。

## 虎牙多路播放：历史排查与后续验收

以下保留第6/7版阶段的排查记录；后续修复及验收状态见本节末尾。

### 已确认的现象

- 同一用户此前使用原本体能播放虎牙；第 6 版同时播放 `dank1ng`、`124952`、`814814` 时反馈后两路断连，降低画质无效。日志中 `dank1ng` 也曾失败后恢复。
- 最新日志有 8 条播放器 HTTP 403 分类、5 条 HTTP 503 分类，并出现取流超时、TLS 失败及连续画面静止刷新。
- 本地 HLS 转发器收到部分 401/403 后设置 `refresh_required`，后续请求会收到本地产生的 503。因此不能将所有 503 当作 CDN 故障。
- 尚未确认首次拒绝发生在清单还是分片、具体 CDN 是否持续拒绝，以及新转发路径是否造成回归；现有日志没有证明解码器是原因。

### 下一步修复顺序与验收条件

1. **先复现后续分片拒绝。** 本地 HTTP 服务模拟清单和首分片成功、后续分片返回 403；记录转发器收到的上游错误与本地产生的 503。补充清单/分片类别、脱敏 CDN 主机、播放会话、重连次数及换源结果，不记录完整签名地址或 Cookie。
2. **验证恢复时实际换源。** 403/401 后作废该次取流结果，重新取得签名和候选 CDN；同房间、同画质优先尝试其他可用线路，短期避免反复选择刚失败的线路。一次恢复穷尽可用候选后有界失败，保留用户画质及正常房间的播放，不仅重试同一个旧地址。
3. **合并恢复时序。** 断流与画面静止检测共用同一格子的恢复入口；已有取流任务或恢复计时器时不叠加请求。短暂进入 `playing` 不应立即清除所有失败退避，需持续恢复后再复位；停止、换房和关闭时取消待执行恢复，迟到结果不得覆盖新会话。
4. **检查转发是否必要及是否兼容。** 保留已经验证的请求头与 HTTP 行为，在同房间、同画质下对照直接播放和转发播放。仅在证据表明适用时使用或切换路径，不把所有拒绝归因于用户网络，也不直接扩大为全平台播放器改造。
5. **分层验收。** 自动回归覆盖“后续分片 403 后换源恢复”“所有线路拒绝后退避”“一个房间失败不影响其他两路”“停止/换房后无迟到恢复”。在根 `run.cmd` 复测后，由用户对相同三路依次做单路和三路持续播放，分别记录清晰度、断连次数与恢复时间。

当时的结论仅覆盖对应测试版，后续验收记录见下文；历史产物保留。

### 测试版 7 的实施范围（历史记录）

- 同房间重连时，60 秒内将播放中失败的 CDN 排在其他线路之后，重新取签名并探测候选；不改变其他房间和手选画质。
- 播放错误或缓冲期间不再用静止画面触发额外刷新；虎牙已有取流任务或重连计时器时不叠加恢复。连续播放 15 秒后才重置失败退避。
