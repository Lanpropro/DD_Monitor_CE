2026-10-14 点击准备延迟优化：浅色例外样式改为一次安装、按 `appearanceLight` 属性启用，避免每次切换重设全部关注卡片和格子控件的样式。开播圆点使用调色板边框色，默认文件夹图标复用缓存；深浅模式固定使用 8 像素格子间距，避免切换时重排原生视频窗口。快照只绘制界面区域，跳过直播输出。模拟 67 张卡片、3840×2160 大窗口的同一耗时分析中，首次准备约 307ms 降至约 130ms；无耗时分析器的后续测量约 80ms，机器和实际素材会影响结果。保持 360ms 扩散时长。`dev/selfcheck_theme_latency.py` 检查样式重设少于 20 次、图标缓存及视频几何保持，并记录各阶段耗时。

## 深浅色模式

### 入口与交互

设置新增独立「外观」页面，在页面最上方放置「深色 / 浅色 / 跟随系统」三选一控件，每项配小型界面缩略图。下方预览关注卡片、文件夹、菜单和顶部提示，方便比较可读性；后续皮肤选项放在同一页面。

主界面外置主题入口改为 22×22 纯图标按钮，放在真实关注栏上方的状态工具行，位于「排序」和刷新按钮之间。使用半明半暗圆形图标，悬停提示下一次切换的目标模式和当前模式。不在底部「布局预设 / 设置」行增加文字按钮，不增加侧栏宽度或额外工具行。

竖屏沿用现有排序、刷新工具移至顶部第一行的布局，外观图标与它们同组。关注栏收起时，横屏和竖屏均隐藏主题按钮；展开后恢复，不占用收起栏的头像位置。设置 → 外观入口继续可用。

点击图标直接切换深浅色，不弹出菜单或设置窗口；跟随系统及其他外观选项统一在设置 → 外观中调整。当前跟随系统时，点击图标切换到实际显示模式的相反模式，保存为手动选择，之后不再跟随系统，直到用户在设置页重新选择。外置按钮与设置页面共享同一选择，不各自保存状态。全屏观看不额外覆盖视频。

交付流程：先给用户查看深浅色方案截图，用户确认后再实装；目前已按确认方案接入真实软件。侧栏外观图标和设置 → 外观均可立即选择并保存，设置窗口取消只取消其他设置，不撤销已经生效的外观选择。

点击选项立即应用并保存，无需另点确认；首次升级保持深色，不擅自改变用户现有外观。跟随系统时展示「当前：深色」或「当前：浅色」。设置中的恢复默认回到深色。

切换只重绘界面：不创建新播放器，不重新绑定视频 HWND，不重连直播，不清空弹幕，也不改变录制、布局、音量和画质。菜单与新打开的窗口使用当前模式；已打开的弹幕窗口和设置同步更新。

深浅色切换动效（2026-10-13）：鼠标操作使用 360ms 圆弧扩散过渡，深浅色都从触发按钮的左上角流出，向右下方展开至整个窗口；外置按钮与设置页按钮各自作为起点。参考 [Chrome 官方圆形扩散实例](https://developer.chrome.com/docs/web-platform/view-transitions/same-document#animating_with_javascript)，使用 Qt 原生动画与 cubic-bezier(0.23, 1, 0.32, 1) 曲线，参数集中在 `ddm/motion.py`。只裁切旧界面快照，视频区域透明，直播继续播放，浮标参与颜色过渡。连续点击保留当前可见的混合画面，再从按钮流出下一种颜色，不出现整页闪回；移动、缩放、隐藏或关闭相关窗口，以及外部系统主题变化时立即清理快照。设置窗口与主窗口同步过渡，不拦截鼠标操作。键盘操作、启动恢复及系统关闭动画时即时切换。每帧不改布局或主题样式，结束释放快照；实现见 `ddm/theme_transition.py`。

切换性能：全局 QSS 结构保持不变，颜色通过调色板更新并清除绘制缓存；浅色媒体控件的局部例外单独处理，新创建控件也适用。每次普通切换只抓取一次旧界面，切换期间暂停主窗口重绘并移除动画的全局事件过滤器；不重新应用整份全局 QSS。本机 60 个关注项、16 个格子、1440×900 测试场景中，使用相同分析工具测得点击准备耗时由约 717ms 降至约 177ms（不含 280ms 动画时长，具体时间随设备与界面规模变化）。`dev/selfcheck_theme_palette.py` 对比旧配色方案的实际像素输出，并检查局部自定义调色板保留；`dev/selfcheck_theme_wave.py` 检查起点、透明视频区域、打断时的画面连续性和清理行为。

### 视觉规格

深色完全沿用当前软件的 `ddm/theme.py` 配色、透明度、字体、圆角、间距、局部样式与自绘效果，不采用上一版手绘方案图的深色数值。浅色采用冷灰底、白色卡片，蓝色用于选择与操作，粉色用于直播提示。实际视频画面与 VLC 原生黑边保持原样；空格子、尚未加载的视频底及弹幕格改用浅色。底部控制条也采用浅色文字与图标、透明底，不再显示整块灰黑遮罩；深色模式底栏遮罩透明度从 0.72 减至 0.24。

2026-10-13 用户补充：浅色模式下格子顶部悬浮栏也改为浅色。LIVE/人数浮标、主播/标题浮标、直播时长浮标及右上角画质/刷新/关闭按钮统一使用 #F7F9FC 底色与 #D7DDE7 细边，正文和图标 #202630，次要标题/时长 #4A5565；LIVE 字样保留 #B93665 粉色强调。悬停使用 #E7EFF7 底色与 #007BA8 图标。沿用现有圆角、位置、宽度省略及原生遮罩，不移动控件；底部控制条也采用浅色，不改变其位置和播放功能。预览检查实际绘制出的浅底与深色文字；深色浮层不改变。

左侧浮标边缘修正：避免用逻辑整数 QRegion 再裁切抗锯齿边缘，保留透明像素的圆角过渡；1px 细边框向内收半像素，避免描边被画布截断。截图检查 LIVE 与标题浮标均保留半透明过渡像素，尺寸及位置不改变。正式原生视频浮层实现使用 `ddm/badge_surface.py`，通过 Windows 分层子窗口与逐像素 alpha 合成，深色恢复原窗口样式与遮罩；已验证透明圆角、实际视频背景、按钮点击及模式往返。没有直接把无遮罩预览覆盖到原生视频上。

### 接入与验证

配置增加 `settings.appearance_mode`，取值 `dark`、`light`、`system`，缺失或非法值回退 `dark`。实际系统模式与用户选择分开，保存的是选择。

复用 `ddm/theme.py` 的令牌与 `qss()`；自绘控件、硬编码颜色、缓存图标与局部样式统一在模式变化时刷新，不另建一套窗口。顶部视频浮层使用对应模式的独立配色，底部视频控制条按当前模式刷新图标和文字，实际视频不随主题重新着色。系统变化使用 Qt 的 `QGuiApplication.styleHints().colorSchemeChanged`；无法识别系统模式时回退深色。

实施前盘点 `ddm/widgets.py`、`ddm/dialogs.py`、`ddm/app.py`、账号窗口、弹幕与菜单的颜色入口。验证两种配色的正文对比度；测试选择持久化、旧配置升级、系统变化与非法值回退。原生 Windows 下验证多路播放、全屏、录制和弹幕持续运行，切换前后播放器对象与 HWND 保持一致。横竖屏和 100% / 175% 缩放检查文字、边框、菜单及浮层。

## 修改文件夹图标

### 入口与交互

普通文件夹和智能文件夹的右键菜单增加「修改图标…」，放在重命名或编辑规则之后。打开小型对话框：顶部显示当前图标与文件夹名称，中间是图标选择区，底部为「恢复默认」「取消」「保存」。

内置图标首版提供文件夹、星标、爱心、游戏、音乐、视频六种统一线性图标。选中时显示蓝色边框与勾选；颜色提供默认、蓝、粉、绿、橙、紫六种，默认色随主题变化。图标预览立即变化，点击保存才修改真实文件夹；取消不改变配置。

「选择本地图片…」支持 PNG、JPEG、ICO。导入时保持比例，居中缩放进正方形画布，不拉伸、不直接裁掉边缘。图片原色保持不变，不提供着色选项；透明图片在深浅两种背景上并列预览。

普通文件夹默认为文件夹图标，智能文件夹默认为现有智能文件夹图标。自定义后智能文件夹仍保留「智能」文字或规则提示，避免只凭图标判断类型。展开箭头独立于图标，修改图标不会改变展开、排序、拖放或关注归属。

### 尺寸与保存

列表中图标为 18×18 逻辑像素，选择区预览为 24×24，当前图标预览为 32×32。内置图标采用矢量路径，按主题与 DPI 绘制；本地图片导入为 256×256 PNG，运行时按实际 DPR 缩放，保留透明度。

文件夹记录增加可选字段 `icon`：内置图标保存类型、名称和颜色，本地图片保存相对文件名。图片复制到软件目录 `utils/folder-icons/`，以独立随机文件名存储；不保存原绝对路径，用户移动或删除原图片后图标仍可用。不修改用户源图片。

导入上限 5MB、4096×4096 像素，先检查尺寸再解码。无法读取、格式不支持或超限时保留当前选择，显示明确原因。保存失败保留旧图标并提示重试；缺失或损坏的已保存图片回退默认图标，避免影响软件启动。恢复默认在保存后生效；删除文件夹不额外扫描或清理其他用户文件。

### 接入与验证

复用 `FollowFolderButton` 当前图标入口和文件夹保存流程，新增选择对话框；配置规范化保留合法 `icon` 字段，旧文件夹无字段时保持默认。

实施测试覆盖普通/智能文件夹、选择/取消/保存/恢复、重启保持、源图片删除后的恢复、非法配置和缺失图片回退。验证透明图片、非正方形图片、175% 缩放、横竖屏标题旋转，以及修改图标后的展开、排序和拖入卡片功能。
