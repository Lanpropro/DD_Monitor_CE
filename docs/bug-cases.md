# Bug 案例库

更新：2026-11-02。用于展示、检索和回归，不是待更新功能清单。

范围：归纳截至本日的历史反馈、版本说明、集成记录及本轮诊断；同类重复反馈合并为一个案例。没有留下记录的问题无法追溯，不声称覆盖未记录的故障。已解决案例保留，不因合并 PR 或发布而删除。

## 状态说明

- **已验收**：有用户明确确认；确认只覆盖所述版本和操作范围。
- **已修复待验收**：已有代码和验证记录，但缺少相应用户确认；不代表已经发布。
- **已实现待合并**：修复位于独立 PR 或本地组合，尚未合入 develop。
- **历史修复待复核**：历史版本记录过修复，不能直接当作当前 libmpv 版本的完整验收。
- **待定位**：有现象记录，具体根因或修复仍未确认。
- **暂缓定位**：保留现象与证据，按用户要求暂停主动定位；不代表已修复或已确认为普遍缺陷。
- **待复现**：证据不足或缺少同条件对照，暂不认定为已确认缺陷。
- **测试或环境记录**：不是已确认的产品缺陷，单列以避免误诊。

功能需求不混入 Bug 数量：例如 Del 快捷键、弹幕黑色描边、自定义布局、常看优先、全局音量和画质入口。

## 重点案例：Del 清格后拖放失效与崩溃

### BUG-001：WASAPI 清理破坏主线程 COM 状态

**状态：已验收。** 2026-10-21 用户确认首次操作恢复，随后重启再次测试未复现，明确同意验收及合并。修复 [PR30](https://github.com/Lanpropro/DD_Monitor_CE/pull/30) 已合入 develop，合并提交 `ae82165`；不等同于已发布 EXE。

**现象**：抓起关注卡片即出现禁止指针，看不到拖拽影像；所有格子和关注列表排序都可能无法接收，继续抓卡还可能卡死或崩溃。曾在九格切回 1+5 后出现，也曾在停止录制、Del 清格后出现。

**用户确认的精确复现序列**：

1. 选择 1+5 布局，拖入一路直播。
2. 鼠标位于该格子，按 Del 清空。
3. 再拖入一路，随后再次 Del 清空。
4. 切换九格，再拖卡片，出现禁止指针；继续尝试可能崩溃。

只需单路播放；多路解码、录制和九格缩减到六格都不是必要前提。该路径偶发，单次成功不足以验收。

**证据链**：

- Qt 已创建卡片图像和正确 MIME；失败拖动没有进入目标的 DragEnter/Drop。返回 IgnoreAction，不能归为某个空格拒收。
- 原生栈位于 `QDrag.exec -> DoDragDrop -> InternalGetWindowPropInterface2 -> COM/RPC`；出现 `0x80010012`，崩溃为 combase.dll 的 `0xC0000005`。
- 第二次 Del 的停止播放器阶段，GUI 主线程从 MAINSTA 变为隐式 MTA，主线程 OLE 窗口消失；变化发生在切换布局之前，主 Qt 窗口句柄及拖放属性仍保留。
- 经用户授权的本地硬件断点捕获到 libmpv 在 GUI 线程调用 `CoUninitialize`。静态函数边界、相邻 WASAPI 日志字符串与实际版本源码相互对应；最近导出的函数名不冒充精确内部符号。
- 临时本地 WAV 回归在旧实现第 0 轮终止后得到 `CO_E_NOTINITIALIZED`。没有其他 MTA 持有者时，表现为未初始化而非隐式 MTA；两者均不是正常 Qt STA 状态。

**根因与最小修复**：默认 gapless audio 会保留音频输出至最终销毁；GUI 线程调用终止 API 时，遗留的 WASAPI 输出在该线程清理并调用 `CoUninitialize`，破坏 Qt 依赖的 COM 生命周期。嵌入播放器设置 `gapless_audio=False`，使音频输出在 mpv core thread 结束播放时释放。没有替换 OLE 拖放、重置系统 COM、无限补初始化引用或更换系统 DLL。

**排除与纠正**：

- Windhawk 排除后、进程无其模块时仍复现，不能把注入当作必要原因。
- Del 不是唯一可触发播放器释放的入口；布局切换只是曾经观察到的邻近操作。
- PR28 的回调引用和占位恢复是独立加固，不能把它当作本例根因修复。
- mpv 原生窗口确有独立 OLE 注册，但源码有 RevokeDragDrop；没有证据证明遗漏撤销。禁用内置窗口拖动也不等于禁用文件拖放注册。
- 部分异常是进程仍存活时的 first-chance COM 异常；不把每条异常日志都称为一次崩溃。

**回归与验收**：

- `selfcheck_player_lifetime` 覆盖普通/预览构造参数、重绑和重复释放，先红后绿。
- `selfcheck_mpv_com_lifetime` 使用临时静音 WAV，直接终止、正常 release、预览绑定清理各 30 轮通过；不读取账号、不联网、不模拟真实 OLE 拖放。
- 当前本地组合的 offline 33/33、smoke 8/8、repository 8/8 通过；用户随后完成真实拖动及重启验收。
- 独立开发基线的既有 composer 测试曾有后台请求越过 stub 生命周期的审计失败；这不是播放器回归通过的证据，另见 BUG-060。

遇到相似症状时先比对 COM apartment、清理调用线程和实际错误签名；不要仅凭“禁止指针”直接套用本根因。原始诊断仅本机保留，不上传账号、完整内存或个人路径。

## 启动、账号与发行环境

### 2026-10-30：拖放复发的临时开发版记录

用户报告正常使用中再次出现关注卡片消失、禁止指针、无法拖入播放框，本次没有 Del 清格或切布局操作。故障进程 GUI 线程仍有 Qt 窗口，但只读枚举未发现该线程的 `OleMainThreadWndClass`；正常同版本 Qt 对照存在此窗口。此线索与 BUG-001 相符，不等于已直接读取故障线程 COM apartment，也不能确认本次由 WASAPI 引起。现有播放器 COM 生命周期检查 terminate/release/preview 各 30 轮通过，尚未复现，问题继续定位。

临时将源码开发版 `run.cmd` 重定向到 `dev/diagnose_drag_windows.py`，再启动原 `main.py`；模拟器、控制台入口及发布 EXE 不自动启用。每 500ms 只读检查 GUI 线程 COM 状态，仅基线和变化写详细快照；同时记录播放器操作前后的状态变化调用链、拖动开始/返回以及目标收到的拖放事件。不修改 COM 初始化计数，不记录拖放内容或 Cookie。

日志在 `logs/drag-windows.jsonl`，单文件 5 MiB，保留 3 个轮转备份；复发后结合当日 `ddm-*.log` 和发生时间分析。找到并验证原因后，恢复 `run.cmd` 的 `main.py` 入口，删除临时脚本及专项测试，并移除测试索引/套件和仓库地图的对应条目。本段保留为调查记录，不把临时诊断标记为修复。

2026-11-01 用户反馈卡片拖动排序有所缓解，但偶尔抓起停顿、卡顿后拖影黏住指针。补充轻量分阶段记录：`drag:press`、`drag:stage`（pixmap/lift/layout/hook）、`snapshotMs`、`previousWriteMs`，以及进入/返回原生拖放时的 Qt 与 Windows 左键状态。拖放期间以 50ms 定时检查记录超过 150ms 的消息处理间隔及观察到的松键；定时回调可能受原生拖放循环调度影响，不等同于桌面呈现帧率。拖放总持续时间包含用户操作，不能直接当成卡顿时间。新增记录须重启根目录 `run.cmd` 后生效；日志仅本机保留，不记录账号凭据或弹幕内容。

同日后续复测仍有一次黏住，日志观察到物理左键松开后约 1.34 秒拖放才返回；不能仅凭此判断丢失松键或直接取消原生拖放。增加仅在一次拖放期间运行的后台调用栈采样：消息心跳间隔或持续松键超过 150ms 时，最多采集 8 条 `drag:stall-stack`，只保留主线程函数名、文件名和行号，不读取局部变量或调用 Qt。拖放结束后写入日志并停止采样。同时补录排序、放入播放格、预览和播放器收尾的慢调用耗时，以区分原生拖放等待与业务回调阻塞。

## 2026-10-31：滚动弹幕超出设置速度

### BUG-068：垂直同步关闭时渲染线程动画超速

**状态**：已验收。2026-10-31 维护者转述反馈用户“验收通过”，覆盖本次滚动弹幕超速修复；具体启动方式未另行说明，不扩大为所有显示配置均已验证，也不代表正式安装包已更新。

**反馈与视频证据**：反馈用户使用当时最新发布版，笔记本外接 200Hz 显示器，关闭垂直同步。约 49.5 秒、1920×1080/120fps 的录屏中，35 秒处观看设置显示弹幕速度 116%；30.55—30.75 秒同一条问号弹幕约向左移动 721 像素（约 3605 像素/秒），明显超过设置上限 200% 对应的约 4 秒完整穿屏时间。视频原始文件仅本机留存，不能仅凭录制帧率推断实际显示器刷新率。

**定位与对照**：Python 使用 perf_counter 按实际时间维护轨道；视觉位置使用 Qt Quick XAnimator。Qt 默认渲染线程动画驱动在每次渲染时按刷新周期累计时间，依赖垂直同步限速。关闭或失去该限速时，渲染线程可能比实际时间更快地推进动画。Qt 官方场景图文档说明了此限制及实际时间驱动选项：https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html 。

本机在窗口外使用合成弹幕、swapInterval=0 / QSG_NO_VSYNC=1 复现同类机制：设定 100 像素/秒，默认驱动实测约 1013 像素/秒；新增严格速度断言在旧计时下失败（另一轮约 1994 像素/秒）。启用 QSG_USE_SIMPLE_ANIMATION_DRIVER=1 后独立对照约 99.92 像素/秒，回归约 100.16 像素/秒。具体倍率受机器与渲染负载影响，不能套作原机精确倍率。

**最小修复**：在共享 Quick 弹幕层初始化前默认选择上述基于实际经过时间的 Qt 动画驱动；保留渲染线程动画，不调小用户速度、不按显示器刷新率补倍率、不修改显卡设置。显式已有的环境变量仍保留。后台 GUI 阻塞 350ms 时，修复后的视觉动画仍前进约 35 像素；定时器对照在阻塞期间不动。

**验证与边界**：selfcheck_danmaku_render_thread 增加实际像素/秒断言及 --unthrottled 路径；先等待初始场景图同步再计量，避免把首帧同步跳变混入速度。测试采样原生场景图变换，不代表最终桌面合成或原用户实机效果。反馈用户已确认验收；后续若复发，再收集脱敏诊断包以核对实际版本、速度配置及显卡驱动。现有诊断工具不收集各显示器刷新率、排列及驱动垂直同步开关，这些需单独说明。
