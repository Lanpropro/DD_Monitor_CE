# Bug 案例库

范围：归纳截至本日的历史反馈、版本说明、集成记录及本轮诊断；同类重复反馈合并为一个案例。没有留下记录的问题无法追溯，不声称覆盖未记录的故障。已解决案例保留，不因合并 PR 或发布而删除。

## 状态说明

- **已验收**：有用户明确确认；确认只覆盖所述版本和操作范围。
- **已修复待验收**：已有代码和验证记录，但缺少相应用户确认；不代表已经发布。
- **已实现待合并**：修复位于独立 PR 或本地组合，尚未合入 develop。
- **历史修复待复核**：历史版本记录过修复，不能直接当作当前 libmpv 版本的完整验收。
- **待定位**：有现象记录，具体根因或修复仍未确认。
- **待复现**：证据不足或缺少同条件对照，暂不认定为已确认缺陷。
- **测试或环境记录**：不是已确认的产品缺陷，单列以避免误诊。

功能需求不混入 Bug 数量：例如 Del 快捷键、弹幕黑色描边、自定义布局、常看优先、全局音量和画质入口。

## 重点案例：Del 清格后拖放失效与崩溃

### BUG-001：WASAPI 清理破坏主线程 COM 状态

**状态：已验收。** 2026-10-21 用户确认首次操作恢复，随后重启再次测试未复现，明确同意验收及合并。修复 [PR30](https://github.com/Lanpropro/DD_Monitor_CE/pull/30) 已合入 develop，合并提交 `ae82165`；不等同于已发布 EXE。

**现象**：抓起关注卡片即出现禁止指针，看不到拖拽影像；所有格子和关注列表排序都可能无法接收，继续抓卡还可能卡死或崩溃。曾在九格切回 1+5 后出现，也曾在停止录制、Del 清格后出现。

**用户确认的精确复现序列**：

1. 选择 1+5 布局，拖入一路直播。
2. 鼠标位于该格子，按 Del 清空。
3. 再拖入一路，随后再次 Del 清空。
4. 切换九格，再拖卡片，出现禁止指针；继续尝试可能崩溃。

只需单路播放；多路解码、录制和九格缩减到六格都不是必要前提。该路径偶发，单次成功不足以验收。

**证据链**：

- Qt 已创建卡片图像和正确 MIME；失败拖动没有进入目标的 DragEnter/Drop。返回 IgnoreAction，不能归为某个空格拒收。
- 原生栈位于 `QDrag.exec -> DoDragDrop -> InternalGetWindowPropInterface2 -> COM/RPC`；出现 `0x80010012`，崩溃为 combase.dll 的 `0xC0000005`。
- 第二次 Del 的停止播放器阶段，GUI 主线程从 MAINSTA 变为隐式 MTA，主线程 OLE 窗口消失；变化发生在切换布局之前，主 Qt 窗口句柄及拖放属性仍保留。
- 经用户授权的本地硬件断点捕获到 libmpv 在 GUI 线程调用 `CoUninitialize`。静态函数边界、相邻 WASAPI 日志字符串与实际版本源码相互对应；最近导出的函数名不冒充精确内部符号。
- 临时本地 WAV 回归在旧实现第 0 轮终止后得到 `CO_E_NOTINITIALIZED`。没有其他 MTA 持有者时，表现为未初始化而非隐式 MTA；两者均不是正常 Qt STA 状态。

**根因与最小修复**：默认 gapless audio 会保留音频输出至最终销毁；GUI 线程调用终止 API 时，遗留的 WASAPI 输出在该线程清理并调用 `CoUninitialize`，破坏 Qt 依赖的 COM 生命周期。嵌入播放器设置 `gapless_audio=False`，使音频输出在 mpv core thread 结束播放时释放。没有替换 OLE 拖放、重置系统 COM、无限补初始化引用或更换系统 DLL。

**排除与纠正**：

- Windhawk 排除后、进程无其模块时仍复现，不能把注入当作必要原因。
- Del 不是唯一可触发播放器释放的入口；布局切换只是曾经观察到的邻近操作。
- PR28 的回调引用和占位恢复是独立加固，不能把它当作本例根因修复。
- mpv 原生窗口确有独立 OLE 注册，但源码有 RevokeDragDrop；没有证据证明遗漏撤销。禁用内置窗口拖动也不等于禁用文件拖放注册。
- 部分异常是进程仍存活时的 first-chance COM 异常；不把每条异常日志都称为一次崩溃。

**回归与验收**：

- `selfcheck_player_lifetime` 覆盖普通/预览构造参数、重绑和重复释放，先红后绿。
- `selfcheck_mpv_com_lifetime` 使用临时静音 WAV，直接终止、正常 release、预览绑定清理各 30 轮通过；不读取账号、不联网、不模拟真实 OLE 拖放。
- 当前本地组合的 offline 33/33、smoke 8/8、repository 8/8 通过；用户随后完成真实拖动及重启验收。
- 独立开发基线的既有 composer 测试曾有后台请求越过 stub 生命周期的审计失败；这不是播放器回归通过的证据，另见 BUG-060。

遇到相似症状时先比对 COM apartment、清理调用线程和实际错误签名；不要仅凭“禁止指针”直接套用本根因。原始诊断仅本机保留，不上传账号、完整内存或个人路径。

## 新案例记录规则

1. 沿用 `BUG-xxx` 唯一编号，记录首次反馈日期、版本/提交、现象及最短复现步骤；未知字段明确写未知。
2. 分开记录现象、证据、推测、已排除条件、修复及验证结果。相同表现不等于相同根因。
3. 自动测试标明 mock、离屏、原生或真实网络；阶段性未复现不写作已验收，失败项不计通过。
4. 验收注明用户操作及重启结果；PR 合并、develop 集成和版本发布分别记录。
5. 不保存 Cookie 值、账号配置、签名流地址、完整内存或个人绝对路径；原始诊断另行本机留存。
6. 复发时更新原案例状态并补新证据，保留旧修复结论的时间范围，不删除历史或覆盖成一个笼统的“已修复”。
