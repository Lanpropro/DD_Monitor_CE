# 插件商店与本体更新

设置 → 插件提供「已安装」「插件商店」两个页签。首次打开商店时读取官方仓库目录；选择安装或更新后后台下载并校验 SHA-256，保存并重启后生效。本体更新位于设置 → 软件更新，与插件版本独立。

插件商店目录保存在 `cache/plugin-catalog.json`，重新打开设置时立即使用缓存，十五分钟内不重复查询。停留在商店时每十五分钟检测一次；有 ETag 的仓库目录或 Release API 使用条件请求，内容未变化时保留原列表，有变化才自动更新。网络失败时保留已有目录。手动刷新按钮位于圆角页签右侧，仅在选中插件商店时显示，可立即检查。

## 发布插件

下载来源固定为 `Lanpropro/DD_Monitor_Plugins` 的 Release。插件商店优先读取最新正式 Release 的 `plugin-catalog.json`，没有目录时兼容现有 Release 安装包列表；公开 API 限流或离线时优先保留本地缓存，无缓存则显示内置的已发布 1.0 插件目录，并明确提示目录可能不是最新。比赛二路尚未在该仓库发布时显示暂不可安装，不下载本地开发文件。

每个插件 `plugin.json` 建议声明 `min_app_version`，例如 `"0.3"`。生成目录时提供本次仍受支持的所有插件安装包，目录是完整列表，不仅包含本次改动的插件。

```powershell
python dev/build_plugin_catalog.py --tag v1.1 --output plugin-catalog.json domestic_live-1.1.zip global_live-1.1.zip
```

将生成的目录和对应 ZIP 一起上传到同一正式 Release。工具只读取已有 ZIP，不执行插件代码或生成新 ZIP。每次升级使用新版本和新的附件 URL，不覆盖旧版本附件。

安装在下载后验证包 ID、版本及最低本体版本。新插件按现有安装器装载，不执行代码；已有插件暂存到 `plugins_user/.updates/<id>`，重启时在插件加载之前合并新文件并替换目录。保留原设置及包中未覆盖的数据文件，升级前在 `.updates/<id>.backup` 保留上一版本目录，替换失败恢复原目录。运行期间新增的数据在下一次启动时复制，避免下载后退出前的写入丢失。插件开发者应将运行数据与包内代码/资源分开，不在升级包中放入个人配置。

## 发布本体

0.3 开始包含更新助手。EXE 构建中生成 `ddm-build.json`，记录版本、Windows x64 平台和更新协议；生成 ZIP 时另在输出目录生成 `app-update.json`，包含版本、下载地址、大小、SHA-256 及更新说明。它们由正常发布脚本生成，不需要用户配置 GitHub Token。

正式发布时上传 **EXE ZIP 和 app-update.json**，并使用与本体版本一致的新 tag，例如 `v0.3`、`v0.3.1`。将该 Release 标记为最新正式版本。程序优先从最新 Release 的固定附件 URL 获取更新清单，兼容 GitHub Release API；草稿和预发布版本不会通过 API 推送。

软件更新先后台下载、验证版本及协议、检查路径和空间，再解压至系统临时目录。用户点击「重启并更新」才保存设置并正常收尾录制、播放器和插件。旧进程退出后，暂存的新程序以 `--apply-update` 启动助手，不初始化 Qt/VLC，等待旧 PID 退出、备份并替换程序文件，然后启动新版。助手启动失败时保留原程序；替换失败时恢复已替换的文件，并在更新页显示结果。

「自动更新」是保存到设置的开关，默认关闭。开启后启动软件时在后台检查本体新版；有新版才显示上方居中的悬浮提示，不抢焦点、不使用模态弹窗，十秒未点击自动消失。点击「查看更新」跳转到软件更新页，显示检测到的新版说明，由用户选择下载及重启安装；提醒本身不会下载或安装。

启动时也会检查已安装插件的可用新版，复用商店缓存和十五分钟检查间隔，不受本体自动更新开关影响。仅有插件更新时，提示按钮进入插件商店；本体和插件都有更新时合并提示，优先进入软件更新页。检测到更新后，主界面设置入口和设置中对应的导航右侧显示红点，插件商店页签及可更新插件按钮的右侧也显示红点。确认没有新版、删除对应插件或插件更新已下载等待重启后，清除对应标记。

点击设置入口后清除入口的红点，尚未查看的更新页仍保留标记。用户查看对应更新页面后，即使暂不安装，也会清除该版本的红点并保存已查看记录；同一版本不再重复提示，更高版本仍会重新提醒。关闭悬浮提示本身不算查看，更新按钮保持可用。提示栏使用软件主题的浮层背景色。

「更新说明」区域按 Markdown 展示更新清单中的 `notes`，或 GitHub Release 正文；发布脚本会将本次 `RELEASE-v*.md` 内容写入清单。未检查、没有新版或网络失败时显示随程序附带的当前版本 `RELEASE-v*.md`，缺少文件时提示前往发布页查看。

`utils`（含关注配置、账号凭据）、`cache`、`logs`、`plugins_user` 和录制目录不会被更新包覆盖。程序文件清单用于后续更新清理过期运行库，未记录的用户文件保留。临时程序和备份在更新完成后的正常启动中清理，文件仍占用时留待后续启动。

源码版可以检查新版和打开发布页，自动替换仅用于 EXE 版。旧 v0.2 EXE 没有更新入口，第一次需手动升级至包含该功能的版本；之后才能在线更新。

开发验证：`selfcheck_online.py`、`selfcheck_online_ui.py` 和 `selfcheck_update_install.py` 覆盖校验失败、取消、兼容性、插件暂存及回滚、用户数据保留、Windows 父进程等待和录制退出接入。正式发版还需用真实冻结 EXE 在隔离目录中完成一次跨版本升级验收。

0.3.1 作为固定程序名的过渡版本，额外提供 `DD监控室CE-v0.3.1.exe`，供旧 0.3 更新器识别；该入口启动后转交给 `DD监控室CE.exe`。之后的发布包只提供固定名称主程序，版本信息仍在更新清单和 Windows 文件属性中保留。

EXE 包内程序目录及日常启动文件固定为 `DD监控室CE/DD监控室CE.exe`，在线更新保留原安装目录，避免按路径设置的白名单因版本号变化而失效。手动更新请解压覆盖原目录。
