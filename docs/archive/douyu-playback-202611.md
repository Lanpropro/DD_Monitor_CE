## 斗鱼输入中断与解码恢复的区分

2026-11-15 19:08:02 的真实直接模式记录依次出现 curl 接收失败、FLV 包损坏/长度不匹配、H.264 NAL 数据不足；旧恢复逻辑随后重开同一地址并切到CPU。这只能确认当前传输中断与截断后的解码报错相伴，不能据此认定硬解故障或确定网络/CDN根因。

同一次斗鱼播放已收到 error/fatal 级别的 curl `transfer failed` 后，停止该会话的解码回退，让原EOF/故障重连处理来源；下一次播放清除标记。未出现传输错误的解码回退、其他平台、画质、CDN和重试间隔不变。此修正避免错误切CPU，不代表缓存耗尽或线路中断已经解决。

2026-11-15深度样本还确认：华为线路加入时先给出非IDR视频帧，独立FLV检查的完整tag/NAL长度正常，却发生缺参考帧的mmco报错；旧逻辑会立即切CPU并重开原地址。斗鱼的明确损坏包/缺参考帧消息不再直接置位硬解故障；后续独立硬解错误仍可触发原回退。边缘线路在独立HTTP读取中也出现8秒读超时和未完成尾tag，不能归因于mpv直接接收方式。

## 深度模式 TLS 对照

斗鱼深度转发对实际边缘源域名的精确 HTTPS origin 增加 `AES256-GCM-SHA384` 套件，
保留 Python 默认套件、最低 TLS 版本、安全等级及证书/主机名校验；官方 API、华为源及其他域名不应用此适配。
此兼容基于两个返回节点的真实握手对照：Python 默认配置收到握手失败 alert，兼容套件可协商 TLS1.2，
证书校验通过。未签名根路径 HEAD 被节点直接关闭，不作为媒体实播成功证据。
`network.tls-policy` 记录本次连接采用的配置，代理连接使用相同源 TLS 上下文。
已有进程不会加载此代码修正；先完整退出，随后再设置线路控制并启动深度入口，避免旧实例用旧 TLS 配置重试。
