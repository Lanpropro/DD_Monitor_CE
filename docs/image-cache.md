# 头像与封面缓存管理

入口：设置 → 软件更新 → 数据与存储 → 图片缓存。

饼图展示头像与直播间封面两类图片的占用比例，中心为合计大小。点击扇区可以选择或取消该类图片，下方复选框提供相同操作；分类同时显示大小、文件数与占比。这里的占比仅包含这两类图片，不代表整个软件或磁盘的使用率。

- **清理所选**：删除已选类别的图片缓存。
- **全部清理**：删除头像与封面两类图片缓存。
- **刷新统计**：重新统计当前数据目录中的占用。

统计与清理在后台完成；完成后显示实际释放大小、清理文件数和跳过的占用文件数。没有缓存时显示空状态；仍在内存中的图片可以继续显示，后续需要时再加载或下载，不会因为清理而立刻批量重新下载全部图片。

头像与封面采用“新图成功保存后清旧图”：按平台房间 ID 分别跟踪最近头像、封面及实际 URL 缓存文件。获取失败、图片无法解码、保存失败或接口没有新图片时保留旧图；头像变化不影响封面。多个房间共享的文件等最后一个引用更新后再清理，后到的旧请求不能覆盖新图片。

按房间保存的最近图片继续供启动时和未开播时使用，不设置图片天数有效期或容量淘汰。旧版本遗留且无法确认归属的 URL 文件不推测其主人，可通过手动清理删除。图片归属、请求顺序及清理标记保存在数据目录 `cache/images.sqlite`；头像/封面清理会重置对应归属并保留协调标记，防止此前的下载任务重新写回缓存。

清理范围仅限当前数据目录的 `cache/avatars/`、`cache/covers/` 内的图片文件。横幅、表情、账号、关注、布局预设、皮肤、插件、日志、录制及待恢复录制分段不在此范围；不跟随缓存目录中的链接或 Windows junction。原生文件占用导致不能删除时跳过，保留给后续清理。

## 验证

```powershell
run.cmd --check-image-cache
python dev/run_checks.py --script selfcheck_image_cache
```

专项使用临时数据目录、合成图片、离屏 Qt 和请求替身，覆盖新图替换、失败保留、共享引用、CDN 回退、晚到请求、跨进程清理标记、实际释放大小、数据保留、饼图选择、空状态和主题切换。不读取真实账号、不访问外网、不清理用户缓存。

人工从根 `run.cmd` 启动，进入上述设置页，点击饼图选择一类并清理，预期另一类占用保留且统计更新；随后可清理全部图片。确认关注、登录、预设和录制仍在，刷新图片后能正常加载；真实主播换图、直播/录制同时清理及高 DPI/跨屏仍需人工验收，自动回归不代表这些场景已验收。
