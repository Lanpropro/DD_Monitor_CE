# 卡顿与错位：采集指南

> 类型：指南 ｜ 状态：维护中 ｜ 适用版本：0.7.x ｜ 更新：2026-11-15 ｜ 读者：维护者、贡献者

本页记录当前采集方法。长时间使用后卡顿仍见 [BUG-070](../bug-cases.md)；文件夹错位、拖动停顿和播放转圈按各自发生时段取证。采集器检查只证明数据采集功能可用，性能结论需要真实软件中的问题时段。

## 用户反馈与独立诊断工具

用户正常使用软件。发生问题时记下时间、启动后大致时长、正在播放的路数、当时操作、声音是否连续，以及问题是否仍留在画面上。

当前**开发候选版**的[独立诊断工具](../../tools/diagnostics/README.md)可在软件运行中收集现场和已有日志；公开附件尚未更新到该工具版本。文件夹仍错位或重叠时保持界面，选择“抓取文件夹现场”后生成诊断包；拖动时出现禁止指针，可选择“记录一次拖放”，随后在软件中尝试一次。问题已消失或软件已退出时，直接生成诊断包收集已有日志。旧版缺少内部现场接口时，工具会说明只能取得外部窗口状态。

诊断包保存在本机，由用户检查后手动提供。独立工具不要求预先启动专项、重启软件或再次复现；事后数据无法还原未记录的操作和已消失的画面状态。

## 普通运行时的轻量记录

根目录 `run.cmd` 直接启动本体。实时排查时，对正在运行的进程调用[本体 MCP](../../tools/host_mcp/README.md)。文件夹错位仍在时使用 `capture_diagnostics` 的 `folders`，要观察拖放和滚动时使用 `measure_sidebar_interactions`。

发生卡顿后，维护者先按时间对照已有日志和用户描述。若没有覆盖问题阶段的证据，再选择下表中的专项采集；不凭一次正常采样认定历史问题已解决。

## 维护者按需采集

| 方法 | 适用场景与入口 | 边界 |
| --- | --- | --- |
| 本体 MCP | 指定软件 PID，从 `capture_diagnostics` 选择专项，或用 `measure_sidebar_interactions` 观察关注栏操作 | 运行中按需采集。按结果中的会话标识对照本地日志。 |
| 现有客户端的播放采样 | 按 PID 调用 `capture_diagnostics(mode="playback")` | 默认采集约 60 秒，结果随 MCP 返回，同时写入 `logs/on-demand.jsonl`。 |
| 完整响应性诊断 | 用 `prepare_startup_diagnostics` 登记 `responsiveness` 或 `responsiveness-profile`，再重启 | 专项采样和函数分析会引入额外开销，结合真实操作时段判读。 |
| 拖动专项 | 使用 `capture_diagnostics(mode="drag")`。需要首次拖动函数归因时，登记启动模式 `drag` 并重启 | 运行中采集观察一次拖放，启动采集提供额外的函数归因。 |

播放采样可对照同一格的缓存暂停、缓存时长、下载或中继计数、丢帧、进度和源状态。缺失属性保持缺失，不能当作零；所选 URL 的主机不等于已确认的最终出站。UI 心跳、Qt 几何和 mpv 进度都不等同于桌面实际呈现帧率。采样与真实故障时段不一致时，只能说明所采窗口的状态。

具体字段、隐私边界和历史执行细节见[2026 年 11 月调查记录](../archive/responsiveness-capture-202611.md)。专项功能检查入口见[验证指南](testing.md)；功能回归不能替代用户的真实复现与验收。
