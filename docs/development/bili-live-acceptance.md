# bili_live 本地验收（2026-10-23）

原目录 `run.cmd` 使用本地验收分支。宿主基于 develop 9d6e39e 适配 PR33 的公开控件及登录快照接口，插件基于 PR2 83ef743；两项 PR 均未因此合并或发布。直播弹幕接收、侧栏和画面绘制保留；本体内置发送器与表情编辑器移除，由插件提供输入区。

## 功能与待选择差异

| 项目 | 原本体 | 当前插件验收版 |
| --- | --- | --- |
| 文本与草稿 | 按房间保留本次运行草稿 | 按房间保留本次运行草稿；成功清空对应草稿，失败保留 |
| Enter | develop PR44 支持悬停格子聚焦、全屏两步唤出 | 通过通用控件接口保留；中文选词、自动重复按键不发送 |
| 小表情 / 大表情 | 小表情插入，大表情点击直接发送 | 同样区分；大表情点击会真实发送 |
| 分类及表情排序 | 拖动排序，保存在本体配置 | 无此拖动排序功能；旧排序数据保留，不迁入插件，等待用户选择 |
| 表情目录缓存 | 按房间和账号持久缓存，重新打开可先展示 | 内存缓存当前上下文；重启后重新请求；图片有磁盘缓存 |
| 分类外观 | 分类封面与普通表情专用图标 | 房间分类封面；普通表情分类显示文字；新浮窗样式 |
| 错误和登录提示 | 顶部带房间头像提示，可点击重新登录 | 输入框附近浮动提示及工具提示；需手动从本体进入登录 |
| 发送按钮和窄格子 | 原有三控件输入区 | 新增礼物入口；输入区小于176px隐藏发送按钮，仍可 Enter 发送；空间不足整组隐藏 |
| 礼物 | 无集成礼物面板 | 礼物分类、电池余额、背包、数量、子礼物、大航海协议确认 |
| 登录与卸载 | 输入器内置 | 使用本体登录快照；插件不独立保存账号，禁用/移除按本体保存并重启流程 |

排序、目录缓存、分类外观及错误提示保留插件原行为，待用户判断保留哪一方；未擅自迁移。

## 逐步人工验收

1. 用户自行退出旧进程，再从原目录 run.cmd 启动。设置 → 插件确认 B站直播互动已装载，格子底部只有一套输入区。
2. 先不发送：输入草稿、换房间、切回，验证隔离；检查窄格子、放大、主题切换。
3. 检查 Enter：鼠标悬停目标格子，普通模式聚焦；全屏栏隐藏时第一次唤出、第二次聚焦。输入中移开鼠标，输入框不隐藏；Esc 退出编辑。
4. 打开表情：观察分类、刷新、定位和关闭。小表情只插入；大表情点击即发送，按用户意愿再测。
5. 用户自行选择是否发送一条真实文本，检查成功清空和失败保留。自动测试不真实发送。
6. 礼物先只打开面板、查看余额/背包与禁用原因，不随意点击图标。单次数量且无子礼物的普通礼物可能点击即赠送并扣电池；部分组合礼物再次点击原图标也可能直接送1个。需要数量/变体时先显示小窗；大航海开通类另有金额与协议确认。没有充值、SC 或自动购买。
7. 用户自行判断是否进行真实赠送；不要求付费来完成软件验收。最后检查登录切换及保存重启后的插件状态。

## 自动验证及限制

测试均为 offscreen，使用替身账号、请求或本机临时目录。宿主测试覆盖仓库、smoke、offline、插件控件/凭据/契约、快捷键；插件覆盖 composer、表情、礼物接口/控制/媒体/面板、安装集成、生命周期、发送和交互。

composer 曾在 Qt 样式更新时出现原生 access violation；诊断日志位于主仓 work/bili-live-compat-followup。测试 teardown 原先只 close 未销毁窗口，现 shutdown 并 deleteLater，断言已销毁后再恢复替身账号；修正后完整序列连续三轮通过。原生 Windows 运行是否存在同源问题仍待人工验收，不把重跑成功作为绝对根因证明。后台不会运行会抢焦点的 native/native_follow 套件。

详细证据在主仓 work/bili-live-compat-checks、work/bili-live-compat-followup、work/bili-composer-diagnosis、work/bili-composer-cleanup-checks、work/bili-live-runtime-checks。初次失败日志保留。
