# Windows 安装包与卸载范围

新用户使用 `DDMonitorSetup.exe`；已有用户继续使用软件内更新或 EXE 便携包。安装器提供两种模式，默认“仅为我安装”，位于 `%LOCALAPPDATA%\Programs\DDMonitorCE`，无需管理员权限；选择“为所有用户安装”时通过 Windows UAC 请求授权，默认使用 64 位程序目录 `C:\Program Files\DDMonitorCE`。两种模式均支持选择目录和创建快捷方式，修复安装按所选模式查询 HKCU／HKLM 的已有登记。

安装版的程序文件和用户数据分开保存。每个 Windows 用户的数据默认位于 `%LOCALAPPDATA%\DDMonitorCE\data\<安装路径标识>`；`utils`（配置、加密账号、皮肤、文件夹图标）、`plugins_user`、`cache` 和 `logs` 均使用此位置。程序资源、FFmpeg、播放器运行库和更新清单仍从安装目录读取。不同安装路径分别保存数据，其他 Windows 用户不会共用登录状态。安装标识 `.ddm-install.json` 由 Setup 创建并负责卸载，在线更新包不能覆盖或移除它；旧安装通过 `.ddm-uninstall\unins000.dat` 识别。便携版和源码版默认继续在程序旁保存数据。

旧安装首次启动会将上述四类数据复制到用户目录，完成后再切换；原文件保留。设置→软件更新→数据与存储提供当前目录、打开目录和“迁移数据目录”入口。选择独立、可写的空文件夹后，点击“保存并重启”：正常保存设置、收尾录制并退出，下一进程等待原进程退出后复制数据，再原子切换目录登记。失败保留原位置和原文件，并明确提示；目标已经有内容时停止，避免覆盖。录制文件保存在录制设置指定的位置，不随迁移移动。账号凭据仍受原 Windows 用户 DPAPI 保护，迁移文件夹不意味着可以跨用户解密。自定义位置由当前用户的 `%LOCALAPPDATA%\DDMonitorCE\locations\<安装路径标识>.json` 登记；位置丢失时提示恢复，不静默创建空配置。

软件平时使用普通权限运行。在线更新先下载、校验并暂存；目标程序目录不可写时，更新页说明将请求管理员权限。退出后由普通权限助手通过 UAC 启动替换程序文件的助手，随后仍由普通权限助手重新启动软件。取消授权保留原版本；更新结果写到当前数据目录。独立诊断工具也按目录登记读取脱敏配置、插件版本和日志，不读取账号文件。

安装向导使用深色背景、软件标志和蓝色品牌图。安装版保留 `RELEASE-v0.5.md`，供软件更新页离线显示当前版本说明；仅省略便携版的 `运行说明.txt`。许可证、`ddm-build.json`（版本和更新识别）及 `.ddm-program-files.json`（更新时清理已登记的过期程序文件）继续保留，这些 JSON 是程序元数据。

目录选择使用 Windows 原生 IFileOpenDialog 文件夹模式，支持地址栏、侧边栏和搜索；选择父目录后自动追加 `DDMonitorCE`，已经选择同名目录时不重复追加。取消保留原路径。系统对话框遵循 Windows 自己的主题。

正常交互启动时始终询问当前用户／所有用户安装模式，不沿用旧安装的权限而隐藏模式选择；显式使用 `/CURRENTUSER`、`/ALLUSERS` 或静默安装时遵循对应命令行选项。目录选择页始终显示，包括已有安装时的重复安装；识别到旧安装目录时仅作为可编辑的默认路径，不跳过路径确认。

浏览启动工具时按 Windows 命令行规则转义路径末尾的反斜杠，确保从 `C:\`、`E:\` 等根目录浏览不会合并后续参数。工具收到不完整的 `--pick-folder` 参数时只返回错误，不进入卸载入口。

选择目录后和正式安装前，安装器会在目标目录（尚不存在时使用最近的现有父目录）创建临时目录和文件测试写入权限，并清理测试内容。无权限时停留在向导并说明原因，建议使用默认目录或其他可写位置，如 `E:\DDMonitorCE`；需要受保护目录时提示重新选择“为所有用户安装”并授权，避免进入解压阶段才报“错误 5：拒绝访问”。不修改原目录 ACL，也不根据 Program Files 的名称直接拒绝。

浏览工具位于压缩包头部并与主程序数据分块，在向导初始化时提取；点击浏览不会再先解压整个程序包。卸载入口同样在主程序数据之前安装，避免解压流回退。安装采用 `lzma2/fast`，日常安装不强制写逐文件诊断日志；诊断时显式传入 `/LOG`。原生入口通过 RC 资源嵌入软件图标。卸载选择窗口使用一次字体/DPI缩放及固定紧凑布局，避免高缩放下重复放大。

可在 Windows“已安装的应用”、开始菜单，或安装目录的 `DDMonitorUninstall.exe` 启动卸载。后者是约 128KB 的本机入口，只定位并启动 `.ddm-uninstall` 内唯一的卸载 EXE，随后退出；真正卸载仍由 Inno 的逐文件记录管理，不重命名或移动原记录。目录内卸载 EXE 缺失或不唯一时提示使用 Windows 设置，避免猜测。开始菜单快捷方式仍遵循已有同名文件不接管的规则。修复安装不主动删除旧版已安装的说明文件，它们仍由原卸载记录管理。

交互卸载提供默认不勾选的“同时清除个人信息（账号、设置及插件）”，并显示实际数据目录。不区分新版与旧版：存在当前用户的数据位置登记时，读取其当前生效的 `root`（含 AppData 或自定义迁移位置）；没有登记时使用软件安装目录。无法确认登记位置或包含链接时保留数据，不猜测其他目录。清理所选实际数据目录中的 `utils/config.json`、其 `.bak` 备份，以及内置平台 AccountStore 的明确账号文件（`.bin` / `.tmp`）：bilibili、douyin、douyu、huya、youtube、twitch、douyin_follows、youtube_oauth_client、twitch_oauth_client。勾选后也清理下述已登记插件文件。其他 Windows 用户的数据、录制和未登记来源的文件保留；独立数据目录生效后，安装目录内遗留的旧副本也不会被当作当前数据删除。静默卸载始终保留个人信息。

插件安装时根据 ZIP 实际文件写入 `.ddm-plugin-files.txt`，更新合并新旧清单，供卸载逐文件清理当前插件、待应用更新和更新备份。记录之外的用户文件和录制保留，只删除空目录。旧插件没有逐文件登记时，仅删除可确认的 `plugin.py` 和 `plugin.json` 入口；其余内容保留，避免猜测来源。插件清单包含越界路径或链接时保留该插件并提示部分清理未完成。

登录浏览器的磁盘缓存使用当前数据目录的 `cache/web-login`，避免应用名称变更后在 AppData Local 留下多套同名缓存目录。

用户自行放入的文件可能位于任何目录；无法确认归属的文件一律保留。皮肤、日志和缓存没有逐文件来源记录，因此即使名称看起来像软件生成的文件，也不自动删除。录制始终保留；不递归清空 `utils`、账号、插件或其他数据目录，卸载后目录可能仍有内容。静默卸载始终保留个人信息。已知清理路径包含链接时跳过相应清理并提示，删除失败也提示保留。清理前需退出应用，避免在退出时重新保存配置。

## 安装与卸载的边界

- 安装输入只能是经过验证的 Windows EXE 便携目录，拒绝账号、配置、插件、录制、未知文件和目录链接。
- 首次安装拒绝接管非空目录，避免覆盖其他软件或个人文件；已经由同一安装器登记的目录可以修复安装。
- 每个程序文件单独登记到 Inno Setup 的卸载日志，不使用通配符删除、整目录递归删除或自定义清盘逻辑。
- 卸载删除登记的程序文件、安装器元数据、它创建的快捷方式及卸载登记。默认保留个人数据；用户主动勾选时清理已知账号、配置和登记的插件文件。录制及未登记文件保留，非空目录不会被整目录删除。
- 已有的同名快捷方式不会被安装器接管。程序目录或已登记的程序子目录被改成链接时，安装和卸载都会停止，避免影响其他位置。
- 安装器提供初始 `.ddm-program-files.json`，供软件内更新清理已登记的过期程序文件；更新仍保留个人数据和未登记文件。该清单不打进在线更新 ZIP，避免覆盖旧版本的清理依据。
- 新构建的 `ddm-program-inventory.json` 随 Setup 和更新 ZIP 安装，描述当前版本路径；用于[历史版本兼容清理](../online-updates.md#无旧清单的历史版本清理)，与安装器初始清单分开保存。
- 卸载使用安装器自身的文件记录。将来仅通过在线更新新增、尚未由安装器登记的文件可能保留；不会为追求清空目录而删除未知文件。需要时可使用新版安装器更新其登记记录。

## 构建与验证

先执行正常便携包构建及检查，再在 Visual Studio 的 x64 Native Tools 环境使用 MSVC 和 Inno Setup 6.7.3 编译安装器。原生入口使用静态 CRT，不要求用户安装 .NET 或额外运行库；同一入口在安装临时目录提供文件夹选择功能：

```powershell
python dev/build_setup.py --payload "<已验证的便携目录>" --out-dir "<产物目录>" --iscc "<Inno Setup 的 ISCC.exe>"
python dev/selfcheck_setup.py
python dev/run_checks.py --script selfcheck_data_paths
python dev/check_setup_permissions.py --iscc "<Inno Setup 的 ISCC.exe>"
python dev/check_setup_data_cleanup.py --iscc "<Inno Setup 的 ISCC.exe>"
python dev/check_setup_install.py --setup "<产物目录>\DDMonitorSetup.exe" --payload "<已验证的便携目录>" --update-zip "<同版本 EXE ZIP>"
```

`check_setup_permissions.py` 使用独立 AppId、合成安装文件及临时目录 ACL，验证已有目录和尚不存在的子目录无写入权限时均能拦截、跳过目录页时仍会检查，以及可写的中文多层自定义路径可安装和卸载。仅修改测试临时目录的 ACL，并在结束时恢复；不操作用户的真实安装或系统目录。

该检查还将合成安装目录设置为不可创建文件／目录，验证配置仍可在独立用户目录保存并重新读取。`selfcheck_data_paths` 覆盖迁移、失败回退、取消设置、账号与皮肤路径及更新授权成功／取消分支；授权分支使用替身，不代替真实 UAC 和完整 EXE 验收。

`check_setup_data_cleanup.py` 在原生入口构建完成后单项执行，不加入通用批量套件。它使用独立 AppId 和微型合成安装，不接管真实安装；测试脚本仅在生成的临时脚本内注入“已勾选”状态，以覆盖实际删除分支，并将数据位置登记改到测试沙箱。覆盖软件目录和独立数据目录各三种场景（默认保留、主动清理、路径链接保护），以及损坏登记保留数据的第七种场景；使用含中文和空格的目录，验证 14 项额外文件保留。独立目录清理时还检查旧安装目录副本不受影响。即使额外文件的名称看起来像日志或缓存也必须保留。

最后一项仅限 Windows，使用项目 `work/` 下的临时目录、合成配置及临时插件。它真实运行安装器和卸载器；若当前账号已有该安装器的卸载登记会直接拒绝，避免接管已有安装。检查包括非空目录拒绝、修复安装、冻结程序启动与分享链接代码、更新清理范围、目录链接保护，以及卸载后的个人文件和相邻目录保留。不读取真实账号、不启动真实直播、不关闭用户的软件。
