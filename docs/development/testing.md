## 设置首次打开与切页耗时采集

从根目录执行 `run.cmd --diagnose-settings-performance`，在实际软件中首次打开设置，依次进入感到卡顿的页面，再按相同顺序切换一次；关闭设置后重新打开作为对照。记录最明显的页面及操作时间。采集主进程和设置子进程的 `logs/settings-performance-<PID>.jsonl`；诊断会话已指定日志目录时沿用该目录，不写入设置子进程的临时配置目录。

`ddm/settings_performance.py` 复用响应采样器，记录设置构建、页面创建和切换、宿主页同步和嵌入、自动保存与显示到首次 Paint 事件的耗时，以及超过250ms的 GUI 心跳间隔调用栈。每进程最多1200条，默认不启用函数剖析，日志经队列在后台写盘，停止时排空队列并关闭文件。确需详细剖析时设置 `DDM_SETTINGS_PERFORMANCE_PROFILE=1`，每种函数仅前20次外层调用启用 cProfile；嵌套调用不替换外层 profiler。不记录设置值、搜索文本或协议内容。首次 Paint 表示 Qt 收到绘制事件，不等同于屏幕实际呈现完成；剖析器自身有开销，耗时用于定位，不能直接视作普通启动的延迟。

普通启动不启用；退出本次软件结束采集。根 `run.cmd --check-settings-performance` 检查开关、嵌套调用及异常语义、输入隐私、记录上限，以及真实设置控件在采集前后的切页与设置值一致性；离屏功能回归不能代替用户现场的性能复现。

## 从哪里开始

设置滚轮失效取证：从根目录执行 `run.cmd --diagnose-settings-scroll`，在外观页或软件更新页滚动到失效，点击设置外部再移回并重复；最后在普通页面滚动作为对照。`ddm/settings_scroll_diagnostics.py` 按进程写入 `logs/settings-scroll-<PID>.jsonl`，每进程最多1200条，记录 Windows 滚轮投递、Qt 接收控件类型、焦点类型和滚动条数值；不记录输入文本、不消费或转发事件。主进程与设置子进程均启用，以区分跨进程嵌入后的投递与页面处理。普通启动不开启；关闭该次程序即结束，无法补录之前的事件。此入口仅采证，不代表滚动故障已修复。

2026-11-16 真实复现采集显示：宿主收到原生滚轮，设置子进程的 Qt 接收者是窗口／容器，祖先中没有页面滚动区。外观与更新页是跨进程嵌入的宿主页，普通页在子进程本地。现由 `settings_wheel.py` 在两个嵌入端点接收原生纵向滚轮，转交真实子控件并沿用既有滚轮规则；子进程日志优先写入诊断目录，否则写入宿主根目录的 `logs/`，避免临时目录退出后丢失。

根入口 `run.cmd --check-settings-scroll` 使用隔离数据验证采集上限、无文本记录、不消费事件、滚轮控件规则及两页连续滚动，并用 Windows 屏外原生窗口检查两端投递、切页返回、保存应用和关闭清理。消息只发送到测试 HWND，不移动系统鼠标；不替代真实操作验收。人工复查步骤：重启根 `run.cmd`，缩小设置窗口使页面出现滚动条，在两页分别连续上下滚动、切到普通页再返回；预期无需点击窗口外部即可继续滚动。2026-11-16 维护者确认滚动修复验收通过，修复提交 `3fd70173`；内存异常仍单独记录。

## 执行分类

| 套件 | 依赖与行为 | 命令 |
| --- | --- | --- |
| `repository` | Python 标准库和 Git；不导入 Qt，不读取账号，不联网 | `python dev/run_checks.py` |
| `smoke` | 开发依赖和 libmpv；离屏核心功能检查，使用合成数据与本机服务 | `python dev/run_checks.py --suite smoke --timeout 180` |
| `offline` | 开发依赖；离屏 Qt、替身接口或本机 HTTP/WebSocket 服务，不访问真实直播 | `python dev/run_checks.py --suite offline` |
| `native` | Windows、开发依赖、libmpv；部分项目需 FFmpeg，会创建原生窗口 | `python dev/run_checks.py --suite native` |
| `live` | Windows、运行库和网络；显式指定公开开播房间，只读接收 | 使用下方单项命令 |

`offline` 是已核对隔离条件的回归子集，`native` 也是明确列出的原生检查子集；均不表示仓库全部相关测试。其余历史脚本按功能列入[完整索引](../../dev/checks/README.md)，需要先检查脚本依赖、测试数据和隔离条件，再单独运行或加入套件。不能根据文件名中的 `live` 判断它是否使用真实网络。

离屏进程会阻止 Python 层的外部 DNS 查询和 socket 连接，只允许回环地址；即使脚本捕获该异常，最终结果仍失败。Qt WebEngine、原生库和子进程仍需逐项审查。套件脚本不能使用 `os._exit` 绕过清理；具体纳入标准与本机归档见[工作区维护](workspace-maintenance.md)。

## 本地视频专项

下列工具保留独有操作场景，播放接口已迁移到 libmpv；仍为单项，不自动加入批量套件。先准备不含个人信息、颜色丰富且时长不少于一分钟的测试视频，画质工具另需低分辨率版本；示例文件路径需替换。

## 结果与新增检查

- 日志与 `summary.json` 写入忽略目录 `work/checks/<时间>/`。
- 所有选中项目完成后，任一失败或超时均返回退出码 `1`；参数错误返回 `2`，全部通过返回 `0`。
- 单项默认超时 300 秒，可用 `--timeout` 调整。遇到失败先查看对应日志，不以“执行结束”判断通过。
- 新增脚本先更新完整索引；核对真实配置、网络、窗口和依赖后，才将其加入 `dev/checks/suites.json`。
- 涉及发弹幕的自动回归使用替身或本机服务。真实账号、跨屏操作、声音听感等需要独立人工验收。
- CI 分别运行 `repository` 和 `smoke`，并编译应用源码。smoke 覆盖设置、通知、布局、关注排序、弹幕发送和插件接口；它不代表原生播放、视觉帧率和真实直播验收全部通过。
- smoke 与 offline 可共享脚本，但必须保持相同隔离模式；同一套件不允许重复脚本。新增 smoke 项目应先核对隔离条件、耗时和依赖，不把所有历史脚本直接纳入 CI。

## 常用功能专项

关注栏卡片原生预览滚动回归可从根目录运行 `run.cmd --check-preview-scroll`，依次执行离屏回归与本地 MP4 原生检查（需要 ffmpeg，不联网）。原生项核对连续24次滚动后的 Qt 与 HWND 坐标、播放器核心不变和播放进度继续；可设置 `QT_SCALE_FACTOR=1.5` 复核高 DPI。这是功能回归，真实跳位依据来自专项现场采集，不以本地视频证明用户机器的视觉改善。

直播时长：`run.cmd --check-live-elapsed` 验证先播放后补时间、时间先到但播放器未确认起播、关注栏缓存后入墙、缺失时间及下播重开；确认时间有效后立即计时，继续按悬停规则显示，缺失的补充字段不清空有效时间，确认下播则清除上一场时间。`selfcheck_live_elapsed` 同时进入 smoke／offline 套件。真实客户端已记录到状态回调写入开播时间后计时器仍停止、后续播放回调才启动；隔离回归用于验证这些状态转换，不作为接口或播放性能改善的依据。`run.cmd --diagnose-live-elapsed` 复用现有开发诊断，增加状态／播放回调前后记录及三个布尔值（时间已到、计时器运行、画面已起播），不增加网络请求。人工重启该根入口，打开B站直播并刷新状态，悬停应及时显示时长；移开继续隐藏，下播后清除，再开播使用新时间。已有数据可直接复用，仍需真实用户复验等待是否改善。

自定义弹幕格入墙：`selfcheck_pane_danmaku` 覆盖主画面＋5小环绕中右侧两格切为弹幕后，新增关注与普通入墙连续填入下方可见空视频格，保持弹幕底层格为空，拖入弹幕面板仍只切换弹幕来源。自动入墙按当前 `PaneDanmaku` 的 cell 绑定排除弹幕底层视频格；普通隐藏视频格原有溢出入墙行为保留。实际运行记录已出现隐藏格播放、下方视频格仍空的状态；隔离回归不作为真实播放验收。人工从根 `run.cmd` 重启后配置同样布局，添加两名主播，预期依次进入下方空视频格、侧栏入墙标记对应可见视频，右侧两格继续作为弹幕格。

设置与弹幕覆盖：根 `run.cmd --check-fullscreen-layers` 包含 `selfcheck_settings_occlusion`，使用真实的独立设置进程 HWND 和顶层 Quick 弹幕窗口，检查设置上报句柄前暂缓弹幕显示、原生前后顺序、滞后设置矩形不留空洞、排序失败的原生裁剪回退、表面重建和呈现窗口切换，以及取消／退出／异常结束后的清理。设置进程在显示前上报窗口句柄，`SettingsProcess` 唯一持有该句柄并在结果、退出或停止时清空；Quick 的显示与抬升统一经过设置相对排序。排序成功时由系统同步遮挡，失败时保留矩形裁剪，其他窗口及画面边界的裁剪不变。真实运行只读原生采集已观察到设置隐藏后裁剪空洞仍滞留约137ms；本批针对这一证据移除成功排序路径的异步空洞。屏幕外隔离检查不读取个人配置，不移动光标或激活窗口，也不能代替真实运行的视觉验收。人工从根 `run.cmd` 开启多路弹幕后打开设置，来回拖动、缩放、最小化及重开设置，期间切换全屏；设置内不应出现弹幕，窗口移开的区域应立即跟随露出弹幕，关闭后不再滞留空洞。本批不处理设置白屏本身，观感改善仍待人工复验。

控件职责拆分：根 `run.cmd --check-widget-boundaries` 离屏检查公共控件及 Qt 生命周期，不启动客户端或读取账号。覆盖标签缩放恢复、图标模式/信号/销毁和面板删除后跳过排队滚动恢复。人工从根 `run.cmd` 检查关注卡片标题省略、工具条按钮与深浅主题；弹幕更新后切换布局或关闭窗口，应无已删除控件异常。结构拆分不作为性能改善证据。

音量均衡时间响应：根 `run.cmd --check-audio-normalization` 使用隔离参数验证压低／保持／恢复曲线、内嵌可拖动编辑器与参考预设、预览对话框的输入隔离和重置、自动保存提交，以及播放器生命周期和实际 libmpv 合成 PCM 的响度差、静音、左右声道与关闭还原；PCM 部分约需一分钟，需 FFmpeg、numpy、libmpv。设置及独立设置进程另运行 `selfcheck_general_settings`、`selfcheck_settings_process`，宽窄布局运行 `selfcheck_settings_layout`。人工通过根 `run.cmd` 打开设置 → 常规，在“音量均衡”区域直接选择预设、拖动节点并等待自动保存，无需二级弹窗；缩窄窗口后检查图表、参数和预设上下排列且不重叠，关闭并重开设置后应保留修改值。重启后核对保存参数；使用同一段真实直播比较开关与不同保持／恢复时间，特别检查说话停顿时背景声是否起伏。曲线图是同一响应模型的示意，合成 PCM 结果不能代替真实听感验收。

音频职责：`audio_normalization.py` 拥有参数校验、参考预设、纯增益响应以及每个播放器的 Qt 采样计时器；`audio_normalization_ui.py` 拥有常规页内嵌编辑器与示意曲线，编辑器是曲线草稿的唯一状态来源；`audio_output.py` 仅组装测量／增益／采样峰值限幅和声道路由滤镜；`TilePlayer` 拥有启停与播放器生命周期。状态保存在全局设置的 `volume_normalization_curve`，缺失时使用平缓默认；编辑器修改副本，由设置页统一自动保存；关闭均衡仍可编辑草稿，启用状态仅控制播放。预设下拉、参数输入、拖动和恢复默认均通知自动保存。测量使用 FFmpeg EBU R128 的400毫秒瞬时响度，压低／恢复时间定义为恒定目标变化达到95%的用时，保持发生在恢复之前；暂停、缓冲和近静音不推进补偿。
斗鱼/抖音高码率缓冲恢复：`run.cmd --check-live-buffering`。2026-11-15实播记录中，抖音原画缓存上限16MiB仅约7秒；视频缓存仍增长时，9秒无播放推进也会被判为错误。本批仅对非静音的斗鱼/抖音播放使用64MiB包缓存上限、起播及重新缓冲等待3秒。缓存时间戳持续推进时，允许有限回填（总计最多20个1500ms检查周期）；视频缓存停止推进6周期、明确接收失败或EOF仍交给原恢复路径。预览、B站和海外参数保持原值，播放器换平台时恢复默认值。

新策略由`ddm.live_buffering`负责，状态属于单个播放器，新媒体清空；不共享定时器或可变缓存。专项覆盖真实停顿时序的离线回放、有限等待、音频字节增长但视频不动、EOF、平台及播放器隔离、换源重置，并用真实libmpv验证选项可设置和恢复。离线通过不等于实播改善：人工从根`run.cmd`重启，保持同斗鱼原画、同抖音原画和B站，连续播放核对缓存、重连及音画同步。起播增加约3秒预缓冲，实际时长由网络和关键帧到达决定；长时断网/持续输入不足仍会恢复，不保证消除上游中断。

直播间封面缓存：后台准备图片时仅缩小到长边不超过640像素，不放大小图；不透明封面比较JPEG85与PNG编码，保存较小者，透明图保留PNG。两种编码保留归一化人脸裁切信息；既有.png路径兼容Qt按内容识别。历史封面在正常读取时本地转存，保存标记避免重复有损编码；没有URL或未开播的房间也可从快照读取，不因压缩重新下载。不增加容量淘汰或批量删图。根`run.cmd --check-image-cache`验证压缩、快照及旧图引用/失败保留/清理并发，封面裁切专项验证缩小后仍保留相同人脸区域。真实缓存样本测量与临时合成回归分开记录，不把样本降幅直接外推全库。

主播头像缓存：复用JPEG85/PNG较小编码，透明图仅PNG；后台下载、URL缓存读取及启动房间快照回填时，长边限制256像素，小图不放大，保存独立标记避免重复有损重编码。界面同步读取入口保持只读，转存留在后台；没有URL的旧快照无需联网，未读取历史文件不批量处理。根`run.cmd --check-image-cache`覆盖大图、下载后快照、透明度、小图、共享引用、离线回填和清理后迟到写入；`selfcheck_room_images`验证后台交付和启动协调。人工从根`run.cmd`重启，检查关注栏展开/收起、竖屏头像条、通知和高DPI清晰度，并确认未开播主播仍有旧头像；无需先清缓存。

SC 自动缩放：设置 → 弹幕中的“SC 随画面缩放”默认关闭，开启后以画面逻辑高度720为基准，卡片宽高、头像和文字一起缩放，手动75%～200%仍叠加生效；弹幕栏SC继续使用手动大小。位置独立／同步、折叠、边界容纳和关闭行为保留。预览使用同一几何函数，`run.cmd --check-sc-layers`覆盖原生表面及离屏SC功能；`run.cmd --sc-simulator`的隔离控制台也提供两种缩放开关。

滚动弹幕的小画面缩放：设高度比例r=画面逻辑高度/720，小于1时使用sqrt(r)，其余仍使用r，字号保留10～144像素限制。基准28时，180/360/540/720高对应14/20/24/28像素；720以上和关闭缩放时行为不变，描边跟随实际字体。此候选响应用户截图中“小格子太小”的反馈，专项验证曲线单调、逐像素变化无突跳、实际卡片重排和设置保存；是否符合真实观看习惯仍需用户从根run.cmd验收，不将模拟渲染写成真实性能改善。

滚动弹幕悬停穿过：新弹幕的栅格结果只做入轨判断，已有弹幕不会因经过悬停弹幕而被清理。悬停条在 QPainter 和 Qt Quick 中都置于前层，点击也优先命中该条。移开后由同轨前方的弹幕短暂加速，间距足够时恢复原速。根 `run.cmd --check-danmaku-independent` 覆盖新栅格到达时的保留、重叠像素和点击、松开时两种前后关系，以及无跳位恢复。窗口外的完整画面弹幕和 Qt Quick 动画检查在预载 Effects 后通过。Windows Quick 组合通过悬停层级检查，之后的遮挡用例因测试环境没有前台窗口未完成。实播从根 `run.cmd` 悬停一条正在滚动的弹幕，在同轨弹幕经过时留意其是否在左边继续出现，再在重叠时移开确认两条分开。

环绕布局弹幕合并回归：默认“主画面＋5 小环绕”上下列边缘对齐；将右侧三个格子关联同一主播，手动调整造成轻微错位时仍应成为一栏。合并矩形不得覆盖任意其他格子，多个窗口宽度下只接收一份消息、共用底部发送框并保留草稿，恢复操作还原全部三个格子。独立保存的上下比例保持不变，改变下排比例不应移动上排。

弹幕区域合并：同源且能拼成矩形的相邻弹幕格共用一个连续消息区域；正文与标题右键仅提供“恢复直播画面”，一次恢复整组合并格。专项覆盖横／纵／四格合并、对角／不同源／空来源分开、L 形不覆盖直播格、换台／清空重新分组及合并保留消息。插件控件专项验证同源发送框按物理下方、右方优先迁移且保留草稿。显式点击布局预设（包括当前预设）恢复其默认格子类型；重启和命名直播间组合仍恢复保存的弹幕格。

画面墙格子类型：`run.cmd --check-wall-panes` 验证普通画面墙右键“切换为弹幕”立即转换，在信号图标左侧从右向左展开当前墙内主播头像，单击选择后收起至选中头像；宽度足够保留标题／字号，空间不足才临时切为头像整行，展开期间变宽／变窄也同步切换；重新展开／横向滚动／Esc／系统动画关闭／中断反向／缓存头像更新及有无发送区的深浅主题底部连续圆角，以及关联任意直播格、多个弹幕栏共享接收连接、普通消息／SC／状态分发、换位与换台跟随、原房间／音量恢复、录制保护、状态及直播间组合保存恢复，以及所有横竖屏预设的任意格位。原生部分使用本地静音 MP4 检查播放器核心、HWND 与播放进度不因其他格子的类型变化而重建；不读取真实账号或发送弹幕。真实直播及平台发送区另需人工验收。

布局空位与多选删除回归使用现有检查：`selfcheck_layout_16` 断言九分、十六分和两分切换后的房间保留、空位数量及“拖入直播间”提示；`selfcheck_main_notices` 的 `MainNoticesTests.test_batch_delete_removes_selected_follows_without_new_windows` 验证批量删除关注后无额外可见顶层窗口，未选房间、空位及保存状态保持正确。旧打印脚本的退役依据见[清理记录](../archive/repository-cleanup-review.md#2026-11-16退役两份打印脚本)。这些隔离检查不代替真实播放或性能验收。

所有命令均从仓库根目录执行。默认入口只运行仓库检查，不遍历所有专项脚本。

日常功能和人工验收统一使用根目录 `run.cmd`。特殊项目可隔离测试，完成后必须集成回根目录并在该入口复测；自动回归仍使用合成数据、临时配置和离屏窗口。开发入口与冻结包统一使用 PySide6 6.11.2。

画中画房间选择：顶部保留视频格中的已入墙房间；自定义弹幕格背后的房间不计入顶部，但仍可作为直播关注从下方选择。首次默认勾选遵循同一筛选，应用时拒绝已变成弹幕格的旧索引；重新管理画中画时保留未选视频格的候选。下方按关注文件夹顺序分块，已入墙房间在所属文件夹也显示；鼠标／键盘勾选同步，组合只计一份。普通文件夹、默认关注和智能文件夹沿用关注栏归属规则；空分块不显示。搜索复用关注栏的中文／全拼／首字母匹配，支持房间号、文件夹名和多关键词，重新排紧且保留选择；列数随窗口宽度调整。预览支持拖动交换位置，拖进大格子即可换大画面；取消拖动或关闭选择器不会应用改动，不再提供“主画面”下拉框。`run.cmd --check-picture-in-picture` 的原生专项使用本地视频检查六种排列、预览拖动、墙外临时播放位、换位／音量、组合修改后的释放、原播放器与 HWND 保持、退出恢复及录制收尾。独立的 `selfcheck_pip_picker` 离屏主窗口专项覆盖文件夹分块、重复入口同步、与关注栏相同查询的结果对照，以及80个候选的网格、搜索、头像缓存、拖动/取消、保存及清理，纳入完整 smoke 与根目录画中画检查入口；和其他主窗口用例隔离进程，避免大量 Qt/Python 窗口引用跨用例累积。临时原生窗口从选择器创建后销毁的完整用例仅在 Windows 原生后端运行；离屏 Qt 后端在同样基线流程中也会于关闭阶段崩溃。真实直播播放、音频听感、高 DPI 和跨屏另行人工验收。

侧栏图标排序：`run.cmd --check-sidebar-navigation` 验证上方固定功能图标和下方工具图标各自在组内拖动、跨组取消、固定入口、拖动不触发点击、Esc／移出／卸载清理及横竖屏恢复。关注、功能中心以及底部通知、深浅色和设置保持固定；通知／深浅色／设置上方有独立分隔线，中间分隔与上下区域保留。顺序保存由 `selfcheck_main_notices` 中的独立窗口回归检查。人工从根目录 `run.cmd` 重启，在展开和收起侧栏拖动图标，再重启确认顺序；实际手感与跨屏需人工验收。

## 全屏直播流信息、SC 与弹幕回退

## 顶部通知关闭

`run.cmd --check-notice-close` 验证通知关闭生命周期、多条通知互不影响、入场中关闭、窗口重用及图片回调不会无条件重新打开已隐藏的通知。保留现有退出动画，悬浮通知和通知列表删除增加独立单次定时收尾：即使共享动画不推进，GUI 事件循环仍运行时也能完成关闭；重开取消旧收尾，重复删除只触发一次。检查会暂停动画进行故障注入，随后执行顶部通知与通知中心既有回归。这是功能回归，不证明真实久用或高负载残留已复现或根治，也不能在整个 GUI 线程阻塞时即时关闭通知。

全屏开播通知遮挡弹幕的离线回归也由 `run.cmd --check-notice-close` 执行。在关闭、超时和立即隐藏三条路径上直接读取 Windows 弹幕窗口的裁剪区域。退出动画期间维持通知遮挡，隐藏并重排通知后同一事件内恢复空出的区域，其余通知继续遮挡其当前位置。人工复测从根目录 `run.cmd` 启动，开启滚动弹幕后全屏播放，分别手动关闭通知、等待通知自动消失，观察弹幕是否随通知退出恢复通过原区域。

全屏底栏与设置窗口弹幕遮挡回归：

```powershell

```

该入口使用与开发版相同的 Qt 依赖，在屏幕外检查全屏入口、底栏下滑隐藏与唤回、连续切换、透明底栏原生窗口复原，以及独立设置进程移动、缩放、最小化、重开和退出后的弹幕裁剪恢复。弹幕布局还检查主格子和小格子全屏时输入框的位置、草稿与视频 HWND 保持不变；交换格子和退出全屏时，输入框须在新底栏布局之前归位，普通模式的被动文字标签须恢复由父底栏绘制，不能残留独立原生窗口。使用合成数据和隔离配置，不移动鼠标、不发送弹幕；不能替代真实播放验收。重启普通 `run.cmd` 后，从弹幕布局的主格子和小格子分别进入全屏，输入框应出现在底栏，静置后底栏应下滑收起，移动鼠标后恢复；返回后输入框应回到原来的弹幕栏且底栏无矩形色块。反复交换主格与小格，输入框不应在主格底栏闪现。打开并移动设置窗口，弹幕应避开设置，关闭后恢复该区域。

全屏格子使用独立呈现窗口。录屏若只采集原主窗口，可能只录到画面墙隐藏后的背景；需选择全屏呈现窗口或改用显示器采集。此类采集范围问题与实际屏幕上的黑块分别判断。

格子交换还检查原生暂停按钮和音量滑条的绘制与移动：迁移输入框期间同时暂停底栏布局与绘制，最终几何与位置音量就位后才一次性应用布局，交换返回前刷新原生子控件并消化排队的移动重绘。仅暂停绘制不能阻止原生子窗口携带旧像素移到中间位置。人工验收可为两个格子设置不同音量后反复交换，音量按位置保留，暂停图标与滑条应各显示一份；本地播放专项另检查播放器核心、视频 HWND 和进度连续。

等分网格的音量条样式按画面墙目标几何中最窄列的逻辑宽度统一切换，避免像素取整产生 599/600 两种样式；阈值仍为 600。手动设置不等列宽、大带小、全屏和画中画继续按各格实际宽度判断。墙重排后即使某格尺寸未变，也更新其音量样式；只改变显示方式，各格音量数值保持独立。`selfcheck_plugin_controls` 覆盖边界、单像素窗口增减、手动比例及重置、行高变化和全屏／布局恢复。它使用隔离控件验证已确定的边界行为，不证明用户截图现场已复现。人工验收从根 `run.cmd` 启动，选左右两分并重置比例，缓慢调整窗口宽度，预期两格同时切换；拖为明显不等宽后允许各自切换，进入／退出全屏应恢复正确样式。

真实交换仍有异常时，从根目录运行 `run.cmd --diagnose-control-swap`，复现后静置一秒。`logs/control-swap.jsonl` 按交换记录布局阶段、Qt 绘制/移动事件和原生窗口几何；每次最多 1500 条事件，不读取输入内容，也不为采集创建原生窗口。

直播间组合协调拆分使用根 `run.cmd --check-room-presets`：先检查 `RoomPresetController` 的模块依赖、宿主状态/集合替换、管理校验、全屏快照、重复恢复、录制拒绝及异常后的事务标志，再运行原有真实 Qt 组合操作回归。两项均使用隔离数据；Qt 用例的插件目录临时替换，不扫描本机安装清单。人工从根 `run.cmd` 保存并往返恢复组合，核对格位、比例、声音、弹幕来源和全屏保存，录制替换按原确认流程验收。
