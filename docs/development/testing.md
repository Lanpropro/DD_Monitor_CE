# 验证指南

环绕布局弹幕合并回归：默认“主画面＋5 小环绕”上下列边缘对齐；将右侧三个格子关联同一主播，手动调整造成轻微错位时仍应成为一栏。合并矩形不得覆盖任意其他格子，多个窗口宽度下只接收一份消息、共用底部发送框并保留草稿，恢复操作还原全部三个格子。独立保存的上下比例保持不变，改变下排比例不应移动上排。

弹幕区域合并：同源且能拼成矩形的相邻弹幕格共用一个连续消息区域；正文与标题右键仅提供“恢复直播画面”，一次恢复整组合并格。专项覆盖横／纵／四格合并、对角／不同源／空来源分开、L 形不覆盖直播格、换台／清空重新分组及合并保留消息。插件控件专项验证同源发送框按物理下方、右方优先迁移且保留草稿。显式点击布局预设（包括当前预设）恢复其默认格子类型；重启和命名直播间组合仍恢复保存的弹幕格。

画面墙格子类型：`run.cmd --check-wall-panes` 验证普通画面墙右键“切换为弹幕”立即转换，在信号图标左侧从右向左展开当前墙内主播头像，单击选择后收起至选中头像；宽度足够保留标题／字号，空间不足才临时切为头像整行，展开期间变宽／变窄也同步切换；重新展开／横向滚动／Esc／系统动画关闭／中断反向／缓存头像更新及有无发送区的深浅主题底部连续圆角，以及关联任意直播格、多个弹幕栏共享接收连接、普通消息／SC／状态分发、换位与换台跟随、原房间／音量恢复、录制保护、状态及直播间组合保存恢复，以及所有横竖屏预设的任意格位。原生部分使用本地静音 MP4 检查播放器核心、HWND 与播放进度不因其他格子的类型变化而重建；不读取真实账号或发送弹幕。真实直播及平台发送区另需人工验收。

所有命令均从仓库根目录执行。默认入口只运行仓库检查，不遍历所有专项脚本。

日常功能和人工验收统一使用根目录 `run.cmd`。特殊项目可隔离测试，完成后必须集成回根目录并在该入口复测；自动回归仍使用合成数据、临时配置和离屏窗口。开发入口与冻结包统一使用 PySide6 6.11.2。

侧栏图标排序：`run.cmd --check-sidebar-navigation` 验证上方固定功能图标和下方工具图标各自在组内拖动、跨组取消、固定入口、拖动不触发点击、Esc／移出／卸载清理及横竖屏恢复。关注、功能中心以及底部通知、深浅色和设置保持固定；通知／深浅色／设置上方有独立分隔线，中间分隔与上下区域保留。顺序保存由 `selfcheck_main_notices` 中的独立窗口回归检查。人工从根目录 `run.cmd` 重启，在展开和收起侧栏拖动图标，再重启确认顺序；实际手感与跨屏需人工验收。

- `run.cmd --check-diagnostics`：先验证issue149模型/几何、拖放清理、动画代次、只读句柄、环形/记录大小上限及隐私；再验证9种隔离专项和独立工具的收集、摘要、脱敏及旧版兼容。不读取真实账号，不替代实际故障复现。Windows原生单项可用 `QT_QPA_PLATFORM=windows` 运行 `dev/checks/bootstrap.py dev/selfcheck_sidebar_diagnostics.py`，验证原生句柄读取不会创建窗口或改变几何。
- 独立工具1.3选择专项后点击“启动专项诊断”，源码使用根目录入口；新正式程序使用 `--diagnose-session=<类型>`。类型及限制见[工具说明](../../tools/diagnostics/README.md)。已发布的0.7 / 0.7.1仅支持收集原有日志，新统一专项入口需更新后的主程序。

- 其他专项同样按快捷键标记时刻；通知专项补充当前窗口状态，弹幕专项重新开启一段有限采样。斗鱼深度模式明确使用本地中继，与普通播放分开对照。

## 全屏直播流信息、SC 与弹幕回退

全屏Enter焦点回归：`python dev/run_checks.py --script selfcheck_fullscreen_enter_focus`，使用原生Windows工具窗口和无发送能力的替身输入控件。人工从根`run.cmd`重启后，进入全屏并等待底栏隐藏，按一次Enter应直接出现输入光标；底栏显示时点击视频后再次按Enter也应聚焦。已有草稿不能在聚焦时发送，输入完成后的Enter由插件发送；中文选词回车不能误发。另检查小键盘Enter、重新绑定快捷键及鼠标移到另一屏的情况。真实平台发送由维护者手工验收，自动检查不发送弹幕。

同时验收自动隐藏闭环：输入框持有焦点时，静置超过三秒也保持底栏可见；点击视频画面后退出输入焦点，鼠标停在画面中央约三秒，底栏应向下收起。再按Enter应能重新显示并聚焦。点击画面及收起过程中不得清空或提交已有草稿。

全屏底栏交接：`python dev/run_checks.py --script selfcheck_fullscreen_switch`。从根`run.cmd`播放多路直播，连续进出不同格子的全屏，检查进入时视频与底栏首次出现的顺序，以及退出后所有格子底栏是否立即完整显示；同时检查输入草稿、透明底色、控件位置与自动隐藏。开发`logs/fullscreen.jsonl`的`geometry`记录增加`bar`角色的Show/Hide/首帧Paint，绘制事件顺序不等同于桌面合成帧已同时呈现。

开发入口的全屏记录同时采集进入后八秒的闲置状态（`logs/fullscreen.jsonl`中`fullscreen-idle`），包括隐藏开关、光标隐藏、焦点控件类型、底栏目标与进度、动画时间及显隐、底栏与输入框位置及透明属性。采集到期或退出全屏即停止，不记录输入内容或账号；用于区分闲置检测与底栏动画故障。反复进出全屏至少三轮，均需检查闲置收起及移回底部后的滑出；原生回归额外暂停共享动画时钟，验证底栏独立时钟仍完成收起与展开，此故障注入仅用于回归。

- `run.cmd --check-stream-info`：Windows 原生独立全屏进退、信息窗口归属与复用、刷新计时器，以及隔离采集器回归；随后执行离屏流信息检查。
- `run.cmd --check-sc-layers`：原生 SC 呈现与离屏卡片回归。展开卡片点“×”只收起该条，收起后再点“×”才关闭；正文点击仍可展开，其他留言的折叠状态和计时独立。
- `run.cmd --diagnose-danmaku-motion`：真实运行的数值采集写入 `logs/danmaku-motion.jsonl`，每次启动最多 2400 条；只在界面线程记录动画重设调用来源、暂停/悬停、窗口显隐/暴露，不读取弹幕正文或账号，不添加渲染节点、不接入渲染线程。此日志不能证明桌面最终绘制没有倒退；必要时与用户录像对齐。

人工复查：全屏右键打开直播流信息，点击视频后信息窗口仍可见；进出全屏及再次打开复用同一窗口。SC 两次点击“×”依次收起、关闭单条。弹幕回退单独按真实复现场景核查，不以功能回归或历史超速修复代替本次验收。

## 顶部通知关闭

`run.cmd --check-notice-close` 验证原有通知关闭生命周期、多条通知互不影响、入场中关闭、窗口重用及图片回调不会无条件重新打开已隐藏的通知。关闭策略保持原样，随后执行顶部通知与通知中心既有回归。此检查使用本地合成通知，不证明真实久用或高负载残留已复现或根治。

若再次出现残留，可用 `run.cmd --diagnose-notice-close` 运行并按原操作复现。只在关闭按钮按下／处理后采集相关通知五秒、最多六张通知及 2000 条事件，记录按钮按下／释放／clicked、通知类别、`dismiss`、图像更新、绘制耗时、重排、动画、显示／隐藏、Qt 与 Windows 原生可见状态和界面定时器间隔，写入 `logs/notice-close.jsonl`。不记录通知正文、路径、账号或截图，不改变窗口层级和几何，不接入渲染线程。

## 执行分类

SC 的画面位置与弹幕栏位置分别保存，可关闭同步以独立调整。`selfcheck_sc_simulator` 验证两种预览分别拖动、切换后保留、独立模式仅重置当前预览位置、页面重置两处、实际弹幕栏与画面互不覆盖，以及全屏往返；大小和透明度继续共用。`selfcheck_super_chat` 验证临时配置保存／重载，`selfcheck_settings_process` 验证外置设置进程传回两处位置。旧配置保留画面位置，缺少同步字段时两处沿用画面位置。人工验收从根 `run.cmd` 启动，在“设置 → 弹幕”关闭同步后分别拖动两种布局预览并保存，切换布局及重开设置检查两处位置保持；可用 `run.cmd --sc-simulator` 产生隔离测试留言，不向直播间发送。

“同步画面与弹幕栏的 SC 位置”默认开启，缺少开关字段的旧配置与恢复默认也启用同步；明确保存的关闭选择继续保留。开启时以当前选中预览为准同步另一处，之后拖动和双击同时作用于两处位置；关闭后保持当前两处位置，可继续独立调整。开关与位置一起保存。模拟器专项覆盖默认值、旧配置、明确关闭的持久化、切换、重开、重置与实际显示；外置设置进程覆盖开关及两处值的保存回传。

播放控制按钮依赖拆分回归：`run.cmd --check-playback-controls`。该入口使用离屏 Qt，验证公共按钮导入不加载播放器、旧导出身份、鼠标/键盘/禁用、音量边界及声道提示、刷新动画显隐与父对象销毁、深浅主题和多缩放绘制，再运行共用组件专项；不读取账号或播放真实媒体。普通 `run.cmd` 人工复查时，核对格子暂停/恢复、刷新、静音/滚轮音量/声道、弹幕开关、录制按钮、侧栏收展及全屏控件，预期行为和外观保持原样。

| 套件 | 依赖与行为 | 命令 |
| --- | --- | --- |
| `repository` | Python 标准库和 Git；不导入 Qt，不读取账号，不联网 | `python dev/run_checks.py` |
| `smoke` | 开发依赖和 libmpv；离屏核心功能检查，使用合成数据与本机服务 | `python dev/run_checks.py --suite smoke --timeout 120` |
| `offline` | 开发依赖；离屏 Qt、替身接口或本机 HTTP/WebSocket 服务，不访问真实直播 | `python dev/run_checks.py --suite offline` |
| `native` | Windows、开发依赖、libmpv；部分项目需 FFmpeg，会创建原生窗口 | `python dev/run_checks.py --suite native` |
| `live` | Windows、运行库和网络；显式指定公开开播房间，只读接收 | 使用下方单项命令 |

`offline` 是已核对隔离条件的回归子集，`native` 也是明确列出的原生检查子集；均不表示仓库全部相关测试。其余历史脚本按功能列入[完整索引](../../dev/checks/README.md)，需要先检查脚本依赖、测试数据和隔离条件，再单独运行或加入套件。不能根据文件名中的 `live` 判断它是否使用真实网络。

离屏进程会阻止 Python 层的外部 DNS 查询和 socket 连接，只允许回环地址；即使脚本捕获该异常，最终结果仍失败。Qt WebEngine、原生库和子进程仍需逐项审查。套件脚本不能使用 `os._exit` 绕过清理；具体纳入标准与本机归档见[工作区维护](workspace-maintenance.md)。

## 结果与新增检查

画面内 SC 原生透明层回归：

```powershell
.\run.cmd --check-sc-layers
```

Windows 检查在屏幕外比较左上、右上及左侧中部 SC 的原生呈现像素与其独立图像，避免左侧内容被父视频窗口的背景或标题覆盖；同时检查主窗口／格子移动、独立全屏窗口进出、隐藏／恢复、独立设置遮挡、拖动、缩放、折叠展开及关闭事件。随后执行离屏 SC 存储、头像、透明度、列表、动画和模拟器回归。使用本地测试留言与隔离配置，不依赖付费 SC、不读取账号、不发送弹幕；这些结果不能代替真实直播中的最终视觉验收。

有真实 SC 时，可用 `run.cmd --diagnose-sc` 启动后将卡片拖到左侧，再移到右侧对照。`logs/sc-paint/` 最多记录 300 条窗口几何和绘制阶段，并为每个原生窗口的左右位置各保存最多两张 SC 自身图像，不保存整屏。无需等待付费留言的人工预览入口是 `run.cmd --sc-simulator`，选择“仅画面”后添加测试留言，检查卡片拖到左侧、重叠 LIVE／标题、缩放和折叠后的外观；之后仍需在真实 SC 出现时复核。

开播提醒替换画面回归：

```powershell
.\run.cmd --check-wall-replacement
```

原生 Qt 检查从视频的 QWindow 发送完整点击，覆盖窗口事件转发到视频 QWidget 的路径；其余离屏检查覆盖只替换选中格子、不扩展满员布局、Esc／隐藏取消、侧栏点击排除、可见空位优先，以及关注卡片状态同步。使用隔离数据且禁止外网，不读取账号或发送弹幕。

真实复现用 `run.cmd --diagnose-wall-replacement`，画面墙满员后点击开播提醒的“替换”，再点击目标视频。`logs/wall-replacement.jsonl` 记录物理按键与 Qt 事件的接收顺序、目标是否命中和事件是否被消费，每次选择最多 300 条，不记录房间、账号或弹幕内容。预期点击后仅目标格子换房，十字光标恢复；按 Esc 则取消且不换房。

全屏底栏与设置窗口弹幕遮挡回归：

```powershell
.\run.cmd --check-fullscreen-layers
```

该入口使用与开发版相同的 Qt 依赖，在屏幕外检查全屏入口、底栏下滑隐藏与唤回、连续切换、透明底栏原生窗口复原，以及独立设置进程移动、缩放、最小化、重开和退出后的弹幕裁剪恢复。弹幕布局还检查主格子和小格子全屏时输入框的位置、草稿与视频 HWND 保持不变；交换格子和退出全屏时，输入框须在新底栏布局之前归位，普通模式的被动文字标签须恢复由父底栏绘制，不能残留独立原生窗口。使用合成数据和隔离配置，不移动鼠标、不发送弹幕；不能替代真实播放验收。重启普通 `run.cmd` 后，从弹幕布局的主格子和小格子分别进入全屏，输入框应出现在底栏，静置后底栏应下滑收起，移动鼠标后恢复；返回后输入框应回到原来的弹幕栏且底栏无矩形色块。反复交换主格与小格，输入框不应在主格底栏闪现。打开并移动设置窗口，弹幕应避开设置，关闭后恢复该区域。

全屏格子使用独立呈现窗口。录屏若只采集原主窗口，可能只录到画面墙隐藏后的背景；需选择全屏呈现窗口或改用显示器采集。此类采集范围问题与实际屏幕上的黑块分别判断。

格子交换还检查原生暂停按钮和音量滑条的绘制与移动：迁移输入框期间同时暂停底栏布局与绘制，最终几何与位置音量就位后才一次性应用布局，交换返回前刷新原生子控件并消化排队的移动重绘。仅暂停绘制不能阻止原生子窗口携带旧像素移到中间位置。人工验收可为两个格子设置不同音量后反复交换，音量按位置保留，暂停图标与滑条应各显示一份；本地播放专项另检查播放器核心、视频 HWND 和进度连续。

真实交换仍有异常时，从根目录运行 `run.cmd --diagnose-control-swap`，复现后静置一秒。`logs/control-swap.jsonl` 按交换记录布局阶段、Qt 绘制/移动事件和原生窗口几何；每次最多 1500 条事件，不读取输入内容，也不为采集创建原生窗口。

### 斗鱼完整采集与深度逐包模式

`run.cmd --diagnose-douyu` 保持直接播放连接，每 500ms 记录音视频各自的解复用缓存
`ts-per-stream`、音画偏差、同步模式/速率修正、解码与显示丢帧、视频输入/输出参数、显示刷新率、
渲染 pass 的 last/avg/peak/count（纳秒）以及采样自身耗时。另记录取流请求的耗时、请求/实际画质、
编解码选择、取消或失败、源域名及单向源标识；不保存签名 URL、请求头凭据或媒体正文。
mpv 事件覆盖打开、文件就绪、音视频重配置、seek、播放重启和结束，缺失属性列在能力记录中。
同时记录生效的 GPU/音频输出、硬解、同步、线程、缓存及探测参数白名单和轨道技术信息，
不采集轨道标题、外部文件名；重连、卡画面恢复和取流失败入口有调用位置与耗时记录。

`run.cmd --diagnose-douyu-deep` 沿用同一开发启动器，并额外让斗鱼当前播放请求经过本机转发器。
每次播放器 HTTP 请求对应一次上游请求流程，不额外探流或另开录制消费者；上游失败仍按现有转发器规则重试。
记录响应状态/重试、响应头白名单、Range、读取等待、首块、收包间隔、累计字节、解析开销和向播放器写入的阻塞时间。
HTTP 后端可用时还记录连接对端地址、TLS 版本/密码套件和重定向域名；不可获取时留空。
首响应耗时包含 DNS/TCP/TLS/服务端等待，不能拆称独立握手耗时；读取块为 64KiB，间隔不是 TCP 包到达时间。

深度模式只读解析转发中的 FLV，记录每个音视频 tag 的尺寸、前一 tag 尺寸核验、原始 DTS、
AVC 有符号合成偏移和 PTS、相邻 DTS 变化、SPS/PPS 数量、NAL 类型/长度异常、IDR 与间隔。
内存中的单 tag 检查上限为 4MiB；无法识别、超限、边界损坏或扩展 FLV/非 AVC 会明确记录未解析，
解析失败不更改转发字节；不保存音视频内容、不修改时间戳、不重封装。
这些头部信息不能证明完整参考帧依赖正确，DTS 回绕需结合原始值单独判断。

两个模式均生成 `logs/douyu-responsiveness.jsonl`：100ms 主线程心跳、超过 250ms 阻塞时的调用位置、
每 10 秒进程 CPU 累计时间、内存、句柄及线程数。主日志与此文件通过启动时间、进程和 `window.ready`
中的 responsiveness_session 关联；播放、上游连接及源请求分别有会话/尝试/连接/请求 ID。
渲染 pass 只反映 mpv 暴露的内部渲染耗时，不是显示器最终呈现时间；本工具不采 GPU 利用率或 DXGI Present。
深度模式会改变 HTTP/TLS 栈并引入本机转发、解析开销，不能把其与直接模式的差异自动归为修复。

人工采集：退出旧实例，保持相同房间、画质和布局，从根目录运行深度命令；起播即开始记录，
故障后继续约 15 秒并正常退出，以写完队列。记录当时声音是否连续、画面是否停止及发生时间，
核对主日志、轮转文件和 responsiveness 日志的同次启动数据。预期看到 `deep=true`、`network.*`、
`flv.*`、`playback.sample` 及心跳文件；没有这些记录时不能声称该层已采到。
功能回归：`dev/selfcheck_douyu_deep_capture.py` 使用分段合成 FLV 和本机 HTTP，验证字节一致、
单一上游请求、Range 传递、时间戳/参数集/NAL、损坏数据边界和异步收尾；不作为真实直播根因或改善证据。

同房间同画质的 CDN 对照：诊断入口读取当前数据目录的 `logs/douyu-control.json`。
例如 `{"room":"douyu:6979222","cdn":"scdncttbej"}` 只针对该房间覆盖取流接口的 CDN 参数，
保留原生画质 rate、正常登录流程和其他房间选择。指定项必须出现在接口返回的线路清单中，
日志 `source.cdn-control` 记录请求线路、实际 rate、返回域名和可用清单；服务端仍可能回退，
须结合域名及 `source.result` 核对，不仅凭指定参数判断切换成功。
控制文件在每次取流时重读：修改后点击当前格子的重载按钮即可，不自动中断已有播放。
设置 `cdn` 为空字符串或删除此诊断控制文件恢复默认选择。普通启动不装载此控制，
首次增加控制功能后须重启诊断入口一次。文件不放凭据，不额外开探流连接；
P2P/边缘线路可能存在独立稳定性问题，不能将指定线路作为默认修复发布。

斗鱼深度转发对实际边缘源域名的精确 HTTPS origin 增加 `AES256-GCM-SHA384` 套件，
保留 Python 默认套件、最低 TLS 版本、安全等级及证书/主机名校验；官方 API、华为源及其他域名不应用此适配。
此兼容基于两个返回节点的真实握手对照：Python 默认配置收到握手失败 alert，兼容套件可协商 TLS1.2，
证书校验通过。未签名根路径 HEAD 被节点直接关闭，不作为媒体实播成功证据。
`network.tls-policy` 记录本次连接采用的配置，代理连接使用相同源 TLS 上下文。
已有进程不会加载此代码修正；先完整退出，随后再设置线路控制并启动深度入口，避免旧实例用旧 TLS 配置重试。

## 久用卡顿的真实采集

`run.cmd --diagnose-responsiveness` 开启默认关闭的专项采集，步骤及字段说明见[真实复现采集](responsiveness-capture.md)。采集器回归不代表 BUG-070 已定位或性能改善。

2026-11-02 的真实侧栏展开/收起采样中，123 个关注条目下 `Sidebar.set_collapsed` 多次耗时约 200–373 ms，主线程栈反复落在 `Avatar.set_pixmap_image` 的样式设置。针对这条路径，头像已有透明样式时不重复设置，更新图片直接交给 QLabel，不先清空已有图片。`selfcheck_main_notices` 覆盖图片替换、尺寸切换、透明圆角及不重复设置样式/文本；这些断言仅为功能回归。展开黑区和实际响应改善仍需相同操作的真实对照采样确认，不能据此宣布 BUG-070 已解决。

头像修正后的真实对照仍出现黑块，侧栏切换约 103–363 ms，收尾栈还采到弹幕重排。经用户同意，左侧关注栏改为一次切换完整布局：暂停侧栏绘制，准备最终控件、宽度与可见封面，并统一调整播放区后再恢复显示；取消逐帧宽度动画和延迟收尾。`selfcheck_main_notices` 检查卡片/列表模式、连续切换、智能文件夹副本、隐藏恢复及异常时释放绘制；`selfcheck_sidebar_performance` 检查最终尺寸、无后续宽度变化、屏外封面和本地播放器，可用 `--background` 将原生测试窗口置于屏幕外。合成功能检查不作为真实流畅度证据。

人工对照：退出旧实例，从根目录 `run.cmd --diagnose-responsiveness` 重启；以相同关注数量和播放布局反复收起/展开。预期直接呈现头像栏或完整关注栏，不经历窄条封面拉伸；滚动后封面正常，播放与弹幕位置正确。若黑块或停顿仍出现，记录到秒的时间以及展开结束后是否残留，再核对新会话日志。

12:24 的真实函数明细（123 个关注）显示，每次切换有 123 次 `setParent`、约 370 次图片缩放，以及大量显隐/置顶事件。对应修正：空闲缩略图停止直接返回；头像在目标尺寸下一次完成裁切与圆环，不先重裁旧图；平台图标固定挂在条目上，用坐标定位到头像角落或展开位置，不再随模式切换换父级。回归覆盖图标显隐、横竖屏位置、头像透明角与圆环、预览提示清理和播放器停止。函数分析增加耗时；这些回归及合成测试不代表真实流畅度改善，仍需用户同场景录屏和明细对照。

12:40 录屏反馈明确允许右侧格子随后缩放，但要求左侧一次显示完整内容。切换收尾因此先恢复侧栏绘制并同步提交完整侧栏的绘制，再释放播放区尺寸保持；不增加固定等待或新的宽度动画。回归记录实际 `QEvent.Paint`，检查侧栏在最终宽度下的绘制先于播放区几何更新，并保留隐藏、原有绘制暂停、异常恢复和连续切换检查。该顺序检查覆盖 Qt 绘制调用，不等同于 Windows 桌面合成器实际呈现的录像验证。
