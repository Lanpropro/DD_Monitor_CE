# 二路计时器 OCR 评估（2026-10-23）

## 结论

暂不接入观看流程，保留现有画面匹配。不要将本次微基准视为「OCR 不影响观看」的验收。

本机未安装 ONNX Runtime、PaddleOCR 或 Tesseract。先尝试无需新增依赖的 Windows.Media.Ocr，使用独立 PowerShell 进程测量，未操作正在播放的软件、未连接真实直播、未读取账号。

## 样本与结果

12 张 160×56 像素合成计时器图片：Arial 粗体、深色背景白字，字号 32 和 18，内容为 0:49、1:35、0:08、0:00、1:00、0:59。图片由 PySide6 绘制。使用英文识别器，预热一次后逐图循环 5 轮，共 60 次调用。

- 平均每次识别约 0.65ms，P95 约 1.14ms。
- PowerShell 工作进程累计 CPU 时间约 1.56ms/次；工作集约 114MiB，包含 PowerShell 和 WinRT，不能当作 OCR 模型本身占用。
- 首轮 12 张样本中 9 张正确、3 张为空：较大字号的 1:35、两种字号的 1:00 漏读。
- 不包括进程冷启动、直播帧截取、跨进程传图、调度、长期多路播放及游戏负载的成本。未验证直播字体、压缩失真、回合重置、暂停和重复倒计时。

低识别耗时不能抵消漏读、重复计时器和秒级精度的限制。当前不增加常驻工作进程或额外 OCR 模型；若后续恢复此方向，需要真实比赛区域样本，以及开启/关闭 OCR 的多路播放对照测试。

## 基准入口

将仅包含计时器裁剪图的 PNG 放入测试目录（文件名用于结果对应，不使用账号或录制直播）：

```powershell
powershell -NoProfile -File dev/benchmark_match_sync_ocr.ps1 -ImageDirectory C:/path/to/timer-crops -Repeats 5
```

依赖 Windows 已安装的英文 OCR 语言包。本脚本不由插件导入，不随插件 ZIP 分发。
