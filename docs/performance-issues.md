## 本对话中的卡顿反馈

### 三路同播时设置操作造成声音和界面短暂停顿

- **现象：** 三路同播时打开设置菜单，播放声音会卡一下，设置菜单稍后才出现；在菜单中点击保存等按钮也会出现类似停顿。
- **反馈时版本：** 对话未注明。对应修复前的仓库提交基线为本体 `v0.4`、比赛二路同步插件 `v1.2.3`；这只能说明代码基线，不能确认用户当时运行的安装包版本。
- **处理与后续：** 插件 `v1.2.4` 将音频缓冲从 60ms 增至 200ms；设置页改为首次访问时创建，保存时保留未打开页面的原值；插件未变化时不重建平台房间列表。插件 `v1.2.6` 又把混音与音频设备供给移入独立线程，使设置界面短时阻塞时音频仍可读取已有缓存。
- **相关对照需求：** 用户希望主播较少时同时展示各路偏移对照，不再逐个选择。`v1.2.4` 在总路数不超过四路时同时显示主画面和全部副路；超过四路时保留选中一路的方式。
- **状态与验证：** 用户已确认这两项完成。四路 1440p/60 本地素材检查记录为：全部对照打开时主画面约 59 FPS，关闭时约 61 FPS，期间未见缓冲；`v1.2.6` 的独立音频线程通过两次各 550ms 的界面阻塞供音检查。真实直播长期表现仍未由这些短测覆盖。
- **记录：** [插件 v1.2.4 更新说明](releases/PLUGIN-match-sync-v1.2.4.md)、[插件 v1.2.6 更新说明](releases/PLUGIN-match-sync-v1.2.6.md)、`dev/selfcheck_match_sync_four_compare.py`、`dev/selfcheck_match_sync_responsiveness.py`。对应提交为 `a7fd1c0`。

## 比赛二路同步中的直播停滞处理

这类问题是取流落后、缓冲不足或断流，不等同于设置窗口造成的 UI 卡顿。

- 插件 `v1.2.3` 起保持主画面播放基准；副路缺少当前同步内容时单独静音并等待，不为了副路延后整组画面。缓存不能补造尚未收到的内容或断流缺口。
- 插件 `v1.2.8` 对已验证且持续晚到至少 5 秒的副路，尝试以最多约 2% 的轻微降速平滑建立共同缓冲，最长尝试 2 分钟；缺口过大、缓存不足或超时会提示具体慢路并建议更换主画面。缺内容的副路仍可单独静音，正常副路继续播放。
- 验证覆盖短时晚到、单路变慢、缓存容量不足、约 16 秒缺口和超时等情况；真实网络断流或设备资源不足仍可能中断播放。
- **反馈时版本：** 仓库发布说明没有提供这些问题各自的用户询问版本。当前工作区插件为 `v1.2.8`。
- **记录：** [插件 v1.2.3 更新说明](releases/PLUGIN-match-sync-v1.2.3.md)、[插件 v1.2.8 更新说明](releases/PLUGIN-match-sync-v1.2.8.md)、`plugins_user/_match_sync/README.md`。
