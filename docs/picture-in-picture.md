# 多画面画中画

从「布局预设」旁的独立「画中画」按钮进入，收起侧栏时也可从账号菜单进入。勾选当前画面墙中的直播间，预览组合并选择自动、横向、纵向、两列或三列排列；至少选中一路才能打开。首次打开后主窗口自动最小化，小窗继续观看；仅修改已有组合不会再次最小化主窗口。小窗的「组合」可重新选择，取消保留当前组合。

六路组合可选择「单主＋五辅（6路）」，在同一面板的「主画面」下拉框指定重点观看的一路。主画面在左上，右侧两路上下排列，底部三路横向排列；六路均为16:9时，整体也是16:9，主画面宽高分别为小画面的两倍。预览与实际窗口共用计算，改变主画面不会交换监控室原格子顺序；取消保留原组合，确认后记住选择。此布局需要恰好勾选六路，数量不符时提示并禁止应用；原有自动及等分排列保留。

横竖屏适配读取播放器的 `video-out-params`／`video-params`，优先取显示宽高或显示比例，并计入90度旋转。单主布局的右侧两路按同列宽度、底部三路按同行高度计算，整个小窗比例随实际源比例调整，保持每路比例并贴合铺满。竖屏可作为主画面，也可作为辅助画面；源流本身带有黑边时仍保留黑边。没有有效元数据时暂用16:9，同一房间重连保留上次比例，取得新信息后再更新。

选中的画面在一个独立小窗中显示，不复制整套软件界面。外形参考常见流媒体画中画：平滑圆角，无标题栏、额外边框和独立工具栏，多路画面贴合排列；支持 Windows 11 原生合成圆角，避免整数区域硬裁切造成高缩放下的阶梯边。旧系统不支持此圆角 API 时保留区域裁切。鼠标移入显示我们自己的「组合／调整位置／置顶／关闭返回」四个半透明圆形图标，移出后只留下画面；悬停有功能提示，开启状态高亮。小窗获得焦点后可按 Tab 进入图标并用键盘操作。

点击双向箭头「调整画面位置」开启换位模式，按钮变蓝、画面使用手形光标。将一路拖到另一格后松开，两路在画中画内互换；开启期间拖动画面不移动整个小窗，边缘仍可缩放。短点、拖回原格、拖到窗外或丢失鼠标捕获均不换位。再次点击按钮退出，恢复拖动小窗；每次重新打开画中画默认关闭此模式。房间、播放器和音频跟随原画面，主监控室格子顺序保留；单主布局拖入主位置的画面成为新的主画面。组合顺序会保存，重新应用组合面板不会重置拖动后的排列。

画中画中的连接／缓冲提示按完整样式等比缩至正常尺寸的75%，图形、文字、间距及圆角一起缩放；较小格子进一步收缩以留在格内。普通监控室恢复原尺寸，暂停提示保留原样式。

默认置顶，可用悬浮图标关闭置顶；拖动画面移动整个小窗，拖动四边或四角等比例缩放。每格跟随直播源的显示比例，横屏与竖屏可以混排；小窗整体比例随组合确定，不再把格子任意拉宽／拉高。各行铺满宽度，最后一行不足列数时也按实际画面数量铺排，不留空槽。没有视频信息的画面先按 16:9 占位，取得信息或源比例变化后自动调整；同一房间短暂重连时保留已取得的比例。直播源自带的黑边保留。

图钉蓝色只表示已置顶；取消后即使鼠标仍停在按钮上也保持中性灰色，移入时提示「已置顶，点击取消置顶」或「未置顶，点击置顶」。Windows切换仅修改原生窗口的Z序，不重算整套Qt窗口样式，不隐藏、重新显示小窗或视频窗口；重新显示及跨DPI时按保存的置顶状态同步。悬浮工具仅在出现或位置变化时抬高，不在每次轮询中重复改Z序。关闭小窗或按 Esc 后恢复主窗口。

组合按钮仅在鼠标悬停或通过 Tab 聚焦时高亮，工具窗口自动取得焦点不会将它常亮。Windows 悬浮工具显隐依据实际命中的原生窗口，覆盖原生视频、透明弹幕层及切换置顶后的鼠标移出／重新移入。

Windows 拖动边角时，通过 DWM 实时合成缩放整组视频、弹幕和醒目留言；原生播放器保持原尺寸继续播放，避免每次鼠标移动都逐个重建输出尺寸。松手只落实一次最终尺寸，合成窗口短暂覆盖这次更新后退出。缩放期间收起悬浮按钮，结束后按鼠标位置恢复；快速再次拖动仍可接续。视频不切换为静态截图、不新增播放器或音频实例。非 Windows 或 DWM 注册失败时沿用约一帧合并一次的原路径；实际直播中的流畅度仍以人工复测为准。

隐藏每格底部信息条、文字播放控件和状态浮标，保留原有右键菜单、弹幕与醒目留言。组合选择窗口打开时收起悬浮图标，避免遮挡；返回监控室后恢复每格样式与交互。

监控室原画面区域显示管理与返回入口。播放器、原生视频窗口、房间、录制及各路音频参数沿用原实例；未选中的画面按原设置在后台播放。画中画运行期间隐藏主窗口到托盘不暂停播放，最小化主窗口也不隐藏小窗。画中画结束后托盘设置恢复原有作用。

关闭小窗、点击「返回」或在小窗按 Esc，恢复原监控室布局与布局比例。选择监控室新布局、应用房间预设或进入单格全屏，会先返回监控室再执行对应操作。退出软件会关闭画中画并按原流程结束播放与录制。保存小窗的位置、大小、置顶、排列和选中位置；下次启动软件不会自动弹出小窗。

## 验证与验收

`python dev/run_checks.py --script selfcheck_picture_in_picture` 使用临时配置和示例房间离屏检查选择、取消、组合、无框圆角与贴边画面、图标透明背景与显隐、画面拖动、边角缩放及最小尺寸、置顶、主窗口隐藏、布局恢复与退出，不访问账号或直播。

根入口 `run.cmd --check-picture-in-picture` 依次执行 Windows 原生本地视频检查和离屏功能回归；不打开或重启用户客户端。

Windows 原生后端可用 `QT_QPA_PLATFORM=windows` 执行 `dev/checks/bootstrap.py dev/selfcheck_picture_in_picture.py --native`。检查横屏和竖屏两路本地 MP4、真实 libmpv 核心与视频 HWND 保持不变、播放进度继续、共享弹幕和醒目留言归属、比例更新／重连、托盘及清理；该检查不代替真实直播、音频听感或跨显示器人工验收。

原生专项同时检查实时合成缩放：拖动期间源窗口和各播放器尺寸不变，DWM 视频／Quick 弹幕／醒目留言表面均保留，松手只调整一次源窗口，连续再次拖动、按钮恢复、保存可见尺寸和注册失败回退正常。附加 `--live-resize` 可短暂显示本地测试画面，保存 `work/pip-previews/live-resize-*.png` 并在相同输出尺寸下比较视频区域的连续帧，验证显示内容确实更新。这些是功能与呈现回归，不作为真实直播 FPS 或延迟改善证据。

单主布局回归遍历六个主画面位置、全横屏／全竖屏／混合比例及多种小窗宽度，核对比例、无重叠和铺满；六路临时房间检查数量限制、主画面预览、取消／应用、选择保存、返回原格子顺序。原生检查复用本地横屏／竖屏MP4，确认切换主画面后的核心、视频HWND与播放进度连续。

换位回归在普通及单主布局检查开启／关闭、拖动互换、主位置更新、组合面板保留顺序、短点／窗外释放／失去捕获取消、关闭模式后拖动小窗恢复，以及房间音频／核心／HWND不变。缓冲回归覆盖小窗和最小尺寸下的等比缩放与格内边界、返回普通监控室恢复；播放浮标专项检查深浅主题和不同DPI下的动画、文字与透明圆角绘制。

这一呈现路径参考用户提供的 B 站画中画连续缩放录像：缩放期间实时播放并保持比例。Chromium 的视频画中画使用 [合成视频表面](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/ui/views/overlay/video_overlay_window_views.cc)；本项目保留既有 libmpv，使用 [Windows DWM 的实时窗口表面映射](https://learn.microsoft.com/en-us/windows/win32/dwm/thumbnail-ovw)实现组合缩放，后端并非同一套浏览器代码。DWM 缩略图是持续更新的窗口连接，不是任务栏截图的静态拷贝。

需要检查实际桌面圆角像素时附加 `--corners`，在短暂显示的受控洋红背景上播放本地蓝色视频，断言圆角存在视频与背景的混合过渡色，保存 `work/pip-previews/native-rounded-<倍率>.png`；该项要求支持原生圆角的 Windows 11。普通根检查入口保持屏幕外运行，不显示此取证窗口。API依据见 [Windows 原生圆角说明](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-rounded-corners)；显示比例读取 [mpv 的 video-params / video-out-params](https://mpv.io/manual/master/)。

2026-11-05 用户在真实客户端复现快速缩放时短暂脱开。外部只读采集得到844份窗口变化样本，包含94次外层尺寸变化；91份样本中画面墙与外层矩形不同，26份中mpv输出窗口与其父窗口不同。结合 `PictureInPictureWindow.eventFilter/resizeEvent`、`WallGrid._relayout_picture_in_picture`、`Tile._layout_areas` 和 `VideoSurface` 的更新路径，针对性同步画面墙布局、合并缩放请求，并将圆角配置和隐藏控件操作移出重复更新路径。外部逐个查询原生窗口可能跨越一次更新，不能将这些样本直接当作显示帧耗时或Python调用计时。回归中的120次连续指针事件只验证合并机制和最终几何、不是实际直播改善证据。

首轮优化后，用户确认不再脱开，但仍有卡顿，并提供真实录像。对当前真实实例使用既有 py-spy 非阻塞采样，GUI线程样本在缩放链路中多次停于 `raise_overlays`、`_layout_areas` 和 Quick 遮罩更新。后续仅在画中画模式跳过已隐藏控件的重排及原生抬高，同轮各格的弹幕遮罩合并后提交；保留视频、加载／暂停提示、弹幕、醒目留言以及恢复监控室时的完整布局。采样权重用于定位调用路径，不作为FPS测量；本轮流畅度仍需真实场景复测。

人工从根 `run.cmd` 启动，在画面墙中准备一路、五路及横竖混合直播：

1. 点击全局画中画入口，勾选任意组合，预览后打开；小窗只显示所选画面，主窗口自动最小化。选择窗口取消则主窗口保持原状；从任务栏恢复主窗口后修改已有组合，不应再次最小化。
2. 确认只有组合画面与平滑圆角，没有标题栏或额外边框；五路组合不留空槽，横竖视频各自保持源比例，拖动边角后比例不变。鼠标移入后右上角出现三个圆形图标，移出后隐藏。拖动画面移动小窗，点击图钉切换置顶；最小化主窗口、切到其他应用，小窗仍可观看。
3. 点右上角四格图标修改或取消组合；取消不改变当前内容，确认后切换组合。组合窗口不受悬浮图标遮挡；检查 Tab、Enter／空格及 Esc 操作。
4. 检查各路原有声音、自然收到的弹幕与醒目留言；测试不需要发送真实弹幕。
5. 连续切换图钉，确认置顶状态和提示同步，画面不隐藏重显、左侧组合图标不闪蓝。关闭小窗或按 Esc，确认主窗口恢复、原房间顺序、布局比例和声音设置恢复。再次打开检查小窗偏好。
6. 检查深浅主题、横竖屏、侧栏收起入口及跨屏缩放；退出软件后无残留小窗。
7. 用原来的真实直播组合快速放大、缩小几轮，检查拼接画面是否仍有短暂脱开，松手后应立即对齐且保持源比例。布局调整仍等待用户另行指定，不自动改变现有排列。
