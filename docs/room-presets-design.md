# 直播间组合预设设计

记录日期：2026-10-15。状态：首版已实现，待用户验收，列入 0.4 发布前置条件；当前软件版本仍为 0.3.1。本次不触发版本更新、远端合并或上传。

试用入口：重新启动源码版 → 关注栏“布局预设” → “直播间组合” → “保存当前组合…”。组合卡片右上角“···”可以重命名、用当前画面更新或删除；点击卡片恢复保存时的画面和声音。

## 保存范围

保存的是按下“保存当前组合”时的画面墙快照。以下范围作为本次设计默认方案，其中静音状态随音量一并保存。

| 内容 | 保存与恢复规则 |
| --- | --- |
| 布局 | 内置布局 ID；拖动后的实际分区比例也保存，不只记录“1+5”等布局名称 |
| 直播格子分布 | 按实际布局位置保存各格的房间 ID，保留主画面、小画面、空格子及当前弹幕格位置 |
| 音量 | 每格独立保存 0～100 的音量及静音状态；空格子同样保存 |
| 声道 | 每格保存当前声道值，恢复后与音量、静音一起生效，沿用现有声道枚举 |
| 名称 | 用户命名，可保存多套；名称不作为唯一标识，使用独立 ID |

画质、画面弹幕开关、皮肤、关注文件夹、账号及录制会话不纳入首版快照；应用组合时沿用相关现有设置。保存时不读取播放器临时音量，也不将在线状态作为固定状态保存。

全屏时保存原画面墙的布局和全部格子，静音使用进入全屏前的原始状态，排除全屏独占声音造成的临时静音。拖动尚未松手时，只保存上次已提交的比例。保存过程不重排、不停播、不启动播放。

## 菜单与交互

入口只放在关注栏现有的“布局预设”弹层中，不新增主界面常驻按钮或设置页入口。在原有“普通布局／弹幕布局／竖屏布局”页签旁增加“直播间组合”。

```text
布局预设
┌ 普通布局 │ 弹幕布局 │ 竖屏布局 │ 直播间组合 ┐
│                              保存当前组合… │
│ ┌ 比赛二路         ⋯ ┐  ┌ 日常观看       ⋯ ┐ │
│ │ 按保存比例画缩略图 │  │ 按保存比例画缩略图 │ │
│ │ 显示主播及空格位置 │  │ 显示主播及空格位置 │ │
│ └ 1+5 · 6 个直播间 ──┘  └ 九分 · 4 个直播间 ─┘ │
└─────────────────────────────────────────────┘
```

- **保存当前组合…**：在当前页面展开名称输入框及保存、取消按钮，不另开窗口；保存后自动选中新卡片。空名称在原处提示；重名时按钮变为“确认覆盖”，再次确认才覆盖，修改名称或取消即退出覆盖确认。全部为空也允许保存，可用作空画面工作区。
- **组合卡片**：缩略图使用保存时的实际比例和位置，标出主播名称、空位及弹幕区域；悬停可查看各格音量、静音和声道。图片只作界面示意，不保存直播截图或启动预览播放器。
- **点击组合**：一次恢复布局、房间位置和声音。当前组合被调整后显示“已调整”，仍保留原快照；再次点击同一卡片恢复保存状态。当前状态完全一致时不重复取流、不产生重复保存。
- **卡片右上角 ⋯**：重命名、用当前画面更新此组合、删除。更新和删除需明确确认目标；删除只删除预设，不删除关注，也不停止当前画面。
- **空列表**：显示“尚未保存直播间组合”和“保存当前组合…”入口。
- **较多组合**：卡片区滚动，保存入口固定在顶部，弹层保持在屏幕可用范围内。

内置布局卡片仍只管理格子排布，再次点击当前内置布局恢复默认比例；组合卡片恢复的是用户保存的比例。两种卡片使用不同动作，不能因布局 ID 相同而意外走到“恢复默认比例”。底部原有重置按钮只属于内置布局页，组合页不显示它。

调整组合后的实时画面不会自动覆盖保存的组合。应用另一套组合前不额外弹出“保存更改”；要更新快照时，用户通过 ⋯ 明确操作。重新打开软件后仍保留全部命名组合，启动沿用现有的上次退出状态，不主动重新应用某套组合。

## 恢复流程与边界

1. **先校验完整快照**：检查布局仍受支持、位置和容量正确、音量与声道合法、房间不重复。损坏的快照不能先清空当前画面再报错；保留记录并提示原因。
2. **处理录制**：仅在恢复会换房间或移除正在录制的格子时，一次列出受影响直播间并询问是否正常结束录制后继续；取消则当前画面不变。仅调整比例、音量和声道不结束仍可沿用的录制会话，也不将保存时的录制状态恢复成自动开录。
3. **应用目标布局**：需要横竖屏切换时采用快照对应的布局方向；恢复实际比例及弹幕区域位置。不根据直播在线状态自动挪动主播，也不调用普通布局切换中的“优先把直播中主播挪到前面”逻辑改写快照。
4. **按位置恢复格子**：设置布局物理格位，再设置各格房间及音量、静音、声道，最后启动需要播放的房间，避免以默认声音先播放再修正。能沿用的播放器和换位路径继续复用；必要的换房、声道路由重建沿用原流程。
5. **异步更新信息**：未开播、断流或插件未启用时保留原格位并显示原因，其他房间正常恢复；不拿其他主播补位。恢复时不要求房间仍在关注列表，也不自动添加关注或修改文件夹。平台恢复可用后沿用现有刷新／重试机制。
6. **保存实时状态**：恢复成功后写入普通退出恢复状态，组合快照本身不改写。切换期间的旧取流或房间信息回调不能覆盖新的目标房间；沿用并验证现有取消和房间身份校验。

同一布局下可保存多套不同的实际比例：例如“比赛”和“日常”都用 1+5，各自恢复各自的比例、主播和声音。组合中保存的比例是独立副本，后续拖动、重置内置布局或修改另一套组合，不会反向修改它。只恢复当前组合的比例，不覆盖其他布局已记住的比例。

## 数据与代码接入

沿用现有配置文件，在配置顶层新增 `room_presets`，包含 `version: 1` 和 `items` 列表。旧配置缺少该字段时使用空列表。每条记录保存：

| 字段 | 含义 |
| --- | --- |
| `id`、`name` | 唯一 ID 与展示名称 |
| `layout.id` | 内置布局 ID，方向从布局定义获取 |
| `layout.ratios` | 当前布局的比例快照；1+5 复用 `corner_ratios` 结构，其他预设复用分区权重结构；缺省默认比例也必须能确定恢复 |
| `layout.danmaku_cell` | 实际弹幕格位置，不带弹幕时为空；遵守布局现有位置限制 |
| `slots` | 按物理格位保存的记录，每项含 `cell`、`room_id`、`volume`、`muted`、`audio_channel`；`room_id` 为空表示空格子，`label` 仅缓存展示名称、不参与状态比较 |

物理格位以布局 cell 索引表示，不保存屏幕像素坐标，也不能直接把 `wall.tiles` 的顺序当作物理位置；弹幕格换位后须通过现有 cell 映射还原。缩略图与恢复使用同一份格位／比例数据，避免显示位置与实际恢复不同。

仅提取上表中的字段，不直接复制整个 `current_state()`，其中包含会话和其他不属于组合的配置。预设不复制主播 room 字典中的临时媒体地址。音频值从格子状态取得，静音复用全屏原始状态的取值规则。

- `ddm/room_presets.py`：组合校验、旧配置集合兼容和快照比较；`ddm/config.py` 沿用已有配置读写保存该字段。
- `ddm/room_presets_ui.py`：组合卡片、缩略图和管理交互。
- `ddm/widgets.py` 的 `LayoutPicker`：组合页签、卡片与管理动作；`WallGrid` 提供当前物理格位和比例的快照／恢复能力。
- `ddm/app.py`：保存及应用组合的独立流程，协调全屏、录制、音频和取流。沿用比例和声道校验；不要直接复用会重置同 ID 布局或自动重排主播的普通布局选择动作。
- 保存组合的名称输入、错误提示和重名覆盖确认均留在当前页面；卡片管理中的重命名、更新与删除沿用现有 Qt 对话框。首版不增加云同步、文件导入导出或自由布局编辑器。

## 验证清单

1. 从“布局预设 → 直播间组合”保存、命名、重命名、覆盖和删除；重名／空名／取消行为明确，删除不影响当前播放。
2. 保存两套 1+5 组合，分别设置不同实际比例、六位主播位置及空位；往返恢复和重启后逐格一致。
3. 逐格设置不同音量、静音及默认／左／右声道，保存后修改再恢复；恢复结果不被默认音量或异步状态刷新覆盖。空格子同样验证声音状态。
4. 验证弹幕格换位、主次画面互换、普通网格和横竖屏恢复，缩略图、物理位置及实际比例一致；不自动优先排列开播房间。
5. 全屏期间保存后退出再恢复，得到原画面墙和原始静音；不能把全屏独占声音造成的临时状态写入组合。
6. 再次点击当前组合恢复保存比例；再次点击当前内置布局仍恢复默认比例；不互相混淆。同状态重复应用不重复取流。
7. 下播房间、已取消关注房间及停用平台保留位置；单房取流失败不阻断其他格子；旧回调不能串到新房间。
8. 录制中的替换／删格正常收尾，取消恢复不改变画面；不受影响的录制继续，应用组合不自动开录。
9. 旧配置、非法 cell、重复房间、越界音量、无效声道、损坏比例和已删除布局均被明确处理；错误不能先破坏当前画面。

首版已按本稿实装，并补充组合保存／管理、物理格位与声音恢复、录制确认及异步收尾、配置重启和真实 VLC 播放回归。手动测试按本清单继续，首版实现不等同于用户验收完成；0.4 发布仍受组合预设和皮肤／美化两项前置条件约束。
