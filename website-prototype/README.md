# DD监控室 CE · 展示页原型 01

这是 DD监控室 CE 的高保真展示页原型，用来先确认「页面长什么样、讲哪些功能、动效是什么气质」，
不是最终网站，也没有接入正式下载统计、插件目录或部署流程。

预览截图：

- [首屏 1440 × 900](shots/hero.png)
- [整页 1440 × 5742](shots/desktop.png)
- [手机 390 × 8782](shots/mobile.png)
- 可交互版本：[index.html](index.html)

## 设计方向

**Signal Room / 信号控制台。** 把软件的多路直播墙翻译成广播控制台与机架的语言：暖黑底、骨白字、
信号橙作为「正在发生」的颜色、少量荧光绿表示插件与在线状态。画面里大量使用通道号、时间码、
刻度线、状态灯、机架螺丝和裁切角标，让页面像一台正在运行的控制设备，而不是一张通用软件落地页。

- 不使用蓝紫渐变、居中大标题 + 三张功能卡、玻璃拟态卡片这类常见 SaaS 模板。
- 视觉方向独立于软件内 UI 与已有宣传片；页面没有复用仓库里的旧网站方案。
- 中文展示字用 Windows 的 `SimHei`，数据与英文标签用 `Bahnschrift` / `Consolas`。
  原型不打包字体；正式站点应改为自托管 OFL 中文字体，避免跨平台字体差异。
- 图片全部来自仓库里的真实软件截图，不画假 UI。截图可能对应较早界面，正式发布前应重新截取。

## 信息结构

| 区块 | 内容 | 目的 |
| --- | --- | --- |
| Hero | 十六个直播间，同时在场。16 路画面墙、六平台、免费开源 | 3 秒内说明“是什么 + 多震撼” |

| 02 控制台 | 逐路音量、静音、画质、L/R 声道、录制、断流重连、关注管理 | 说明“不是只能看，还能管” |
| 03 录制 | 独立录制、即时回放、原画直存、GPU 编码、后台进程收尾 | 展示高价值但容易被忽略的能力 |
| 04 插件 | 国内 / 海外插件、插件插槽、平台列表、代码接口、安装三步、安全边界 | 把插件从“附加项”提升为产品结构 |

没有虚构用户量、Star 数、性能数字或下载量。

## 动效设计

原型是零依赖的 HTML / CSS / 原生 JS，动效全部可由 `prefers-reduced-motion` 关闭。

1. **首屏入场**：标题三行依次从遮罩中推起（950ms，`cubic-bezier(.16,1,.3,1)`），
   画面墙从 3D 透视中落位（1100ms），通道灯、对讲红点随后呼吸。
2. **画面墙视差**：指针在画面墙区域移动时，整体旋转 ±2.4° / ±1.8°；离开后回到静止角度。
   只在桌面端启用，移动端和减少动态偏好下完全关闭。
3. **信号带**：顶部滚动字幕 38 秒线性循环，悬停暂停；底部下载大字带同样循环。
4. **布局预览**：点击 01–04 会切换真实截图、标题、通道码和当前说明；竖屏模式自动收进
   16:10 黑色舞台，隐藏边框拖拽标记。可用 `?mode=portrait` 直接打开某个状态。
5. **控制台微交互**：L / R 按钮、录制按钮、保存片段按钮都有真实状态变化；音量电平条持续起伏。
6. **截图模式**：`?capture=1` 会暂停所有装饰性动画，并让标题与画面墙直接呈现最终状态，
   用于生成稳定的评审截图。

## 文件

```text
website-prototype/
  index.html          单页原型
  styles.css          设计 token、布局、响应式与动效
  app.js              布局切换、视差、按钮状态、capture 模式
  build_assets.py     从 docs/ 原截图裁切页面素材（需要 Pillow）
  capture.mjs         用本机 Chrome / Edge 截全页并做基础审计
  test_prototype.py   静态契约测试
  assets/             裁切后的本地图片
  shots/              评审截图
```

## 预览与验收

直接双击 `index.html` 即可；也可以在仓库根目录启动静态服务：

```powershell
python -m http.server 8080 --directory website-prototype
```

打开 `http://127.0.0.1:8080/`。

重新生成素材与截图（Windows，需要本机 Chrome 或 Edge）：

```powershell
python website-prototype/build_assets.py
node website-prototype/capture.mjs
python website-prototype/test_prototype.py -v
```

`capture.mjs` 会：

- 在 320 / 375 / 414 / 768 / 1024 / 1440 六个宽度检查横向溢出；
- 检查所有图片是否加载成功；
- 收集浏览器运行时错误；
- 输出 `shots/desktop.png`（1440 宽整页）与 `shots/mobile.png`（390 宽整页）。

当前已通过：六档宽度无横向溢出、图片全部加载、无浏览器错误。

## 原型的边界

- 截图来自仓库现有素材，界面细节可能不是当前最新构建；正式上线前需要重新录屏/截图。
- 01 的「平分布局」与「大带小」目前共用一张横屏截图；正式站点应分别补真实截图。
- 插件页的「2 MODULES · 1 SLOT FREE」是产品结构示意；正式页面应从插件目录数据动态生成。
- 下载按钮指向真实 GitHub Releases 页面；没有做系统探测、版本 API 或下载统计。
- 页面没有实现移动端折叠导航、真实插件搜索/筛选、多语言、后台 CMS、部署配置。
- 「06 平台」按安装国内 + 海外插件后的能力计算；单独运行本体时只有 B 站。
- 截图统一使用 `?capture=1` 的冻结状态；直接打开 `index.html` 可看到真实动效。
