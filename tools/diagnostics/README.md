# DD监控室CE 诊断工具 1.3

当前开发候选增加了**事后现场采集**，尚未更新公开工具附件。用户无需提前开启监测，也不需要先复现一遍：

- 文件夹已经错位或重叠：保持原界面，打开工具选择软件目录，点击“抓取文件夹现场”，完成后点击“生成诊断包”。工具读取当前布局、动画和已有原生窗口状态，不强制重排或重绘，不自动截图。
- 出现禁止指针、无法拖动：点击“记录一次拖放”，回到主软件尝试一次。该次拖放结束后自动停止；没有完成操作时最多等待60秒，可随时点“取消采集”。不自动拖动，不改变拖放结果。
- 不要求退出/重启软件。多开源码客户端时选择对应进程。工具采集完成后不继续监测；平时主程序只等待本机请求，不采样、不启动轮询计时器。主程序已有的普通日志行为不变。
- 完整内部现场需要包含按需接口的新版主程序；正式0.7/0.7.1没有该接口。旧版或主程序无响应时，工具只能取得一次Windows窗口坐标/显隐等外部快照，并明确提示内部状态缺失。它不向旧进程注入代码，也不因此自动启动新客户端。
- 软件已退出时直接生成诊断包，保留已有日志和Windows事件。事后采集没有故障前的历史，不能还原未记录的操作或已消失的状态，不代表已经定位或修复故障。

双击 `DDMonitorDiagnostics.exe`，无需安装 Python 或启动主软件。使用 Windows 自带的 .NET Framework / WinForms，支持目标为 Windows 10、11；Win10 实机验证仍待完成。

1. 首次启动自动查找软件目录：检查工具所在目录、正在运行的主程序位置、安装记录及默认安装目录，并检查工具附近的 `result/`、`results/` 解压目录（最多向下 3 层、检查 512 个目录，跳过链接与运行数据），不扫描整块硬盘。多个候选时选择目标目录；未找到时可浏览手动选择，或点击“自动查找”重试。
2. 选择诊断包保存位置，填写问题发生时间、操作步骤、实际表现及预期结果。
3. 在问题描述下选择“稳定复现”“概率触发”或“尚未确认”。点击“添加图片”，或从资源管理器将图片文件拖到附件区，添加后显示缩略图；单击缩略图打开大图预览（Esc 关闭），点击每张图右上角的 × 删除附件，不删除原图。也可按 Delete 移除当前选中的附件。同一文件不会重复添加。支持 PNG、JPG、BMP、GIF；最多 5 张，每张原图及转换后不能超过 20MB，转换后合计最多 50MB。单边不超过 8192 像素、像素总数不超过 4000 万。GIF 只保留首帧。
4. **一般反馈无需启动专项**：“日志收集”默认显示“生成时自动收集已有日志”，直接点击“生成诊断包”即可。需要重新复现、补充更详细的过程时，才展开“高级采集”，从默认“仅打包已有日志（无需专项）”切到对应问题。选择后会显示用途，但**仅选择不会启动、切换或停止任何采集，也不会过滤诊断包的已有专项日志**；展开或收起高级区域也不启停采集。需要开始时，先正常退出客户端，再点击“启动软件并采集”；这是唯一会启动主软件的按钮，不自动结束已有进程。0.7 / 0.7.1 的历史 EXE 尚无新入口，可继续生成已有日志诊断包，专项需使用更新后的主程序；源码目录通过根目录 `run.cmd` 启动。
5. 复现时按 `Ctrl+Alt+F8` 标记发生时间。“文件夹 / 列表错位”和“界面卡顿”还会立即记录当前列表布局、有限历史及随后约2秒的状态，不要求刚点击文件夹；通知专项会记录当前通知的可见状态。弹幕专项在启动后进行有限采样，按此键可重新开始一段采样。复现后正常退出客户端，再点击“生成诊断包”。查看摘要和收集提示，检查 ZIP 内容，然后手动发送给维护者。可勾选“生成成功后自动退出”（默认关闭，仅本次窗口有效）；成功保存 ZIP 后工具自动关闭，失败时保留窗口供重试。自动退出后仍可在选定保存位置找到 ZIP。GUI 沿用已有深灰底色、蓝色强调色与圆角按钮。

生成诊断包不联网、不修改个人配置、不启动或关闭主软件，不需要管理员权限。“启动软件并采集”会按所选类型启动主软件，其播放、联网和账号行为与正常运行一致；普通专项有额外记录开销，斗鱼深度采集会使用本地中继，须单独选择，不能当作无扰动的播放对照。专项用于定位，不会自动修复问题。附件会将实际图片内容放入 ZIP；“添加”或“拖入”不会自动上传。部分系统信息无法访问时会记录提示，其余内容继续收集。保存目录无法写入时，可换一个目录重试。

## 收集内容

主软件在正常运行时自动写入常规运行、播放异常和已有崩溃记录；工具生成诊断包时自动收集白名单中的已有记录，不要求先启动专项。
详细专项是在重新复现时额外记录过程，不能事后还原未记录的现场，也不保证捕获所有异常。本机开发入口的外部卡死监测另按本地配置常态启用，独立诊断工具不会自动给历史正式版安装该监测。

| 文件 | 内容 |
| --- | --- |
| `诊断摘要.txt` | 问题描述、文件说明、缺失或无法收集的内容 |
| `problem.json` | 发生时间、问题描述、复现情况、附件列表、收集时间与工具版本 |
| `live-capture.json`、`logs/on-demand.jsonl` | 用户主动请求的当次现场，含进程、时间、完成/超时/缺失状态；内部记录只含布局数值、匿名行号、拖放类型和原生窗口信息。内存中的最近一次现场随诊断包保存，换软件目录后不带入原目录现场；主程序端记录最多两份512KiB轮转日志。不包含故障前历史 |
| `attachments/` | 用户手动添加的问题图片，重新编码为 PNG，去除 EXIF 等元数据；不自动遮挡图片中的个人信息 |
| `system.json` | Windows 版本、架构、CPU、内存、显卡型号与驱动 |
| `software.json` | EXE/源码/构建版本、更新说明标题、关键程序文件版本与 SHA256、当前程序清单缺失项 |
| `native-dependencies.json` | 独立子进程中的 libmpv 实际加载结果、位数检查、Win32 错误码、直接依赖 DLL 和缺少的函数入口；同时记录系统及软件目录的 Vulkan 加载器是否存在 |
| `config/` | 当前配置及备份的脱敏副本；损坏或过大的配置不收集原文 |
| `plugins.json` | 已安装插件 ID 与版本；启用状态见配置中的 `plugins_enabled` |
| `platform-diagnostics.json` | 自动汇总已收集日志中的平台响应、查询、取流、画质和播放器诊断，按阶段计数并保留最多1000条脱敏记录；用户无需手工筛选标记行。缺少记录不代表正常，不自动判定根因 |
| `specialized-diagnostics.json`、`logs/*.jsonl` | 未决问题专项白名单：文件夹布局、界面卡顿、通知关闭、弹幕运动、拖放、斗鱼播放及响应、主题/全屏切换耗时，以及专项会话。最多24份（含轮转）、每份末尾2MB；汇总阶段计数、会话编号和不完整行，不自动认定根因。不收集已验收的换格、替换、SC源图专项 |
| `recording/`、`recording-diagnostics.json` | 从当前配置指定录制目录的 `.ddm-parts` 读取最近5份FFmpeg `.log`，每份仅末尾2MB；匿名编号并脱敏链接、Cookie和路径，另保留HTTP403及URL的 `expires` Unix秒数。跳过链接目录和文件，不读取视频分片 |
| `logs/`、`ddm-pyinstaller-paths.txt` | 最多五份主程序/更新日志，兼容日期日志、轮转备份与 PR61 文件名，优先当前崩溃日志，其余按时间排序；每份仅末尾 2MB，以及已有启动路径日志 |
| `processes.json` | 匹配所选安装路径的主程序进程、内存与启动时间 |
| `crash-events.json` | 最近七天内与所选安装路径匹配的 Windows Application 事件，最多三十条 |
| `collection.json` | 收集限制、警告与隐私范围 |

不读取账号文件、插件私有配置、弹幕聊天记录、录制视频、缓存或内存转储，不自动截取桌面。仅收集近期录制FFmpeg日志，不收集视频。只打包手动选择的图片，请添加前遮挡个人信息。过滤配置与日志中常见的凭据字段、链接、本机路径及用户/计算机名称。自由文本可能包含其他个人信息，自动脱敏不能替代发送前检查；请勿在问题描述中填写密码或 Cookie。

程序清单只检查文件是否存在；关键文件计算的 SHA256 供维护者对照正式包，并不自动判定文件正确。DLL 检测会在隔离子进程中加载所选软件的 libmpv 及其直接依赖，执行库的初始化代码，但不启动主程序、播放器实例或用户插件；最长等待 10 秒，崩溃或超时会记录结果，其余内容继续收集。请只选择可信的软件目录。可检测缺少 Vulkan 等加载依赖或函数入口；它不穷举间接和延迟加载依赖，加载成功也不保证实际播放正常。摘要会列出加载状态和异常依赖。未发现崩溃事件不能证明未崩溃，工具不还原崩溃前内存。

## 1.3 更新

### issue #149 布局、拖放与原生窗口对照

仅显式选择 `folders` / `responsiveness` 开启增强采集；普通开发入口保留原有轻量记录。增强记录继续写入原白名单JSONL，`schema=2` 包含：

- 根据当前模型顺序、文件夹折叠/搜索、卡片模式及尺寸推导应有槽位，和实际坐标、显隐、内容高度及滚动范围对照。支持普通文件夹和现有智能副本，不调用会创建/隐藏控件的布局函数。它不验证关注排序偏好本身是否正确。
- 重排代次、调用位置、动画出生代次、目标/进度/停止，以及拖放启动、结束和取消的共同清理路径；记录临时折叠、待恢复数量、鼠标捕获和按键状态。Qt取消槽保持原身份，不影响原信号断开与清理。
- 现有Qt/原生窗口的父子关系、坐标、显隐、DPR/DPI和裁剪边界，预览启动/停止及句柄变化。不调用 `winId()`、抓图、强制重绘或重新排布现场。
- 绘制事件派发次数、最近派发时间/区域、更新请求和更新开关。Paint派发不是绘制完成或屏幕正确呈现的证明；布局不一致计数也不能直接认定根因。
- GUI线程每500ms保留最多20条状态（常态约10秒），关键事件最多96条，坐标/动画事件另保留64条。启动、文件夹点击、手动标记后最多记录约2秒/40帧；每次最多16个视口相关条目、32个文件夹，布局模型最多512个槽位。详细原生快照限8个可见条目及其视频、容器和共用预览浮层，另查最多4个已有原生句柄的隐藏/屏外卡片及子层，避免漏掉“Qt已隐藏、原生表面仍存在”的情况。

`before` 是历史状态，`evidence_before/after` 是详细对照，`evidence_samples` 保留触发后的有限采样。`evidence_clock` 可将事件、帧和日志时间对齐；`capture_ms/packing_ms` 记录采集开销。`in_transition` 用来区分正常移动中的坐标差异；模型缺失/截取标记必须同时查看。为保证单行可被工具完整解析，超过约240KiB时优先移除旧历史/帧等记录，并在 `trimmed` 记录数量；`ring_dropped_total` 表示环形记录累计淘汰数量。记录仍受原有文件轮转及收集末尾2MB的限制，缺少证据不表示正常或已经修复。

### 统一专项入口与收集

- 正式主程序和根目录统一使用 `--diagnose-session=<类型>`，只在明确选择后安装对应采集器；不在普通 EXE 启动时开启额外采样。
- 可选类型：`folders` 文件夹错位、`responsiveness` 界面卡顿、`notices` 通知残留、`danmaku` 弹幕回退、`drag` 拖放异常、`douyu` 斗鱼播放、`douyu-deep` 斗鱼深度、`theme` 主题切换耗时、`fullscreen` 全屏切换耗时。
- `responsiveness` 同时支持“启动便滚动关注栏、格子直播并行加载”的轻量对照，按会话时间关联滚动汇总、Qt视频窗口准备、mpv核心初始化与预览切换；显式入口不做函数profile、不额外创建原生窗口，不改变播放或滚动结果。[操作与字段说明](../../docs/development/responsiveness-capture.md#刚启动便滚动关注栏同时加载直播)。
- 新增列表持久错位的手动快照；只记录数字编号、折叠状态、数量、坐标、滚动范围和动画状态，不记录文件夹名、主播名或聊天内容。截图仍只来自用户手动添加的附件。
- 保留构建提交及诊断入口协议。白名单收集现有专项和轮转日志，缺少采集、截断、不完整行明确记录；旧日志与当前故障需按时间和会话分别判断。
- 采集并不修复问题，不改变通知关闭、弹幕运动或拖放结果；诊断回归使用合成数据，不作为 issue #149 或其他真实故障已修复的依据。

## 开发

从仓库根目录执行 `powershell -NoProfile -File dev/build_diagnostics.ps1`，验收前默认产物在 `work/diagnostics-preview/`，不写入 `results/`。独立工具可单独分发；主软件发布脚本会从同一 HEAD 源码快照构建诊断工具，附带到源码包、EXE 便携包和安装包，纳入程序文件清单。不会替换已经发布的历史包。

验证：根目录 `run.cmd --check-diagnostics`；独立工具也可运行 `python dev/selfcheck_diagnostics.py`。使用临时模拟软件目录验证目录识别、布局、图片、ZIP、凭据脱敏、专项白名单、轮转截取、缺少/不完整日志及版本兼容；专项会话在隔离进程中用合成窗口测试，不读取真实账号配置、不发送弹幕，不作为真实故障或性能改善的证据。
